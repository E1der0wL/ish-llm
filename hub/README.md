# 현행 리팩터링 브랜치 안내

`refactor/llm-clean`의 실행·저장 계약은 [현재 설계](../docs/llm/clean-refactor.md)와
[계약 소유권](../docs/llm/contract-ownership.md)을 기준으로 합니다. 아래 main 사용법은 해당
시점의 참고 자료이며 현재 브랜치의 API·저장 형식·검증 완료 증거로 승계하지 않습니다.
날짜가 있는 과거 검증 결과는 그대로 보존합니다.

현재 CLI는 저장 Agent를 `--agent`로 선택합니다. Engine 등록만으로 Agent가 생성되지는 않습니다.

Hub의 새 프로젝트 기본값은 `assistant`와 Graph 에이전트 `planner`를 제공합니다.
`planner`의 `hub-code-workflow`는 환경 확인 → 코드 수정 → 테스트·보완 → 결과 정리로
진행하며, 각 단계에서 `assistant`의 모델·연결·도구 설정을 사용합니다.
사용법과 적용 범위는 [코딩 Workflow](../docs/hub/coding-workflow.md)를 참고하세요.

새 프로젝트의 명령 출력은 Data에 원문을 보관하고 모델에는 미리보기만 전달합니다.
외부 파일·심볼릭 링크 읽기와 기존 프로젝트의 활성화 방법은
[대용량 데이터 처리](../docs/hub/large-data-tools.md)에 정리했습니다.

```sh
python -m hub --workspace /path/to/workspace --agent assistant --model openai/YOUR_MODEL
```

Agent는 Project 도메인이며 Component 선택과 독립적입니다. 요청 시 고정한 Agent binding과
`request_context`를 승인·재개에도 사용합니다. 현재 저장 형식의 필수 기록이나 증거가 없으면
거부하며 구형 Run이나 불완전한 설정을 기본값으로 보충하지 않습니다. Skill의 정규 정의는
표준 디렉터리의 `SKILL.md`이며 JSON 정의 사본이나 레거시 실행 경로를 만들지 않습니다.

관리 코드를 수정할 때는 선언과 실제 소비자를 함께 변경합니다.

| 변경 대상 | 선언·해석 Owner와 소비 경계 |
|---|---|
| 관리 명령·편집 응답·목록 | `backend/project/management_values.py`의 ManagementAction·EditorRecord·ManagementEntry → Backend 관리 코드와 모든 관리 화면 |
| RAG 관측·삭제 검토·이미지 import | `backend/project/rag_views.py`의 RAGEntry·JobDeleteReview·JobRetentionReview·ImageImport → 공개 RAG 계획과 관리 화면 |
| 미저장 초안·화면 표시 | `widget/forms/manager_values.py`의 DefinitionDraft·ManagerView·DefinitionView·RAGManagerView → 관리 위젯 |
| 저장·무결성·CAS·정책 | 해당 llm Component/Repository의 현재 Owner. Hub는 공개 Data API로 조회·변경하며 내부 파일 구조를 해석하지 않음 |
| 설정·키·문구 | 설정 Owner, `ui/input/keys.py`, `locales/keys.py`. 화면마다 필드·명령·기본값을 재선언하지 않음 |

초안은 사용자가 선택·저장하기 전의 UI 데이터입니다. 관리 Projection은 기존 공개 응답 모양을
유지하며 승인·예산·실제 효과·Checkpoint·Resume의 판단을 대신하지 않습니다. Tool package의
수정 시각 같은 저장 관측도 저장 Owner의 공개 API를 사용합니다. Source의 필수 필드와
관측용 선택 필드, 누락·null·명시값을 구분하며 필수 기록을 빈 데이터로 정상화하지 않습니다.

검증은 [Level 1–3 정책](../docs/llm/verification-policy.md)에 따릅니다. 집중 검증과 통합 전체
검증, 정확한 SHA의 원격 CI를 구분하며 실제 결과는
[전수 적용 검증 기록](../docs/llm/whole-ownership-verification.md)에 기록합니다.
아래 예제의 독립적인 wire 값·사용자 설정·셸 명령은 런타임 계약의 재선언이 아닙니다.

# hub

패널·프로필·설정 탐색 및 오류 안내의 최신 사용법은 [패널과 설정 UX](../docs/hub/panel-ux.md)를 참고하세요.
홈의 키 조작, 완료 이력만 전달하는 정책과 일시 정지 중단은 [홈 탐색](../docs/hub/home-navigation.md)에 정리했습니다.

Prompt-Toolkit 기반 ish AI 대화 플러그인입니다. `LargeLanguageModel`의 공개 API로
Project/Session을 열고, 요청을 저장한 뒤 LoopEngine으로 스트리밍 응답을 받습니다.
사용자 메시지는 오른쪽 정렬하고 Assistant 응답은 Rich Markdown으로 표시합니다.
ish에서는 현재 PTY의 너비와 높이를 채우며, 터미널 크기를 변경하면 자동으로 다시
배치합니다. 좁은 화면에서는 세션 목록을 접고, 출력 태그 바는 입력창 위 보조 버튼에서 열 수 있습니다.
태그 바는 모든 엔진 출력이 상속하는 공통 출력 위젯이 소유하며 출력 본문의 오른쪽에만 표시합니다.
상단에는 태그 바 제목과 접기 버튼이 있고, 열 때 현재 스크롤 위치에 가까운 항목을 표시합니다.
태그 바를 열어도 입력창·보조 버튼·하단 진행 영역의 너비는 유지합니다.

도움말은 언어팩의 Markdown 본문을 Rich로 렌더링합니다. 도움말·프로젝트 로그·컴포넌트 조회 결과는
공통 읽기 전용 팝업을 사용합니다. **이동키**로 스크롤하고 **ESC / Enter / Ctrl+L**로 닫습니다.

## 실제 대화 실행

Linux Python 3.12.14 환경에서 저장소 루트로 이동합니다. `llm/`의 의존성과
`prompt-toolkit==3.0.53`, `rich>=14,<15`, `ascii-magic`, `pyfiglet`이 필요합니다. ish로 배포하면 플러그인
로더가 `llm` 요구사항과 Python 의존성을 처리합니다.

```sh
# ish 또는 Hub를 시작하기 전에 사용하는 제공자의 인증 환경변수를 설정합니다.
export OPENAI_API_KEY="YOUR_API_KEY"

python -m hub \
  --workspace "$HOME/.ish/hub-workspace" \
  --engine loop \
  --model openai/YOUR_MODEL
```

OpenAI 호환 서버라면 `--api-base https://YOUR_SERVER/v1`을 추가합니다.
`--model`에는 LiteLLM의 provider/model 형식을 사용합니다. 환경변수 인증을 사용할 수 있습니다.
Agent 편집 화면에서 `completion.api_key`를 직접 입력하면 해당 Agent 정의에 저장됩니다.

설정 화면에는 저장할 초안만 표시하며, 저장값·현재 적용값의 별도 표시 행은 없습니다.
호스트가 고정한 필드는 읽기 전용입니다. JSON 객체 일부만 고정된 경우 나머지 키는 수정할
수 있지만 고정 경로의 저장값을 바꾸면 저장을 거부합니다. 적용값이나 주입 client의 설정을
Project 설정으로 자동 복사하지 않습니다.

첫 실행은 파일 대화 저장을 사용하는 기본 Project를 만듭니다. 세션은 자동 생성하지 않습니다.
세션이 없으면 pyfiglet 안내 화면이 나오며, 세션 목록에서 c를 눌러 직접 생성합니다.
마지막 세션을 삭제하면 같은 안내 화면으로 돌아갑니다.
이후 같은 workspace로 실행하면 기존 Project와 대화를 다시 엽니다.
**model/api-base 인자는 기본 Project를 처음 만들 때만 적용**합니다. 기존 설정을
조용히 덮어쓰지 않습니다. 다른 모델을 처음 시험하려면 새 workspace를 지정하거나
/agent 관리 창 또는 llm의 Agent API로 해당 Agent를 수정하세요.

특정 Project와 Session을 열 수도 있습니다. ID는 프로젝트 로그와 백엔드 조회 API로 확인할 수 있습니다.

```sh
python -m hub --workspace "$HOME/.ish/hub-workspace" --engine loop \
  --project PROJECT_ID --session SESSION_ID
```

ish에서는 `.ishrc.py`에 다음만 추가하면 실제 Hub가 설치됩니다.

```python
hub_plugin = plugin.get("hub")
if hub_plugin is not None:
    hub = hub_plugin.install(prompt)
```

기본 저장소는 `~/.ish/hub-workspace`입니다. 모델이 없는 첫 실행에서도 Hub와 설정을 열 수 있습니다.
홈의 프로젝트 목록에서 프로젝트를 선택하고 설정 보조 버튼 또는 프로필 영역의 설정 버튼을 누르세요.
/agent 관리 창의 assistant에서 `completion.model`을 지정하고 저장한 뒤 홈 버튼으로 돌아가 대화하세요.
제공자 인증은 환경변수 또는 Agent의 `completion.api_key`로 설정합니다.
기존 workspace와 모델을 지정하는 `install(prompt, config=HubConfig(...))`도 지원합니다.

### OpenAI 모델로 시험하기

[OpenAI 공식 시작 안내](https://developers.openai.com/api/docs/quickstart)에 따라 API 키를 발급한 뒤,
WSL에서 **ish를 실행하기 전** 환경변수로 지정합니다.

```sh
export OPENAI_API_KEY="YOUR_OPENAI_API_KEY"
```

ish를 실행하고 Ctrl+Q로 Hub를 연 다음 `/agent`로 관리 창을 열고 assistant를 편집합니다. 입력창에서
모델·주소·인증은 해당 Agent의 `completion` 항목에서 설정합니다.

| 항목 | 시험 설정 |
| --- | --- |
| `model` | `openai/gpt-5-mini` |
| `api_key` | 비움: 위 환경변수 사용 |
| `api_base` | 비움: OpenAI 기본 주소 사용 |

[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini)는 스트리밍과 함수 호출을
지원하는 모델 예시입니다. 계정에서 사용 가능한 다른 모델 ID도 `openai/모델_ID` 형식으로
지정할 수 있습니다. 문자열 필드는 따옴표 없이 입력합니다. 기존 Gemini API 키·주소·전용 옵션을
함께 제거하고 저장 버튼으로 저장합니다. 새 세션을 만들어 간단한 요청부터 시험하세요.
기존 프로젝트의 모델 변경은 `HubConfig.model` 대신 해당 Agent 편집 화면에서 합니다.

기본 Engine은 `loop`, `graph`이고 Graph에는 AgentNode와 ToolNode 처리기가 연결됩니다.
새 Project에는 `tools`, `skills`, `mcp`, `rag`, `vision`, `agents`, `workflows`, `memory`, `goals`, `refinement`, `prompts` 및 Hub 내장 도구가 등록됩니다.
Graph 요청별 Workflow는 백엔드 실행 옵션으로 지정하며 전용 페이지는 추후 제공됩니다. 컴포넌트 등록과 별개로 실제 도구·Workflow 데이터,
RAG 모델·MCP 연결 등 사용하는 기능의 설정은 필요합니다. 기존 Project의 컴포넌트 선택은 보존됩니다.

`engine_factories`는 기본 엔진에 병합하고 `component_factories`는 내장 목록에 추가하거나 같은 이름을 교체합니다.
팩토리는 클래스나 인자 없는 생성 함수입니다. 설정 화면에는 별도 추가 기능 체크 영역 없이
엔진·등록된 컴포넌트 설정이 표시됩니다. 이전 `config.data.hub.engines` 목록은 엔진 노출을 제한하지 않습니다.
승인과 질문은 기존 대화 입력창에서 응답하며, 승인된 도구는 백엔드 체크포인트에서 이어서 실행합니다.

| 키 | 실제 대화 모드 |
| --- | --- |
| Enter | 대기 상태에서는 요청 전송, 실행 중에는 전송 방식 선택 |
| Ctrl+Space | 입력 커서 위치에 줄바꿈. 미확정 자동완성은 취소 |
| Ctrl+Q | 셸에서는 Hub 열기, Hub에서는 최소화 |
| Ctrl+P | 패널 하단 프로필 영역. 설정 / 홈 버튼으로 페이지 이동 |
| Ctrl+W | Hub의 모든 화면에서 실행·예약 작업을 취소하고 정리 후 재시작 |
| Ctrl+D | 홈 입력창에서 실행 중·일시 정지된 요청 중단. 유휴 상태에서는 마지막 중단 요청 재개. 예약 요청은 유지 |
| 목록 ↑↓ | Session 전환. 다른 Session 실행은 계속됨 |
| 실행 중 Enter | 실행 중 추가 지시 / 후속 지시 선택. 여러 추가 지시 대상이면 대상 선택 |
| ↑ / ↓ | 자동완성이 열려 있으면 후보 선택 |
| /help | 현재 언어의 도움말 |
| 목록 c / r | Session 생성/복제와 이름 입력 |
| 보조 버튼 → 태그 바 | 출력 객체 태그 바 |
| ESC | 메인에서 패널로 이동. 패널에서는 동작 없음 |
| Ctrl+← / Ctrl+→ | 좌측 패널 너비 조절. 너비만 즉시 자동 저장 |
| c / d / e / r | 홈의 프로젝트·세션 목록에서 생성 / 삭제 / 이름 변경 / 복제 |
| 보조 버튼 → 찾기 | 현재 세션 출력 검색. Enter 다음 결과, Alt+P 이전 결과, Esc 닫기 |
| 보조 버튼 → 요청 목록 | 요청 목록. Space 체크, d 삭제, e 편집 후 실행, r 체크포인트 재시도 |
| 보조 버튼 → 로그 | 현재 프로젝트 실행 이력 최근 300건. 다시 열면 갱신 |
| Tab | 선택한 자동완성 확정. 미선택 시 첫 후보 확정, 목록이 닫혔으면 목록 열기 |
| Alt + 이동키 | ↑↓←→ / Home / End / PgUp / PgDn 전체 지원. 대화 출력에 적용. 도움말·로그·조회 팝업은 이동키만 사용 |
| Ctrl+C | 선택한 텍스트 복사. 선택이 없으면 입력창·설정에서 동작 없음. 독립 실행의 셸에서는 종료 |

정상 종료는 활성 Run을 중단하고 예약 요청은 저장해 둡니다. 다시 연 Session의
예약 요청은 백엔드가 복구하며, 이전에 실행 중이었던 Run은 자동 재실행하지 않습니다.
다른 Session의 예약 요청은 해당 Session을 열 때 복구합니다.
기존 Project가 memory 저장을 선택했다면 화면에 표시되며, 그 메시지는 종료 시 사라집니다.

홈 상단에는 `홈`을, 입력창 제목에는 메인 모델 이름을 표시합니다. 실행 중에는 경과 시간,
현재 Step을 표시하며 사용량은 프로필 설정에서
표시합니다. 제공자가 보낸 `reasoning_content`는 답변과 분리된 Markdown 블록으로
표시합니다. 제공자가 생각 과정 텍스트를 보내지 않으면 임의로 만들지 않습니다.
이 데이터는 llm의 Completion 관찰값으로 저장되어 재접속해도 조회할 수 있습니다.

보조 버튼의 찾기는 현재 세션에 표시되는 사용자 메시지·응답·생각 과정에서 텍스트를 찾습니다.
대소문자를 구분하지 않는 일반 문자열 검색이며, 일치 부분과 현재 결과를 다른 색으로 강조합니다.
입력할 때 첫 결과로 이동하고 Enter/다음 버튼으로 다음 결과, Alt+P/이전 버튼으로 이전 결과를
순환합니다. Esc로 닫으면 강조는 해제하고 읽던 위치는 유지합니다.
검색 대상은 Markdown을 렌더링한 출력이므로 원문의 서식 기호를 검색하는 기능은 아닙니다.

Hub에 연결된 다른 세션의 실행 시작·완료·실패·중단·일시 정지는 우측 하단에 알립니다.
알림은 입력 포커스를 바꾸지 않고 기본 8초 뒤 사라집니다. 일반 설정에서 알림 종류와 표시 시간을 변경할 수 있습니다. 최대 3개 세션의 최신 상태를 표시하며,
같은 세션의 알림은 갱신합니다. 초기 이력 조회는 알리지 않습니다. Hub 안에서 표시하는
일시 알림이며 OS 알림이나 영구 알림 이력은 아닙니다. 팝업을 조작하는 동안 알림은 가려집니다.

실행 중 **Enter**로 맞춤형 팝업을 열어 추가 지시 또는 예약을 선택합니다. 기본 선택은 예약입니다. ↑↓로 선택하고 Enter로 확정하며 닫기/ESC는 선택을 취소하고 초안을 복원합니다. 여러 에이전트가 실행 중이면 추가 지시를 받을 대상을 고릅니다. 대상 Run이 끝나거나 바뀌면 임의로 예약하지 않고 상태를 안내합니다.
**ESC**는 좌측 패널로 이동하고, 패널의 **Tab / Shift+Tab**은 카테고리를 이동하며 **Space / Enter / →**는 입력창으로 이동합니다.
홈 입력창의 Ctrl+D는 실행 중·일시 정지된 요청을 중단하고 예약 요청을 보존합니다. 팝업의 ESC는 팝업만 닫으며 Alt+스크롤은 중단을 일으키지 않습니다.
자동완성은 입력 중 드롭다운으로 표시합니다. 지시는 `session.run.steer()`로
같은 실행에 접수하고 현재 completion/Tool이 끝난 다음 지원되는 처리 시점에 반영합니다.
지원하지 않는 엔진이나 종료된 실행에는 보내지 않고 입력을 보존합니다.

일반 요청은 Enter 즉시 입력창을 비우고 전송 중인 초안을 별도로 보관합니다. 저장이 확인되면
사용자 메시지를 바로 표시하며, 전체 대화 갱신을 기다리지 않습니다. 느린 백그라운드 조회보다
입력·중단 처리를 우선합니다. 저장에 실패하면 초안을 유지하고, 접수 중 새로 편집한 초안은
지우지 않습니다. 메시지 상태와 시각은 다음 갱신에서 저장된 값으로 맞춥니다.

응답이 실패하면 출력창에 실패 안내를 표시합니다. 이미 받은 응답은 보존하고 안내를
덧붙이며, 오류 원인은 실행 상세 또는 보조 버튼의 프로젝트 로그에서 확인할 수 있습니다.

**설정 → 모양**에서 **출력창 갱신 간격**과 **로딩 바 갱신 간격**을 각각 변경할 수 있습니다.
단위는 초이며 둘 다 기본값은 **0.1초**입니다(0.01~10초). 숫자만 입력하고 저장하면 즉시
적용되며 재시작 후에도 유지됩니다. 출력창 간격은 스트리밍 갱신을 묶는 간격이고,
로딩 바 간격은 대화·설정 화면의 진행 표시와 스피너에 공통 적용됩니다.
입력 키 처리와 요청 접수 확인은 이 간격 때문에 늦춰지지 않습니다.

현재 키보드 포커스는 영역 제목 앞의 `▶`와 강조색으로 표시합니다.
세션 목록 제목은 ` 세션 목록`이고 스크롤바 양 끝은 `△`·`▽`입니다.
실행·응답 수신·생각 과정에는 `⚙`·`✍`·`💭` 등 상태 아이콘을 표시합니다.
``(U+F03A)는 Nerd Font 또는 Font Awesome 글리프를 지원하는 터미널 폰트가 필요합니다.
출력 영역은 포커스를 받지 않습니다. 태그 바는 보조 버튼에서 열어 탐색합니다. 출력창은 Alt + 이동키로 스크롤하고,
마우스로 클릭하거나 휠을 굴려도 입력 포커스를 빼앗지 않습니다. 좁은 화면에서도 ESC로
세션 목록을 열 수 있고 입력창으로 돌아가면 다시 접습니다. 설정 화면과 선택 대화상자는
Tab/Shift+Tab으로 항목을 이동합니다.
플러그인을 복사해 설치했다면 수정된 `hub/`를 설치 경로에도 반영한 뒤 ish를 재시작하세요.

세션 목록에서 c(생성) 또는 r(복제)를 선택하고 이름을 입력합니다. 이름을 비우면 첫 응답 이후
메인 모델로 제목을 생성합니다. 이름 없는 복제는 복제된 대화로 제목을 생성합니다.
자동 이름 생성은 별도 모델 호출 한 번을 사용하며 `auto_title=False`로 끌 수 있습니다.
제목 생성용 Session은 UI 목록에서 제외하고 작업 후 소프트 삭제합니다. 사용자 대화에는
제목 요청이 들어가지 않습니다. 제목 모델·접속 인자는 완료된 대화를 담당한 Agent에서 가져오며,
내부 `_hub_title` Agent의 `completion`의 명시적 값이 우선합니다.
대화의 JSON 출력 형식·종료 문자열·출력 토큰 제한은 제목에 자동으로 복사하지 않습니다.
실패하면 알리고 같은 설정·같은 응답으로 반복 호출하지 않습니다. 모델·접속 설정을 수정하거나
새 응답이 완료되면 다시 시도합니다. Graph처럼 직접 모델 설정이 없는 Agent는 제목 전용 Agent의
completion을 설정해야 합니다. 다른 Agent의 모델을 임의로 가져오지 않습니다.
복제는 원본의 실행과 대기열이 비었을 때 가능하며, 대화/설정은 복사하고 Run은 복사하지 않습니다.

## ish에서 실제 대화 사용

`llm/`과 `hub/`를 각각 `<ish-home>/plugin/script/llm/`,
`<ish-home>/plugin/script/hub/`에 복사합니다. 인증 환경변수는 **ish를 시작하기 전에**
설정합니다. ish 내부 자식 셸의 `export`는 이미 실행 중인 플러그인 프로세스 환경을
변경하지 않습니다.

`.ishrc.py`에 추가합니다.

```python
from pathlib import Path

hub_plugin = plugin.get("hub")
if hub_plugin is not None:
    hub = hub_plugin.install(
        prompt,
        config=hub_plugin.HubConfig(
            workspace=Path.home() / ".ish/hub-workspace",
            agent_id="assistant",
            model="openai/YOUR_MODEL",
            language="ko",  # "en"도 지원
            # api_base="https://YOUR_SERVER/v1",
            # project_id="PROJECT_ID",
            # session_id="SESSION_ID",
        ),
        # theme=hub_plugin.HubTheme(background="#111923", foreground="#d9e2ef"),
    )
```

Ctrl+Q로 처음 열 때 백엔드를 연결합니다. 셸로 돌아가거나 셸 명령을 실행해도
진행 중인 대화는 계속됩니다. `.ishrc.py` 재로드는 기존 설치·백엔드를 정리한 뒤
다시 설치합니다. `hub.close()`로 명시적으로 해제할 수 있습니다.

ish에 설치한 Hub는 `prompt.context.environ`의 `PWD`와 환경변수를 사용합니다.
`llm` 설치본도 process/shell 도구의 `env` 인자를 지원하는 현재 버전이어야 합니다.
파일 자동완성은 현재 셸 디렉토리를 따르고, 요청마다 Enter 시점의 디렉토리·환경을
저장합니다. 예약된 요청과 승인 후 재개도 그 사본을 사용하므로 이후 `cd`/`export`로
이미 제출한 작업의 실행 위치가 바뀌지 않습니다. 기본 파일·Git·셸·프로세스 도구에
적용되며, 명시적인 도구 `env` 인자는 기본 환경을 완전히 대체합니다.
격리 테스트는 기존 테스트 공간에서 실행하고 환경변수만 같은 사본을 기본값으로 사용합니다.
프로젝트·세션 저장 위치인 `workspace`는 변경되지 않습니다.

환경변수 사본은 재시작 후 재개를 위해 요청/Run의 `engine_options`에 저장합니다.
모델에는 작업 디렉토리만 안내하고 환경변수 목록은 프롬프트에 추가하지 않습니다.
모델 인증/프로바이더의 환경은 기존처럼 Hub 프로세스 시작 시 설정해야 합니다.
별도로 가져온 Python Tool이나 MCP 서버의 전역 실행 환경까지 바꾸지는 않습니다.
ish 없이 독립 실행하면 기존 `HubConfig.file_root` 동작을 유지합니다.
구현 경계와 저장 방식은 [ish 작업 환경 연결](../docs/hub/shell-environment.md)을 참고하세요.

참조 ish CLI가 호출하는 `prompt.run()`을 감싸 `finally`에서 백엔드를 정리합니다.
호스트를 직접 임베딩하여 `prompt.run()`을 사용하지 않는 호출자는 자신의 종료 경계에서
`hub.close()`를 호출해야 합니다. 강제 프로세스 종료 후의 상태 복구는 llm이 담당합니다.

## 백엔드 없는 화면 미리보기

개발 저장소 루트에서 Linux Python 3.12.14, `prompt-toolkit==3.0.53`, `rich>=14,<15`로 실행합니다.

```sh
python -m examples.hub.preview
```

Hub가 열린 상태로 시작합니다. 뒤에 보이는 셸도 입력 보존을 확인하기 위한
모형이며 명령을 실행하지 않습니다. 100열 × 32행 이상을 권장합니다.
88열 미만에서는 왼쪽 목록을 숨깁니다. 116열 이상에서는 실행 상세도 열 수 있습니다.

| 키 | UI 동작 |
| --- | --- |
| Ctrl+Q (셸) | Hub 열기 |
| ESC | 메인에서 패널로 이동. 패널에서는 동작 없음 |
| Tab | 선택한 자동완성 확정 (미선택 시 첫 후보). 목록이 없으면 열기 |
| ↑ / ↓ | 목록에서 샘플 Session 선택, 입력창에서 커서·자동완성 이동 |
| Alt + 이동키 | 출력창 스크롤 (방향키/Home/End/PgUp/PgDn 전체) |
| 목록 ↑↓ | 샘플 Session 전환 |
| 보조 버튼 → 태그 바 | 출력 객체 태그 바 |
| Enter | 입력창에서 전송 미리보기 안내만 표시; 입력 유지 |
| Ctrl+Space | 입력창 줄바꿈 |
| Ctrl+C | 선택한 텍스트 복사. 선택이 없으면 입력창·설정에서 동작 없음. 모형 셸에서는 종료 |

샘플은 완료 대화, 예약 요청 예시, 빈 대화 세 가지입니다. Session별 입력 초안은
실행 중 메모리에만 유지됩니다. 실제 실행/중단/복구 동작은 연결하지 않았습니다.

## ish에서 백엔드 없이 UI 확인

`hub/` 폴더를 `<ish-home>/plugin/script/hub/`에 복사한 뒤 `.ishrc.py`에 추가합니다.
`PLUGIN_META`는 llm 플러그인, PTK와 Rich 의존성을 선언합니다. `preview=True`를 명시하면 백엔드 없이 빈 UI를 엽니다. 기본 `install(prompt)`는 실제 백엔드를 연결합니다.
샘플 대화는 배포 플러그인에 포함하지 않으며 `python -m examples.hub.preview`에서 확인합니다.

```python
hub_plugin = plugin.get("hub")
if hub_plugin is not None:
    hub_preview = hub_plugin.install(prompt, preview=True)
```

ish에서는 처음에 숨겨져 있으며 Ctrl+Q로 엽니다. 셸 명령 입력이 활성화된 동안
사용하는 UI입니다. 외부 터미널 프로그램 실행 중에는 그 프로그램이 입력을 소유합니다.

`install()`은 `prompt.set_float()`와 `prompt.set_key()`를 사용합니다. Float를
다시 만들지 않고 표시 조건만 바꾸며 셸 입력을 유지합니다. Hub가 열린 동안
Application의 셸 키 바인딩을 비활성화하여 Enter/Tab 간섭을 막습니다.
Hub는 터미널의 별도 화면 버퍼(alternate screen)에 표시합니다. Ctrl+Q로 최소화하면
기존 셸 출력과 입력 중인 명령을 복원합니다. 설정 화면에서 복귀할 때도 동일하며,
Hub가 열린 동안 들어온 셸 출력은 원래 셸 화면에 남습니다.
기존 Ctrl+Q 바인딩은 설치 동안 대체되고, `hub_preview.close()` 시 복원합니다.
같은 Prompt에 다시 설치하면 이전 설치를 먼저 해제합니다. 다른 Float는 유지합니다.

## 엔진 등록과 언어팩

`.ishrc.py`에서 엔진 인스턴스를 만드는 함수를 등록합니다. 생성은 백엔드 스레드에서
수행되며 대화 상대 목록의 **수신 대상 변경**으로 다음 요청의 Agent를 지정합니다. 이미 접수된 요청의 binding은
바뀌지 않습니다. `agent_id`는 기본 선택 ID이며 `agent_definition`은 새 Project에 저장할
명시적 정의입니다. 생략하면 Hub의 생성 프리셋을 저장합니다. 기존 Project에는 재주입하지 않습니다.

```python
from llm.engines.loop import LoopEngine

config = hub_plugin.HubConfig(
    workspace=Path.home() / ".ish/hub-gemini",
    model="gemini/gemini-2.5-flash",
    agent_id="assistant",
    language="ko",
    file_root=Path.cwd(),
    agent_definition={
        "engine": "loop",
        "completion": {"reasoning_effort": "low"},
        "system_prompt": "Inspect the workspace and complete the requested work.",
    },
    engine_factories={
        "loop": LoopEngine,
        "review": LoopEngine,
    },
)
hub = hub_plugin.install(prompt, config=config)
```

Gemini의 thinking/reasoning 설정은 [LiteLLM 공식 문서](https://docs.litellm.ai/docs/providers/gemini)에
따릅니다. 위 `agent_definition`은 새 Project의 assistant 정의이며 기존 Project에는 덮어쓰지 않습니다.

설정 창에서도 **/agent → Agent 편집 → `completion.reasoning_effort`**로
지정할 수 있습니다. `e`로 외부 에디터를 열어 `low` 등의 모델이 지원하는 값을 따옴표 없이 입력한 뒤
에디터에서 저장·종료하고 설정 화면에서 **저장**하세요. 저장한 프로젝트 옵션은 이후 새 Run에 적용되며 재시작 후에도 유지됩니다.
빈칸으로 저장하면 이 프로젝트의 옵션을 제거합니다. 이는 thinking 비활성화가 아니라 기본 동작으로 돌아가는 것입니다.
모델·인증·주소·추론 옵션은 Agent가 소유하고 Engine에는 실행 정책만 저장합니다.
모델의 thinking 동작과 텍스트 반환은 별개이며, Hub는 응답에 포함된 `reasoning_content`만 표시합니다.

모델 자체는 기존 Project의 저장된 모델을 유지합니다. 다른 Engine 구현도 같은 방식으로
등록할 수 있으며, Graph/Pipeline의 Workflow 설정과 필요한 Component는 함께 준비해야 합니다.
`component_factories`는 기본 목록에 추가하거나 같은 이름을 교체합니다. 내장 컴포넌트는 별도로 나열하지 않아도 됩니다.
`project_config`는 새 기본 Project의 설정이며 기존 Project를 덮어쓰지 않습니다.

UI 문구는 `locales/ko.py`, `locales/en.py`에 있습니다. 새 언어팩은 같은 키를 제공하고
`locales/__init__.py`에 등록합니다. 모델 답변, 프로젝트/세션 이름과 백엔드 원문 오류는
번역하지 않습니다. 독립 실행은 `python -m hub ... --language en --file-root /path/to/code`입니다.

아이콘은 `asset/icon.py`에서 관리합니다. 선택 표시, 스크롤 화살표, 상태 아이콘,
세션 목록 아이콘과 Markdown 구분선을 여기서 변경할 수 있습니다.
**설정 보조 버튼 → 모양 → 아이콘 스타일**에서 `Nerd Font` 또는 `일반 (Unicode/이모지)`를 고릅니다.
Enter → 방향키 → Enter로 선택을 마친 뒤 저장하면 즉시 적용되고 다음 실행에도 유지됩니다.
기본값은 기존 외형을 유지하는 `nerd`이며, 일반 스타일의 저장값은 `unicode`입니다.
상단 바는 두 페이지에서 같은 위젯과 스타일을 사용합니다. 제목 앞에는 Nerd Font의 ``,
일반 스타일의 `•`를 표시합니다.
세션 목록·상태·생각 과정·알림·편집 표시도 같은 스타일을 따릅니다.

하단 안내는 현재 포커스(입력창, 좌측 목록, 설정 항목의 선택/편집, 버튼, 팝업)에 맞춰 바뀝니다.
실제 키 등록과 같은 정의를 사용하며 ESC → Ctrl 조합 → Alt 조합 → 단독 키 순서, 각 그룹 안에서는 키 이름의 알파벳 순서로 표시합니다.
좁은 화면에서 전부 표시할 수 없으면 `…`로 생략합니다. 입력창 내부의 작성 안내는 유지하고,
좌측 패널 하단의 별도 조작 안내는 표시하지 않습니다.

### 컴포넌트 데이터와 설정

현재 프로젝트에서 선택한 tools·skills·mcp·rag·agents·workflows·prompts만 명령과 자동완성에 표시합니다.
컴포넌트 명령은 단수형 이름으로 관리 창을 엽니다. 도움말은 관리 창 안에 있으며 하위 명령은 없습니다.

```text
/tool
/skill
/mcp
/rag
/agent
/workflow
/prompt
/memory
/agent
```

관리 창에서 경로를 가져오고 항목을 편집·삭제합니다.
Skill은 표준 디렉터리 또는 그 안의 SKILL.md를 가져오고 Markdown 원문을 편집합니다.
자료 파일을 함께 보존하며 저장 시 이름·디렉터리 일치와 revision을 검증합니다. 하단 설정 버튼은 해당 컴포넌트로
프로젝트 설정 페이지를 엽니다. list/get/create/update/delete/settings/install 명령은 제거했습니다.
Prompt·Agent·Workflow는 하단 **생성 / 편집 / 삭제** 버튼과 인라인 JSON 편집 팝업을 제공합니다.
Workflow JSON을 바꾸면 옆의 흐름도도 갱신됩니다. 저장 시 공개 백엔드 API가 정의와 버전을 검증합니다.
자료 생성은 대화로 요청하면 실제 컴포넌트 생성 도구를 사용할 수 있습니다.
MCP 관리 창은 서버 JSON 정의를 가져오고 편집·삭제하며, 가져오기만으로 서버를 실행하거나 연결하지 않습니다.

RAG는 문서 API로 원문과 색인을 함께 관리합니다. 새 프로젝트의 기본값은 청크 1200자,
검색 결과 5개, 후보 20개, hybrid 검색과 리랭킹이며 임베딩·리랭커 모델을 지정해야 합니다.
그래프 추출은 별도로 활성화합니다. 모델의 rag_add_document 도구도 같은 API를 사용합니다.
관리 창은 실패 작업의 재시도·삭제, 실행 작업 취소, PNG/JPEG의 OCR·모델 분석 등록을 제공합니다.
문서 개요는 추가 모델 호출 없이 작성하며 관련 문서에 대한 RAG 우선 검색을 안내합니다.
[RAG 설정·이미지 사용법](../docs/hub/rag.md)을 참고하세요.

Memory·Goals·Refinement는 작업 중 모델 도구와 정책으로 사용합니다.
사용자는 `/memory`로 프로젝트·세션 메모리를 조회·생성·수정·삭제할 수 있습니다.
새 프로젝트에는 기억 회상·목표 문맥 주입·개선안 도구 정책과 네 종류의 생성 스킬이 들어갑니다.
기존 프로젝트의 선택·설정·스킬은 재열기 시 변경하지 않습니다.
[연결 방식과 도구](../docs/hub/resource-authoring.md),
[관리 팝업](../docs/hub/component-managers.md)을 참고하세요.

세션 목록에서 `c`/`r`로 이름을 지정하여 생성·복제하고, `e`로 이름을 변경합니다.
복제 창에서 마지막으로 포함할 요청·응답을 선택할 수 있습니다. 기본값은 최신 대화까지입니다.
보조 버튼의 **요청 목록**에서는 요청을 체크하고 삭제·편집·재시도할 수 있습니다. 목록 아래에서 사용자 메시지를 편집하고 응답을 확인합니다. 편집·재시도는 단일 항목만 지원하며 화면의 기존 위치를 유지합니다. 내부 실행 기록은 새 Run으로 보존합니다. 예약 항목의 삭제는 예약 취소로 처리합니다. [자세한 동작](../docs/hub/request-history.md)을 참고하세요.
삭제는 확인 후 해당 요청·응답·추가 지시를 대화와 이후 모델 문맥에서 제외하는 소프트 삭제입니다.
원본 JSONL 이벤트와 Run·Step 기록은 보존합니다. 실행·대기 요청 중에는 삭제할 수 없고,
미완료 재개가 참조하는 턴도 보호합니다. 재개가 완료되면 과거 paused 상태만으로 삭제를 막지 않습니다.
미완료 작업을 더 수행하지 않으려면 삭제 확인창의 **재개 포기 후 삭제**를 사용합니다.
영향받는 Run ID·Engine·상태를 확인하고 모두 동의했을 때만 포기와 논리 삭제가 함께 저장됩니다.
확인 이후 참조가 바뀌면 재확인이 필요합니다. 취소하면 변경하지 않습니다.
포기한 Run은 재시작 후에도 재개할 수 없지만 체크포인트·Step·승인·Tool 실행 증거는 남습니다.
이미 수행한 파일 변경이나 외부 작업은 되돌리지 않습니다.
보조 버튼의 **로그**는 `project.aactivity()`로 최근 실행 이력 300건을 저장된 순서로 표시합니다.
출력은 포커스를 받지 않으며 **이동키**(↑↓←→ / Home / End / PgUp / PgDn)로 스크롤합니다.
하단 **닫기** 버튼 또는 `Enter`, `Esc`, `Ctrl+L`로 닫습니다. 조회 중에도 닫을 수 있으며, 다시 열면 최신 이력을 조회합니다.
본문은 최대 30행으로 표시하고 터미널의 여유 높이가 부족할 때만 줄어듭니다. 열린 상태의 크기 변경도 반영합니다.
각 항목에는 시각·상태·이벤트와 전체 세션/Run ID를 표시하고, Step ID와 오류 코드가 있으면 함께 표시합니다.
Run 시작·완료·실패·중단·일시 정지와 Step 실패를 표시하며, 운영 로그 파일이나 전체 도메인을 순회하지 않습니다.
이 목록은 파생 인덱스이므로 실행·복구의 기준 데이터는 기존 Run·Step입니다.

우측 하단 알림의 제목은 세션 이름입니다. Nerd Font에서는 `` 오류, `` 정보,
`` 경고, `` 성공 아이콘을 사용합니다. 색은 모양에 저장한 팔레트 값을 그대로 사용하며,
알림별 `alert_*` 색을 따로 설정하지 않습니다.
Ctrl+Q로 셸 프롬프트에 돌아가 있어도 알림이 표시되며 입력 포커스는 유지합니다.
외부 명령 실행으로 PTK가 화면을 그리지 않는 동안의 변경은 다음 프롬프트에서 확인합니다.
명시적으로 바꾼 이름은 자동 이름 생성으로 덮어쓰지 않습니다. `d`는 확인 후 소프트 삭제하며,
실행·예약 요청·자동 이름 생성이 진행 중이면 삭제를 막습니다. 마지막 세션을 삭제하면
안내 화면을 표시하며, 다음 세션은 사용자가 직접 생성합니다.

### 저장된 Agent로 Graph Workflow 선택

`/agent`에서 Project의 Agent 정의와 표시 이름을 관리합니다.
홈의 대화 상대 보조 버튼에서 **에이전트 추가**로 현재 세션에 초대합니다.
목록에서 방향키로 선택한 뒤 Space/Enter의 **수신 대상 변경**을 선택하면 해당 Agent만 수신하고,
같은 대상을 다시 지정하면 초대한 모두에게 전송합니다. 그룹을 만들고 Agent를 배정하여 그룹 단위로
수신할 수도 있습니다. 입력창 제목에 수신 대상이 표시됩니다.
Agent별 동시 응답은 이름으로 구분하며 Graph Agent의 생각 영역에는 Workflow와
노드 진행 상태가 표시됩니다. 자세한 동작은 [대화 상대 문서](../docs/hub/participants.md)를 참고하세요.
Engine 등록은 실행 전략을 제공하며, 등록만으로 Agent가 생성되지는 않습니다.

```python
from llm.engines.graph import GraphEngine
from llm.engines.graph.agent import AgentNode
from llm.engines.graph.tool import ToolNode
from llm.engines.loop import LoopEngine

def make_graph():
    return GraphEngine(handlers={
        "agent": AgentNode(engines={"loop": LoopEngine()}),
        "tool": ToolNode(),
    })

# HubConfig(engine_factories={"graph": make_graph}, ...)로 등록한 뒤
# 해당 Project에 Workflow와 참조 Agent/Tool 정의를 먼저 저장한다.
await project.agents.acreate({"engine": "graph", "engine_options": {"workflow": workflow_id}},
                             identifier="coordinator")
```

Workflow는 [공개 정의 API](../llm/components/workflows/README.md)로 저장합니다.
Agent는 Component 선택과 독립된 Project 도메인입니다. 등록한 Workflow는
`/workflow`에서 편집합니다. 필요한 Component 선택은 `project.components.aselect()`로 변경합니다.

Hub 확장에서는 `view.choose_agent("coordinator")`로 선택합니다. 전송은
`session.run.submit(text, recipients=[...], request_context=...)`를 사용합니다.
셸 환경은 request_context에 별도로 보존하며 저장 Agent 정의에 합치지 않습니다.
선택은 Project·Session별로 유지하고 접수된 요청은 Agent 정의·revision·Engine binding을 고정합니다.
실행·재개 전 필수 증거를 검증하며 선택된 정의가 달라지면 실행을 거부합니다.

입력창 공통 명령은 `/help`, `/new`, `/clone`, `/stop`, `/details`입니다. 컴포넌트 관리는
`/agent`, `/tool`, `/skill`, `/mcp`, `/rag`, `/workflow`, `/prompt`, `/memory`로 엽니다.
`/new 이름`, `/clone 이름`은 이름이 채워진 확인 창을 엽니다. `/`는 명령,
`/`는 명령어, `@src/`는 지정한 루트 아래 경로 후보를 표시합니다. 도움말은 각 관리 창 안에서 엽니다.
방향키 ↑↓로 완성 후보를 선택하고 Tab으로 확정합니다. 후보를 고르기 전 Tab을 누르면
첫 후보를 확정합니다. Ctrl+Space는 미확정 후보를 취소하고 원래 입력에 줄바꿈을 넣습니다.
ESC로 좌측 패널에 이동하면
선택 중인 후보를 취소하고 입력한 원문을 유지합니다. 경로는 텍스트로 삽입하며
파일 내용 자체를 첨부하거나 읽어서 모델에 전송하지 않습니다.

## 메시지와 테마

사용자 메시지는 오른쪽 정렬이며, 긴 문장은 대화 영역 폭의 약 78% 안에서 줄바꿈합니다.
한글을 포함한 터미널 셀 너비로 계산하고, 창 크기나 태그 바 폭이 바뀌면 다시 배치합니다.
전송한 사용자 메시지와 Assistant 응답 모두 기본적으로
[Rich Markdown](https://rich.readthedocs.io/en/stable/markdown.html)을 적용합니다.
제목, 강조, 목록, 코드 구문 강조, 표, 인용을 PTK의 스타일 fragment로 변환합니다.
Rich가 터미널에 직접 출력하지 않으며 PTK가 화면과 스크롤을 소유합니다.
동일한 내용·폭·테마는 다시 렌더링하지 않도록 뷰별로 캐시합니다.
입력창은 Markdown 원문을 편집합니다. 내용과 자동 줄바꿈에 맞춰 1~8줄로 늘어나며,
8줄을 넘으면 입력창 내부를 스크롤합니다. 작은 터미널에서는 가용 높이에 맞춰 줄어듭니다.
입력창은 테두리 박스로 표시하며 별도 Markdown 미리보기는 제공하지 않습니다.
Markdown 구분선(`---`)은 `──────`로 표시하고,
코드나 일반 텍스트의 하이픈은 변경하지 않습니다.
대화 출력 영역은 Alt + 이동키와 마우스 휠로 스크롤합니다.

Hub가 열려 있는 동안 로컬·SSH 모두 클릭·휠·드래그를 지원합니다.
터미널의 Ctrl+Shift+V 같은 붙여넣기는 터미널이 읽은 텍스트를 Hub에 전달하므로
Hub 마우스 조작과 함께 사용할 수 있습니다. 정확한 단축키는 터미널 설정을 따릅니다.
이 동작이 성공해도 원격 호스트의 Hub가 외부 클립보드를 직접 읽고 쓸 수 있다는 뜻은 아닙니다.
[xterm의 Shift+마우스 우회](https://www.invisible-island.net/xterm/xterm.faq.html)처럼
마우스 보고 중에도 보조 키를 눌러 터미널 자체 선택을 사용할 수 있는 환경도 있습니다.

Hub에서 텍스트를 드래그한 후 Ctrl+C로 시스템 클립보드에 복사를 요청합니다.
Ctrl+V는 시스템 클립보드를 읽어 입력 칸에 붙여넣습니다.
WSL은 기존 Windows 클립보드 연결을 우선 사용하고, Linux 데스크톱은 Wayland/X11 도구를
사용합니다. `DISPLAY`가 있지만 `xclip`·`xsel`이 없거나 실패하면 시스템 `libX11.so.6`으로
직접 연결합니다. Vim의 `"+` 레지스터와 같은 X11 CLIPBOARD를 사용하므로 별도 명령 설치가
필수는 아닙니다. X11 연결은 ish의 `DISPLAY`·`XAUTHORITY` 환경을 그대로 따릅니다.
직접 연결할 수 없으면 지원이 확인된 터미널에서만 OSC 52 복사를 시도합니다.
Hub는 OSC 52 읽기를 요청하지 않습니다. 읽기 경로가 없는 환경에서는 터미널의 붙여넣기
단축키를 사용할 수 있습니다.
터미널이 bracketed paste로 전달한 텍스트는 Hub 내부 레지스터에도 반영됩니다.
셸로 돌아가면 호스트의 기존 클립보드 설정을 복원합니다.

클립보드 도구는 매번 ish의 현재 `prompt.context.environ`에서 PATH, DISPLAY,
WAYLAND_DISPLAY, WSL 연결 정보를 읽고 같은 환경으로 실행합니다. 복사는 비동기로
처리하며 Ctrl+V는 진행 중인 복사가 끝난 뒤 외부 값을 다시 읽습니다. 외부 연결 실패 시
내부 레지스터는 유지하지만, Ctrl+V로 오래된 내부 값을 대신 붙여넣지 않습니다.
클립보드 성공·실패 알림 팝업은 표시하지 않습니다. 외부 값을 읽지 못할 때는 터미널의
붙여넣기를 사용할 수 있습니다. 외부 클립보드가 비어 있으면 내부 값도 비웁니다.

X11 직접 연결은 별도 Python 프로세스에서 동작하여 연결 지연·종료가 UI를 막지 않습니다.
한글·이모지와 긴 텍스트의 INCR 전송을 지원합니다. 복사한 값은 Hub를 최소화해도
외부 앱에서 붙여넣을 수 있으며, 다른 앱이 복사하면 소유권을 넘깁니다. Hub 제거/ish 종료 시
연결을 정리하므로, 종료 후의 내용 보존은 데스크톱 클립보드 관리자에 달려 있습니다.

사내 SSH/VM에서 별도 클립보드 연결 도구를 사용하는 경우, ish 환경변수에 아래 두 값을
지정할 수 있습니다. 해당 도구가 **접속한 사용자 PC**의 클립보드와 연결되어 있어야 합니다.

```sh
export HUB_CLIPBOARD_COPY='/absolute/path/to/clipboard-bridge copy'
export HUB_CLIPBOARD_PASTE='/absolute/path/to/clipboard-bridge paste'
```

위 경로는 예시이므로 실제 설치된 도구와 인자로 바꾸세요. 복사 도구는 UTF-8 표준 입력을
받고, 붙여넣기 도구는 UTF-8 표준 출력으로 텍스트를 반환하며 성공 시 0으로 종료해야 합니다.
명령은 셸을 거치지 않으므로 파이프·리다이렉션은 별도 스크립트에 작성하세요.
명시한 도구가 실패하면 다른 데스크톱 클립보드로 우회하지 않습니다. 도구의 응답 제한은
3초이며 기다리는 동안 UI는 계속 동작합니다. 터미널/VM 자체의 클립보드 공유가 막혀 있다면
해당 환경의 공유 설정이나 허용된 연결 도구가 필요합니다.

Exceed TurboX → Linux VM → SSH 호스트처럼 여러 단계를 거치는 경우에는 각 구간의
클립보드 공유와 마지막 호스트의 연결을 확인하세요. Hub를 실행하는 SSH 호스트에서
`printf '%s\n' "$DISPLAY"`와 `command -v xclip xsel`로 X11 연결 및 도구 유무를 확인할 수 있습니다.
X11 전달은 [OpenSSH의 X11 forwarding](https://man.openbsd.org/ssh#X11_FORWARDING) 또는
기존 ETX의 X11 연결 설정을 따르며, 정상 작동하는 Vim과 같은 `DISPLAY`를 사용하세요.
Hub는 SSH 세션에서 해당 X11 연결을 사용하고,
접속 대상 호스트의 별도 Wayland/WSL 데스크톱 클립보드로 우회하지 않습니다.
`xclip -selection clipboard -o`도 PC에서 복사한 값을 읽지 못하면 Hub 외부의 연결이나
X selection 공유 설정을 먼저 확인해야 합니다. PRIMARY selection을 공유하도록 구성한
환경은 두 연결 도구를 각각 `xclip -selection primary -i`, `xclip -selection primary -o`로
지정할 수 있습니다. Hub는 CLIPBOARD와 PRIMARY 중 하나를 임의로 추측하여 섞지 않습니다.

태그 바가 열린 동안 바깥 영역을 클릭해도 포커스가 이동하지 않습니다.
항목 클릭은 선택과 출력 위치 이동만 수행합니다. Tab·Space·Enter로 표 조작 창 또는 코드 뷰어를 전체 화면에 표시합니다.
표는 열 머리글 클릭으로 정렬하고 셀 클릭·방향키로 선택하며, 검색으로 행을 필터링할 수 있습니다.
코드 뷰어는 검색, 원문 보기, 선택 복사와 코드만 복사를 제공합니다.

사용자 본문은 Rich의 채움 공백을 제외한 내용 폭으로 배경 블록을 만들고 오른쪽에 붙입니다.
헤더는 `계정명 · 접수됨 · 2026-10-03 12:34:56` 형식이며, 상태와 시간은 따로 표시합니다.
시각은 저장된 메시지의 생성 시각을 실행 환경의 로컬 시간대로 변환한 값입니다.
어시스턴트 헤더는 `어시스턴트 · 완료 · 소요 1분 2초`처럼 날짜 대신 초 단위 경과 시간을 표시합니다.
요청 직후 준비 중 표시부터 시간을 측정하며, 저장된 요청 시각이 없는 과거 기록은 Run 시작 시각을 사용합니다.
응답 중에는 현재까지의 시간을 갱신하고 완료·실패·중단 후에는 종료 시점의 값으로 고정합니다.
재실행해도 저장된 Run으로 복원하며, 복제된 대화나 실행 기록이 삭제된 메시지는
`소요 시간 알 수 없음`으로 표시합니다.

`예약`은 QUEUED 요청, 즉 현재 실행이 끝나면 순서대로 실행되는 요청입니다.
지정 시각에 실행하는 일정 예약은 아닙니다. 실행할 요청이 없는 IDLE은 `유휴`,
아직 시작하지 않은 PENDING 실행 단위는 `실행 전`으로 구분합니다.

이름은 기본적으로 현재 OS 계정명이며, 이후 프로필 설정에서도 같은 `UserProfile`을 사용할 수 있습니다.
설정 보조 버튼 → 프로필에서 변경하거나 `HubConfig(..., user_profile=hub_plugin.UserProfile(display_name="표시할 이름"))`으로 초기값을 지정합니다.

읽던 위치와 마지막으로 선택한 Session은 `<workspace>/.hub/view-state.json`에 저장합니다.
스크롤 후 짧은 지연을 두고 저장하며, Session 전환·Hub 숨김·종료 시에도 저장합니다.
메시지 ID와 해당 메시지 안의 줄 위치를 이용해 전환·재실행 때 복원합니다.
명시한 `HubConfig.session_id`는 마지막 선택보다 우선합니다. 저장된 메시지가 삭제되었으면
남은 대화 범위 안으로 위치를 보정합니다. UI 위치 파일은 LLM 대화 기록과 별개입니다.

페이지는 기본적으로 **터미널 기본 전경·배경색**을 사용합니다.
색상은 배경(`background`), 전경(`foreground`), 강조 1~5(`accent1`~`accent5`),
주석 1·2(`comment`, `comment2`)의 팔레트로 관리합니다. 일반 버튼·체크 목록은 강조 1,
설정 입력칸·코드 블록 등 일반 위젯 배경은 강조 5를 그대로 사용합니다.
버튼 글자는 강조 4입니다. 드롭다운과 자동완성은 강조 5 배경·강조 4 글자·주석 1 설명을
사용하고, 선택된 항목 배경만 강조 1로 바뀝니다.
홈 입력창은 통합 배경색(`background`)을 사용하며 기본값은 투명(`default`)입니다.
보조 버튼은 선택 상태에서도 투명한 배경을 사용합니다.
상단 바와 그 버튼, 프로필 바는 강조 5 배경을 사용합니다.
프로필 별명은 강조 2, 계정은 주석 1로 표시합니다. 설정 입력칸도 포커스·편집 중에 강조 5 배경을 유지합니다.
사용자 메시지 박스는 강조 5 배경과 강조 4 글자를 사용하며 Markdown 서식은 유지합니다.
하단 키 안내는 강조 4 배경에 강조 5 글자를 쓰고 `<>` 안의 키는 강조 3으로 표시합니다.
하단 바 자체는 강조 5 배경입니다. 앞쪽 삼각형은 강조 5 전경과 강조 4 배경,
뒤쪽 삼각형은 강조 4 전경과 강조 5 배경입니다.
주석 색은 설명·구분선, 주석 색 2는 진행 바 레일에 사용합니다.
색상 혼합이나 전경 자동 보정은 하지 않으며 비활성 영역만 흑백으로 변환합니다.
기존 저장 색은 유지합니다. 제거된 `appearance.mode`는 설정과 프리셋에서 직접 삭제해야 하며,
이전 위젯별 색상 키를 자동 변환하거나 잘못된 설정 파일을 덮어쓰지 않습니다.
설정 보조 버튼 → 전역 설정 → 모양에서 색을 변경할 수 있습니다. 답변 뒤 다음 사용자 요청 앞에는
기존보다 빈 줄 두 개를 추가해 요청 단위를 구분합니다.
배경색을 `default`로 지정하면 터미널 기본 배경을 사용합니다. 투명도 자체는 터미널 프로그램 설정을 따르며, 뒤쪽 셸 글자가 비치는
Float 투명 모드와는 다릅니다. 배경의 셸 글자는 Hub 아래에서 가려집니다.

설정 보조 버튼 → 모양에서 색을 변경하고 저장하면 즉시 적용됩니다. `.ishrc.py`에서 초기 테마를
지정할 수도 있으며, 화면에서 저장한 설정이 다음 실행에서도 우선합니다.

```python
hub_plugin = plugin.get("hub")
if hub_plugin is not None:
    hub_preview = hub_plugin.install(
        prompt,
        preview=True,
        theme=hub_plugin.HubTheme(
            background="default",  # 터미널 배경 유지
            foreground="default",  # 터미널 글자색 유지
            accent1="#98C379",
            accent2="#528BFF",
            accent3="#D19A66",
            accent4="#A8B2BF",
            accent5="#1D2035",
            comment="#8595a5",
            comment2="#3A3A3A",
        ),
    )
    # 표시 중에도 입력이나 선택을 잃지 않고 적용할 수 있습니다.
    # hub_preview.set_theme(hub_plugin.HubTheme(background="#111923", foreground="#d9e2ef"))
```

색상값은 `default` 또는 `#RRGGBB`입니다. 현재 기본 팔레트의 샘플 화면은
`python -m examples.hub.preview`로 확인합니다.

## 설정 화면

셸에서는 Ctrl+Q로 Hub를 연 뒤 설정 보조 버튼으로 설정을 엽니다. 셸의 Ctrl+S 바인딩은 변경하지 않습니다.
설정 화면의 저장 버튼은 프로필·모양·일반과 현재 프로젝트의 편집 내용을 저장하고 설정 화면을 유지합니다.
취소 버튼은 같은 범위의 미저장 변경을 되돌립니다. 대화로 돌아가려면 프로필 영역의 홈 버튼을 누르세요.
설정의 Ctrl+S 저장·Ctrl+C 취소 단축키는 사용하지 않습니다.
저장 전 모든 초안을 검증하며, 저장 실패 시 화면과 미저장 초안을 유지합니다.
여러 설정 페이지 저장 중 충돌이 발생하면 이미 저장된 페이지는 반영하고, 실패한 페이지를 표시합니다.
ESC는 메인에서 패널로 이동하며, 이미 패널이면 동작하지 않습니다. 최소화는 Ctrl+Q를 사용합니다.
좌측 패널의 Tab / Shift+Tab은 카테고리를 이동하며 Space / Enter / →는 메인 영역으로 이동합니다. 메인은 설정 항목과 현재 프로젝트를 표시하는 하단 버튼 영역의
두 부분이며 Tab / Shift+Tab으로 순환합니다. 별도 추가 기능 체크 영역은 없습니다.
설정 항목에서 편집 중이 아닐 때 ↑↓는 항목 이동, ←는 패널 복귀이며 →는 아무 동작도 하지 않습니다. 버튼 영역은 ←→로 선택하며 ↑↓와 왼쪽 끝에서의 ←는 아무 동작도 하지 않습니다.
Enter로 편집을 시작한 뒤에는 ←→로 커서나 선택지를 이동할 수 있습니다.
중앙과 하단은 좌측 패널을 제외한 전체 너비를 사용하고, 하단 버튼은 가운데 정렬하며 좁은 화면에서는 줄을 나눕니다.
버튼은 양옆 기호 없이 전체 배경색으로 표시하고, 선택·포커스 시 글자만 강조 색과 볼드체로 표시합니다.
버튼에 포커스가 있을 때만 버튼의 커서를 숨기며 입력창과 셸의 커서에는 영향을 주지 않습니다.
버튼·체크 목록·스크롤바 색상도 동일한 팔레트 설정 값을 사용합니다.
체크 목록은 위젯 전체에 배경을 적용하고, 선택·포커스에 따른 배경색 변경은 하지 않습니다.
스크롤 트랙과 손잡이는 공백으로 그리며 손잡이는 강조 색 배경을 사용합니다.
트랙과 △·▽의 배경은 모양 설정의 배경색을 따르며 `default`이면 터미널 기본 배경을 유지합니다.
두 화면은 `ui/layout/TwoPanelPage`를 공유합니다. 메인 하단은 좌우에만 1칸 여백을 두고 항상 1행이며 진행 중에는
로딩 바, 그 외에는 알림을 표시합니다. 알림이 없으면 같은 행을 빈칸으로 유지합니다.
대화의 프로젝트·세션 목록과 설정의 전역·프로젝트 항목은 공통 `SidebarList`를 사용합니다.
설정 목록에서 ↑↓로 이동하거나 클릭하면 Enter 없이 해당 페이지가 열리며, 작성 중인 다른 페이지 초안은 유지됩니다.
조회 중 목록을 빠르게 이동하면 마지막 선택을 적용합니다. 패널 하단에는 공통 프로필과 설정 / 홈 버튼을 표시합니다.
각 영역 안에서는 방향키로 항목을 선택합니다.
중앙 입력칸에서 Enter로 직접 편집을 시작하고, 다시 Enter로 편집을 마칩니다.
직접 편집 중에는 방향키로 커서를 이동하고 Ctrl+Space 또는 Alt+Enter로 줄바꿈합니다.
항목 선택 상태에서 `e` 또는 `E`를 누르면 일반 설정에 저장된 외부 에디터가 열립니다.
직접 편집 중 `e`와 `E`는 일반 문자로 입력됩니다.
에디터에서 저장·종료하면 초안으로 돌아오며, **저장** 버튼으로 실제 설정을 저장합니다.
에디터가 실패하면 이전 초안을 유지합니다. 입력칸은 내용에 따라 1~3줄을 표시합니다.
ESC는 좌측 패널로 이동합니다. 설정의 메인 영역에서 Alt + 이동키는 설정 내용을 스크롤하며,
대화의 출력이나 포커스에 영향을 주지 않습니다.
ESC와 Alt/VT100 시퀀스를 구분하기 위해 Hub가 열려 있는 동안 PTK의 ttimeoutlen과 timeoutlen을
각각 0.02초로 설정합니다(단독 ESC 판별 대기 약 40ms). 셸로 돌아가면 원래 값을 복원합니다.
ESC를 무조건 즉시 확정하는 eager 바인딩은 Alt 조합을 깨뜨리므로 사용하지 않습니다.

왼쪽 위에는 전역 **프로필·모양·일반**, 아래에는 **현재 프로젝트의 일반·엔진·컴포넌트** 항목이 있습니다.
전역 설정은 시작 시 지정한 workspace의 `.hub/preferences.json`에 원자적으로 저장됩니다.
일반 설정에서 데이터 루트를 바꿔도 이 시작 설정 파일의 위치는 유지되므로 프로필·모양과
다음 시작 경로를 계속 찾을 수 있습니다.
설정 창에서도 Ctrl+Q로 셸로 복귀하며 저장하지 않은 초안은 유지합니다.

**일반**은 데이터 저장 위치·언어 팩·알림·시작 동작·대화 출력·외부 편집기·Provider 진단 카테고리로 나뉩니다.

* 데이터 저장 위치: `workspace_root`에 프로젝트·세션·로그를 저장할 경로를 지정합니다
  (예: `~/ai-data` 또는 `/mnt/d/ai-data`). 따옴표 없이 입력할 수 있습니다. 저장 후 Hub를
  재시작하면 적용되며 실행 중인 작업의 경로는 바뀌지 않습니다. 기존 데이터는 자동으로
  이동·복사하지 않습니다. 빈 폴더는 새 작업 공간으로 시작하고, 데이터가 있으면 해당 작업
  공간을 엽니다. 원래 경로를 다시 지정하면 기존 프로젝트·세션을 열 수 있습니다.
  비우면 `HubConfig.workspace`의 시작 경로로 돌아갑니다. ish의 현재 작업 디렉토리,
  독립 실행의 `HubConfig.file_root` 및 ish 자체의 설치 경로와는 별개입니다.

전역 설정 정의는 필드별 `requires_restart` 메타데이터로 적용 시점을 구분합니다.
저장 경로·언어·사용자 언어 팩·시작 시 복원·Provider 진단 설정은 재시작이 필요하고, 모양·알림·편집기 등은
저장 직후 적용됩니다. 재시작이 필요한 항목은 설명에 표시되며 저장 성공 후 확인 팝업이 나옵니다.
**Enter**는 셸을 유지하고 Hub의 UI와 백엔드를 다시 시작합니다. **Esc**는 저장값을 유지하고
재시작을 미룹니다. 미룬 뒤 값 변경 없이 다시 저장해도 재시작 팝업을 열 수 있습니다.
실행·예약 작업과 처리 중인 명령을 취소하고 정리가 끝나면 재시작합니다.
같은 프로세스에서 응답하지 않는 도구는 강제로 죽이지 않으며, 정리가 지연되면 대기 이유를 안내합니다.
프로젝트 설정은 기존대로 프로젝트 서비스에 저장되며 다음 실행의 설정 해석을 따릅니다.

* 언어 팩: `language`에 `ko`, `en` 또는 사용자 팩 코드를 지정합니다. **팩 추가/갱신**에서 코드와
  메시지 키 → 번역 문자열 JSON(예: `{"settings_title": "My Settings"}`)을 입력합니다. 기존 코드면 교체하며,
  **팩 삭제**에서 사용자 팩을 제거합니다. 내장 팩은 유지하고 빠진 번역은 영어로 표시합니다.
  팩 변경도 **저장**으로 확정하며 **취소**로 초안을 버립니다. 언어 변경은 다음 Hub 시작부터 적용됩니다.
  일반 언어가 빈 문자열이면 완전한 현재 프로필의 언어를 초기 선택으로 사용하고,
  그것도 비어 있으면 명시된 `HubConfig.language`를 사용합니다. 불완전한 옛 프로필을
  자동 보충하지 않으며, 문자열이 아닌 값이나 지원하지 않는 언어 코드는 저장 전에 거부합니다.
* 알림: `notification_kinds`는 `error`, `info`, `warning`, `success`의 JSON 배열이며 `[]`로 모두 끕니다.
  `notification_seconds`는 1~120초입니다. 종류 변경은 즉시 반영하고 시간은 이후 생성되는 알림에 적용합니다.
* 시작 동작: `restore_last_project`, `restore_last_session`을 각각 켜거나 끕니다(기본 `true`).
  `.ishrc.py`의 명시적인 프로젝트·세션 선택이 우선하며, 없어진 저장 대상은 기본 프로젝트·활성 세션으로 대체합니다.
* 대화 출력: `auto_scroll`은 기본 `true`입니다. 맨 아래를 보고 있을 때만 새 응답을 따라갑니다.
  `false`로 저장하면 읽던 위치를 유지하며 Alt + 이동키 수동 이동은 계속 가능합니다.
* Provider 상세 진단은 항상 활성화되어 서버의 오류 메시지·필드·API 주소를 기록합니다.
  `provider_request_summary`를 켜면 요청 역할·길이·Tool 대응 개수를 기록합니다(기본 `true`).
  `provider_max_detail_chars`는 상세 오류 문자열 하나당 최대 문자 수이며 기본 2000입니다.
  저장 후 Hub를 재시작하면 적용됩니다. 원문 요청·Tool 인자는 요약에 포함하지 않지만 서버 오류
  메시지에는 작업 내용이 포함될 수 있습니다. 기록은 보조 버튼의 로그에서 확인합니다.
  이 설정은 프로젝트의 재시도 정책을 변경하지 않습니다.
* 오류 분석과 복구: `recovery_enabled`는 기본 `true`이며 Hub 기본 Loop의 응답 수신 전 요청 오류를
  분석합니다. `recovery_model_analysis=true`이면 현재 모델에 짧은 진단만 보내 설명과 조치를 받습니다.
  컨텍스트 초과는 완료된 Tool 결과와 과거 대화의 입력 사본을 분할 요약한 뒤 같은 호출 위치에서
  다시 요청합니다. 원본 대화·Tool 결과·인자·승인과 현재 사용자 요청·추가 지시는 유지됩니다.
  보정 재호출도 해당 Loop의 `policy.provider.max_attempts`에 포함됩니다. 별도 Hub 재시도 횟수는 없으며,
  남은 시도가 없으면 자동 보정하지 않습니다.
  `recovery_timeout_seconds=60`, `recovery_input_chars=12000`, `recovery_summary_chars=2000`,
  `recovery_max_summary_calls=16`으로 시간·분할 입력·요약 크기·요약 호출 예산을 정합니다.
  이 값들도 Hub 재시작 후 적용됩니다. 요청 구조 요약의 저장값은 유지하며 오류 상세 수집은 항상 켜집니다.
  부분 요약은 적용하지 않으며, 응답 수신 이후 오류·사용자 취소·재시작한 과거 Run은 자동 반복하지 않습니다.
  인증·429·503·통신 오류는 백엔드 분류와 Provider 정책을 따릅니다. 직접 지정한 복구 콜백을 보존하며,
  일반 사용자 정의 Engine과 Graph에는 자동 설치하지 않습니다. 자세한 범위는 [오류 복구](../docs/hub/provider-recovery.md)를 참고하세요.

오류 안내는 실패 Step에 저장된 진단과 복구 분석을 우선 사용하고, 없으면 해당 Run 결과의 진단을 사용합니다.
진단을 위해 로그 파일이나 활동 기록을 조회하지 않습니다. 원본 로그는 로그 창에서 확인합니다.
응답 미완료는 종료 사유에 따라 출력 토큰 한도·콘텐츠 필터 등을 구분하고, 출력/Tool 크기 제한과
단계 시간 초과도 별도로 안내합니다. 이미 받은 답변은 유지합니다.
엔진의 `policy.provider.respect_retry_after`와 `jitter`를 켠 경우에도 재시도 카운트다운은
백엔드가 결정한 실제 대기 시간을 사용합니다. 기존 프로젝트의 재시도 값은 자동 변경하지 않습니다.

외부 편집기의 `editor`에는 외부 편집 작업에 사용할 명령(예: `vim`, `nano`, `code --wait`)을 미리 저장합니다.
비우면 `VISUAL`, `EDITOR`, `vi` 순서로 선택합니다. `GeneralSettings.editor_argv(path)`는 실행 인자를 반환하며
셸 코드를 해석하지 않습니다. 설정 입력칸의 `e`는 현재 적용된 에디터 명령을 사용합니다.
문자열은 텍스트 파일, 나머지 값은 JSON 파일로 편집합니다. 에디터가 자동 추가하는 마지막 개행은
원래 값에 없었으면 한 개 제거하며, 내용 중간의 개행은 유지합니다. `code`처럼 별도 창을 여는 에디터는
`--wait`처럼 종료를 기다리는 옵션을 지정해야 편집 결과를 받을 수 있습니다.
**프로필**에는 표시 이름, 이메일, 전화번호를 설정할 수 있습니다. 언어 선택은 일반 설정으로 옮겼습니다.
아래 **사용 통계**는 `Project.amodel_usage()`로 읽은 활성 프로젝트별
호출 횟수, 확인된 토큰, 예약 토큰, 사용량 미확인 호출 수와 각 프로젝트의 집계 기간을 표시합니다.
통계 영역으로 이동한 뒤 ↑↓로 스크롤하며 **불러오기**로 갱신합니다. 조회 오류는 해당 프로젝트에 표시합니다.

프로젝트 선택과 c 생성, d 삭제, e 이름 변경, r 복제는 홈의 프로젝트 목록에서 합니다.
설정 하단에는 같은 너비의 **저장·불러오기·취소**가 있습니다. 저장·취소는 전역 설정과 현재 프로젝트에
적용되며 설정 화면을 유지합니다. 불러오기는 현재 페이지를 다시 읽습니다.
프로젝트를 전환하면 해당 프로젝트의 대화 데이터를 불러오고 설정 필터는 해제됩니다.
설정 화면에는 현재 프로젝트의 항목만 표시합니다.
컴포넌트 관리 팝업에서는 경로를 입력하면 자동완성이 표시되며 Tab으로 확정합니다.
팝업 하단 설정 버튼은 해당 컴포넌트만 보이도록 필터를 적용해 설정 화면을 엽니다.
대화 패널의 프로젝트 목록은 패널 높이의 27%를 사용하고 아래에는 세션 목록이 표시됩니다.
키·설명·`- 타입 : ...` 안내는 llm의 공개 JSON Schema에서 생성하며 타입은 입력창 위에 표시합니다.
패널에서 항목을 선택하면 일반·엔진·컴포넌트별 설정이 메인 영역에 나타납니다.

문자열은 그대로, 숫자·불리언·배열·객체는 JSON으로 입력합니다. 빈칸은 미설정,
`null`은 명시적 null, 빈 문자열은 `""`입니다. 복합 스키마는 JSON 입력창으로 표시합니다.
입력하지 않은 설정과 알 수 없는 기존 키를 보존하고, 저장 시 타입·제약·설정 버전을 검증합니다.
입력값은 **저장** 버튼으로 적용합니다. 변경 사항이 있으면 `* 저장`으로 표시합니다.
**취소**는 전역 설정과 현재 프로젝트의 초안을 버리고, **불러오기**는 현재 페이지의 저장된 최신 값을 불러옵니다.
페이지를 전환해도 초안은 유지됩니다. 저장해도 이미 접수된 요청은 변경하지 않습니다.

좌측 전역 설정·프로젝트·세션 영역의 Ctrl+←/→는 공통 패널 너비를 한 칸씩 조절합니다.
너비만 `<workspace>/.hub/sidebar-width.json`에 비동기로 즉시 저장하며, 연속 입력은 최신 너비로 합칩니다.
다른 설정 초안은 저장하지 않고, 설정 취소 후에도 이 너비는 유지합니다. `모양 → sidebar_width`에서
25~60칸 범위로 직접 편집한 값은 기존 저장·취소 동작을 따릅니다. 홈/설정 버튼과 프리셋 선택을 위한 최소 너비를 유지합니다.

프로젝트 패널의 c는 이름 입력 팝업을 엽니다. 이름은 필수이며 공백만 입력하면 생성하지 않습니다.
새 프로젝트의 모델 설정은 빈칸으로 시작하며 현재 프로젝트 값을 복사하지 않습니다.
이름은 직접 지정해야 하며, 대화 저장 방식을 비워 두면 생성 시 file을 사용합니다.
모델은 나중에 지정할 수 있지만 설정 전에는 대화 요청을 전송할 수 없습니다.
기존 프로젝트를 열거나 복제할 때는 저장된 설정을 유지하며, 복제 버튼에서도 새 이름을 지정합니다.
삭제는 확인창을 거치는 소프트 삭제입니다. 실행 또는 예약 요청이 있으면 복제·삭제를
거부합니다. 현재 대화에 열린 프로젝트를 삭제하려면 다른 프로젝트의 **열기**로
먼저 전환하세요. 대화 저장 방식은 Session이 없는 프로젝트에서만 변경할 수 있습니다.

## 파일 안내

### 확장 출력 블록

Assistant 응답의 독립된 줄에 XML 요소를 넣으면 `OutputParser`가 Markdown과
`OutputBlock`으로 분리하고 `RendererRegistry`가 해당 렌더러로 전달합니다.

```xml
<hub-image src="images/result.png" alt="생성 결과" />
```

`src`는 현재 프로젝트의 파일 루트(또는 HubConfig.file_root)를 기준으로 해석합니다.
코드 블록·인라인 코드·들여쓴 코드의 태그는 해석하지 않습니다. 알 수 없는 태그와
잘못된 XML은 원문으로 표시합니다. 태그는 스트리밍 중 완성된 후 처리합니다.
본문에 `<`나 `&`가 필요하면 XML 이스케이프를 사용합니다. 중첩 요소와 DTD/CDATA는 지원하지 않습니다.
기존 Markdown 이미지를 자동 변환하는 기능이나 diff 전용 렌더러는 아직 포함하지 않습니다.

이미지는 ascii_magic으로 UI 스레드 밖에서 변환하고 PTK 문자·색상으로 그립니다.
외부 URL은 자동 다운로드하지 않으며, 이미지 변환 자체가 모델 호출을 발생시키지 않습니다.
파일은 16 MiB·800만 픽셀 이내, 출력은 최대 100열·40행으로 제한합니다.
한 세션 화면에서 최대 32개를 캐시하며, 세션 전환·너비 변경 시 캐시를 비웁니다.
원본 이미지가 같은 경로에서 바뀌면 `view.output.images.reset()` 후 화면을 갱신하세요.

`.ishrc.py`에서 실제 파일을 명시적으로 연결할 수도 있습니다.

```python
installation = hub_plugin.install(prompt)
installation.view.output.images.register_artifact("preview", "/path/to/result.png")
# 응답: <hub-image src="artifact:preview" alt="결과" />
```

아티팩트 매핑은 UI 실행 중에만 유지됩니다. 재시작 후에도 표시하려면 다시 등록하거나
프로젝트 상대 경로를 사용하세요. 새로운 렌더러는 다음처럼 등록합니다.

```python
class BadgeRenderer:
    def render(self, block, context):
        # context: width, theme, language, root, invalidate
        return [[("class:hub.accent", dict(block.attributes).get("text", ""))]]

installation.view.output.renderers.register("hub-badge", BadgeRenderer())
# 응답: <hub-badge text="완료" />
```

렌더러는 PTK `(style, text)` 조각의 행 목록을 반환하며 터미널에 직접 출력하지 않습니다.
시간이 걸리는 작업은 백그라운드에서 처리하고, 완료 시 `context.invalidate()`를 호출합니다.
캐시 갱신 시 렌더러의 `revision` 값을 증가시키면 대화 출력 캐시도 갱신됩니다.

### 설정과 초기 선택의 소유권

llm은 기본 Project/Session을 만들거나 선택하지 않습니다. Hub가 최초 템플릿과 마지막
선택을 소유합니다. 명시한 Project ID, 복원 가능한 마지막 Project, 가장 오래된 활성
Project 순으로 선택하며, 활성 Project가 없을 때만 `projects.acreate()`를 호출합니다.
`.hub/startup.lock`으로 동시 Hub 시작을 직렬화합니다. llm의 default-project 포인터는 없습니다.
Session은 사용자가 생성합니다. Session 설정은 `parameters.engines.<이름>`에서 명시적으로
덮어쓰고 Project 값을 생성 시 복사하지 않습니다. 프로젝트 공용 전달 인자는 대상별
딕셔너리이며, 모델 설정은 각 Agent의 `completion`에 둡니다. Engine에는 실행 설정만 둡니다.

HubConfig.model/api_base는 **신규 Project**의 loop에 적용하는
Hub 템플릿입니다. 다른 사용자 엔진에는 자동 전파하지 않습니다. 이름이 다른 엔진은
project_config.parameters.engines에 명시하세요. 자동 제목은 내부 `_hub_title` 엔진이 대화 엔진의
모델 설정을 기본으로 사용합니다. 이 내부 엔진은 설정 목록과 JSON 편집에서 숨기며 저장된 별도 설정은
보존합니다. 구성 API는 모든 컴포넌트 설정과 출처를 계속 한 번에 제공합니다.

### 기본 시스템 프롬프트와 스킬

새 프로젝트에는 `asset/guides.py`에 등록된 기본 시스템 프롬프트와 일곱 가지 Skill을 복사합니다.
프롬프트 본문은 `asset/prompts/system.md`, Skill 정의는 `asset/skills/<name>/SKILL.md`에서 관리합니다.
기본 프롬프트와 Skill의 이름·설명·본문은 모두 영어이며, 답변은 사용자의 언어를 따릅니다.
초기 실행과 홈 패널의 프로젝트 생성 모두 동일한 템플릿을 사용합니다.
모델 이름이나 API 키는 기본값으로 채우지 않습니다. 기존 프로젝트는 자동 변경하지 않습니다.

| Skill ID | 용도 |
| --- | --- |
| `hub-code-change` | 코드 맥락 확인, 필요한 수정, 검증과 결과 보고 |
| `hub-diagnose` | 재현, 증거와 가설 구분, 원인 수정과 재검증 |
| `hub-document` | 독자·목적에 맞춘 작성, 근거·예시·형식 확인 |
| `hub-create-rag/workflow/skill/agent` | 스키마·자료 확인, 공개 도구로 생성, 저장 결과 검증 |

시스템 프롬프트는 `config.parameters.engines.loop.config.system_prompt`에 저장하며 설정 화면에서
편집할 수 있습니다. 생성 시 명시한 값(빈 문자열·null 포함)을 유지합니다. 프롬프트는 사용자의
언어로 응답하고, 실제 가능한 작업을 수행·검증하며, 관련 Skill을 먼저 찾아 읽도록 안내합니다.
등록된 Skill은 `/skill` 관리 창으로
관리합니다. 수정·삭제한 내용을 다시 열 때 복원하거나 덮어쓰지 않습니다.

일반 Loop는 llm이 제공하는 `skill_list`·`skill_read` Tool로 필요한 지침을 읽을 수 있습니다.
Graph Agent는 `tools` 허용 목록에 이 두 도구를 포함하거나 `resources.skills`에 Skill ID를 연결합니다.
Skill은 지침이며 실행 도구나 권한을 제공하지 않습니다. 파일 수정·셸 실행·웹 검색은 해당 Tool이
별도로 등록되고 실행 정책에서 허용되어야 합니다. Skill 준수나 결과의 품질을 강제로 보장하지는 않습니다.

진행 중인 컴포넌트 명령은 페이지 하단에 Rich 진행 막대와 작업명을 표시합니다.
진행량을 알 수 있는 작업은 퍼센트를 함께 표시하며 경과 시간은 표시하지 않습니다.
설정 불러오기·저장에도 같은 표시를 화면 하단에 사용하며, 작업이 끝나거나 실패하면 알림으로 바뀝니다.
진행 표시는 포커스를 받지 않으며, 대화·설정 화면에서 항상 한 줄의 공간을 확보합니다.
작업이 없으면 알림 또는 빈 줄을 유지하고, 실행 중에는 Rich 기본 길이(40칸)의 막대를 표시합니다.
여러 작업이 겹치면 최근 시작한 작업과 나머지 작업 수를 한 줄에 표시합니다.
설정 화면의 별도 로딩 문구는 표시하지 않으며, 오류·저장 결과 안내는 유지합니다.
프로젝트·모양 설정은 화면에 보이는 항목 위주로 렌더링하고 항목 높이를 캐시하여,
컴포넌트 설정이 많아져도 화면 밖 입력칸을 매번 그리지 않습니다.
세부 진행률을 전달하지 않는 컴포넌트·설정 API에는 퍼센트 없는 진행 막대를 사용합니다.
RAG 관리 창의 가져오기·수정은 같은 진행 표시를 사용합니다.
등록은 영속 RAG Job과 실제 단계 진행률에 연결됩니다. `/rag add file/run` 명령은 제공하지 않습니다.
컴포넌트 관리는 화면 선택용 공용 잠금을 점유하지 않습니다. 실제 데이터 변경은 각 서비스의
수명·버전 검사와 잠금을 따르므로 같은 데이터를 변경하는 작업은 대기하거나 충돌할 수 있습니다.

## 내장 도구와 질문 입력

`/tool`에서 내장 도구를 Space로 켜고 끌 수 있습니다.
내장 도구는 기본 활성화이며, 직접 비활성화한 상태는 유지합니다.
`ask_user` 질문이 오면 기존 입력창이 답변 모드가 되고, 텍스트나 선택지 번호를 입력한 뒤
Enter를 누르면 같은 작업이 이어집니다. 도구 승인은 같은 입력창에서 명시적으로 선택합니다.
자세한 수명·저장·실행 정책은 [질문·내장 도구](../docs/hub/questions-tools.md)를 참고하세요.

`test_workspace_create/list/execute/delete`로 테스트 공간을 만들고 OS 샌드박스 명령을 실행할 수
있습니다. 기존 Project에는 `/tool`에서 필요한 새 도구를 선택하세요.
파일 도구에 `workspace_id`를 주면 테스트 파일을 작성·확인합니다. 생성·실행·삭제는 기존
승인 경로를 거치며, Run 종료 후에도 산출물은 명시적 삭제까지 남습니다. Linux Bubblewrap이
필요하고 네트워크는 차단됩니다. [설정과 격리 범위](../docs/llm/test-workspaces.md)를 참고하세요.

구조와 로그 경로의 책임 구분은 [Hub 구조 정리](../docs/hub/structure.md)를 참고하세요.

공개 Skill API를 통한 코딩 스킬 복사, 실제 격리 테스트,
준비 중 표시와 오른쪽 방향키 추천 입력은 [코딩 작업 안내](../docs/hub/coding-workflow.md)를 참고하세요.

생각 중 상태, Gemini 생각 요약 설정과 청크 단위 출력 진단은
[Completion 표시 안내](../docs/hub/completion-display.md)를 참고하세요.

새 프로젝트의 일시적 공급자 오류 재시도, 샌드박스 명령 인자 피드백과 대화 화면의
마우스 휠은 [응답 안정성 안내](../docs/hub/response-reliability.md)를 참고하세요.


### 보조 버튼과 테마

홈 입력창과 설정 하단 버튼 영역 바로 위에 투명한 한 줄을 예약합니다.
오른쪽에 한 아이콘씩, 한 칸 간격으로 버튼을 배치합니다. 버튼 바탕에는 모양 설정의 배경색을 사용합니다.

- 홈: 요청 목록, 태그 바, 찾기, 파일 첨부, 로그, 설정.
- 설정: 필터, JSON 편집. JSON은 등록된 에디터에서 편집하고 저장 전 초안에 반영합니다.
- 입력창 또는 설정 버튼에 포커스가 있을 때 Ctrl+S: 보조 버튼으로 이동.
- 좌우 방향키: 버튼 선택. 상하 방향키: 동작 없음. Enter/Space: 실행. ESC: 직전 입력창/설정 버튼으로 복귀.
- 홈 Ctrl+F/G/L/T는 동작하지 않습니다. 설정과 확대 뷰어의 검색은 해당 화면의 안내를 따릅니다.
- 파일 첨부는 경로 자동완성으로 선택한 파일 경로를 기존 입력에 삽입합니다. 파일을 읽거나 업로드하지 않습니다.

설정 필터는 좌측 항목과 프로젝트를 바꾸어도 유지하며 상태 행에 `필터 : ...`를 표시합니다.
빈 검색어를 적용하면 필터와 표시가 즉시 사라집니다. 내부 자동 제목 엔진 `_hub_title`은
일반 설정 목록과 JSON 편집에서 숨기며 기존 저장값은 보존합니다.

홈의 설정 보조 버튼은 현재 선택한 엔진과 관계없이 Loop 엔진 설정으로 이동합니다.
설정의 JSON 보조 버튼은 현재 페이지의 설정 초안을 일반 설정에 등록된 에디터에서
`.json` 파일로 엽니다. 에디터에서 저장 후 종료하면 JSON·스키마·호스트 고정값을 검증하고
초안에 반영합니다. 실제 설정 적용은 저장 버튼으로, 되돌리기는 취소 버튼으로 합니다.
유효하지 않은 JSON은 기존 초안을 바꾸지 않으며 같은 페이지에서 JSON 버튼을 다시 누르면
잘못된 내용을 이어서 고칠 수 있습니다. `_hub_title` 설정은 편집 파일에서 숨기고 원래 값을 보존합니다.

편집 가능한 입력창에 포커스가 있으면 Ctrl+A 전체 선택, Ctrl+C 복사, Ctrl+X 잘라내기,
Ctrl+V 붙여넣기, Ctrl+Z 실행 취소, Ctrl+Y 다시 실행을 사용할 수 있습니다. 선택 영역은
입력·붙여넣기·Delete·Backspace로 교체/삭제됩니다. Shift+방향키/Home/End, Ctrl+Shift+←→/Home/End,
마우스 드래그로 선택하고 Ctrl+←→는 단어, Ctrl+Home/End는 문서 양 끝으로 이동합니다.
설정 항목은 Enter로 편집을 시작한 뒤 적용되며, 읽기 전용 항목과 셸 키 설정은 변경하지 않습니다.
작업 중단/재개는 홈 입력창의 Ctrl+D, Hub 재시작은 모든 화면에서 Ctrl+W입니다. 터미널이 전달하지 않는 키 조합은 사용할 수 없습니다.
모양은 저장한 색을 그대로 사용하며 dark/light 선택과 자동 색상 보정은 없습니다.
강조 색 1은 일반 실행·선택 위젯 배경, 강조 색 4는 하단 키 안내 배경,
강조 색 5는 입력칸·코드 등의 일반 위젯 배경입니다. 페이지 배경과 전경은 별도 설정을 따릅니다.
일반 버튼 글자는 강조 색 5를 사용합니다. 상단·보조 버튼과 드롭다운 글자는 강조 색 4를 유지합니다.
비활성 영역은 각 색의 밝기를 보존한 흑백으로 표시하며, 원래 투명한 배경은 채우지 않습니다.
좌측 패널에서도 현재 포커스된 카테고리만 본래 색으로 표시합니다.

복사는 성공 안내로 상태 행을 덮어쓰지 않습니다. 시스템 클립보드를 먼저 사용하고,
확인된 OSC 52 터미널에만 짧은 제어 문자열을 전송합니다. 지원 여부가 불명확한 VM/터미널이나
긴 복사 내용은 전체 내용을 내부 레지스터에 보존합니다. 호스트의 OSC 52 지원 및 멀티플렉서
전달 설정을 확인한 환경은 `HUB_OSC52=1`로 명시적으로 허용할 수 있고 `HUB_OSC52=0`은 비활성화합니다.
