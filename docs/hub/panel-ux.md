# 패널·설정 탐색과 오류 안내

## 공통 패널

두 페이지 모두 패널 하단에 `사용자 별명 • 운영체제 계정`을 표시합니다. 홈/설정 버튼과 프리셋 드롭다운을 가운데 정렬합니다.
별명은 전역 프로필의 display_name을 사용합니다. 이름 행에는 배경색을 적용하고,
버튼 위·아래에 한 줄씩 공간을 둡니다. Ctrl+P 또는 영역 안의 클릭으로 포커스를 옮깁니다.
버튼은 ←→로 선택하고 Enter/Space로 실행합니다. Tab/Shift+Tab·↑↓는 아무 동작도 하지 않습니다. ESC는 목록으로 돌아갑니다.
팝업·태그 바의 포커스 제한은 그대로 유지합니다.

두 위젯이 한 줄에 들어가도록 패널은 최소 25칸을 확보합니다. Ctrl+←→와 경계 드래그는
같은 최소 너비를 사용하며 너비만 독립 저장합니다.
맨 위 카테고리(홈의 프로젝트, 설정의 전역 설정)는 고정합니다. 아래 카테고리
(홈의 세션, 설정의 프로젝트)에 포커스가 있을 때 그 제목 또는 제목 아래 구분선을
위아래로 드래그하면 두 목록 사이의 높이를 조절합니다. 제목 옆 버튼은 드래그 대상이 아닙니다.
카테고리 구분선에도 우측 경계와 같은 마우스 호버 강조를 적용합니다.
하단 프로필은 고정되고, 두 목록에는 제목과 최소 한 항목을 표시할 공간을 남깁니다.
드래그 중에는 화면만 갱신하고 마우스를 놓을 때 높이 비율을 저장합니다.
홈과 설정의 비율은 각각 기억하며 터미널 높이가 바뀌어도 저장한 비율을 사용합니다.
패널 너비와 높이는 모양 설정의 입력 항목으로 노출하지 않습니다.
너비는 기존 `.hub/sidebar-width.json`, 높이는 `.hub/sidebar-heights.json`에서 관리합니다.
다른 설정 초안이나 프로젝트 설정을 저장하지 않습니다.

## 홈

상단 바에는 프로젝트 이름 대신 **홈**을 표시합니다.
프로젝트 목록의 초기 높이는 패널 전체 높이의 27%이며 드래그로 바꿀 수 있습니다.
극단적으로 낮은 터미널에서는 세션과 프로필 영역을 위한 최소 공간을 우선합니다.
프로젝트를 선택하면 해당 프로젝트의 세션과 저장된 읽기 위치를 불러옵니다.
목록은 ↑↓ 또는 마우스로 선택합니다. 카테고리는 Tab/Shift+Tab으로만 이동하며 ↑↓는 목록 경계에서 멈춥니다. Space/Enter/→는 메인 영역으로 이동합니다.
Tab으로 이미 표시 중인 세션에 돌아올 때는 포커스만 바꾸며, 실행 기록을 다시 요청하거나
출력·입력 초안·읽기 위치를 재설정하지 않습니다.
프로젝트 목록의 c/d/e/r은 생성/삭제/이름 변경/복제이며 세션 목록은 기존 세션 작업을 수행합니다.
현재 프로젝트 삭제는 실행·예약 작업이 없고 다른 프로젝트가 있을 때만 가능합니다.
마지막 프로젝트를 지우려면 먼저 다른 프로젝트를 만들어야 합니다.

## 설정 페이지

전역 설정은 유지하며 프로젝트 항목에는 **현재 프로젝트의 일반·엔진·컴포넌트**가 나옵니다.
프로젝트 제목 앞에 별도의 빈 행을 예약하지 않아 위 목록의 표시 공간을 가리지 않습니다.
각 항목은 같은 프로젝트 초안을 공유하여 다른 항목으로 이동해도 편집 내용이 유지됩니다.
검색은 현재 항목에 적용됩니다. 프로젝트를 전환하면 남아 있던 필터를 해제합니다.
설정 보조 버튼으로 설정을 열며, 컴포넌트 관리 창의 설정 버튼은 해당 컴포넌트 항목으로 이동합니다.

- 저장: 전역 설정과 현재 프로젝트의 초안을 검증해 저장하고 설정 화면을 유지합니다.
- 취소: 전역 설정과 현재 프로젝트의 미저장 변경을 되돌리고 설정 화면을 유지합니다.
- 홈: 대화로 돌아갑니다. 미저장 초안은 유지하되 다른 프로젝트의 저장 대상에 포함하지 않습니다.

재시작이 필요한 설정은 저장 후 기존 재시작 팝업으로 안내합니다. 호스트 고정 값과
서비스 버전 충돌 검사는 유지합니다. 저장 일부만 성공하면 성공한 초안만 반영합니다.

## 실패 안내

실패한 어시스턴트 응답 아래에 원인과 다음 조치를 표시합니다. 같은 프로젝트·세션·Run의
오류 코드와 제공자 진단 기록을 사용하며 API를 추가 호출하지 않습니다. 429, 인증 오류,
서버 오류, 시간 초과, 연결 실패, 잘못된 요청, 빈 응답 등에 대한 한국어·영어 안내를 제공합니다.
일반 사용자는 이 안내를 먼저 보고, 필요한 경우 보조 버튼의 로그로 상세 기록을 확인할 수 있습니다.

알 수 없는 오류는 원인을 단정하지 않습니다. 이전 제공자 오류가 복구된 뒤 도구에서 실패한
경우 그 제공자 오류를 현재 실패 원인으로 재사용하지 않습니다. 로그 원문이나 요청 내용을
다른 모델로 전송하지 않으며, 진단 기능이 작업을 자동으로 재실행하지도 않습니다.
진단 파일 읽기는 백엔드의 별도 비동기 요청으로 수행하고 결과를 제한된 캐시에 보관합니다.

## 구현과 검증

### 같은 항목 재선택

화면 선택과 명시적 새로고침/실행을 구분합니다. 공통 `SidebarList`의 선택 통지를
일괄 차단하지 않고, 각 화면이 현재 표시 중인 대상과 비교합니다. 설정에서는 목록의
기억된 항목이 같아도 현재 표시 페이지가 다른 경우 실제 전환이 필요하기 때문입니다.

- 홈: 현재 세션은 출력·입력 초안·읽기 위치를 유지하고 백엔드 선택 요청을 생략합니다.
- 설정: 유휴 상태의 현재 페이지 재선택은 폼·스크롤·탭을 유지합니다. 로딩 중의 마지막
  선택, 저장 후 표시, 명시적인 `choose`와 불러오기 경로는 계속 실행합니다.
- Agent 편집: 같은 섹션은 편집 모드만 마무리하며 폼과 스크롤을 다시 만들지 않습니다.
- TabPage: 현재 탭의 반복 선택·목록 경계 이동은 포커스만 복구하고 변경 콜백을 재호출하지 않습니다.
- MCP 도구 선택: 같은 Agent는 체크 초안과 목록 위치를 유지합니다. 실제 Agent 전환은 기존 초안을 복원합니다.
- Workflow: 같은 노드 선택은 그래프 위치만 보여줍니다. 다른 노드로 이동할 때의 입력 검증과
  적용·취소·저장 버튼 동작은 유지합니다.

컴포넌트·대화 상대 목록은 선택 시 백엔드를 조회하지 않습니다. 요청 목록은 이미 같은
항목의 본문 교체를 생략하며, 질문은 동일 identity의 관측을 갱신하되 입력 초안을 유지합니다.
태그 재선택의 본문 위치 이동, 승인 관리의 명시적 최신 상태 조회, 프리셋 재적용과 이미지
표시 모드 버튼은 목적이 있는 동작이므로 단순 재선택으로 생략하지 않습니다.
백엔드 CAS·승인·재개 검증과 영속 데이터의 원본은 변경하지 않습니다.

`test_reselection.py`와 기존 화면별 검사에서 불필요한 조회/출력 초기화가 없는 것과
다른 항목으로의 정상 전환을 함께 확인합니다.

- `widget/profile.py`, `widget/sidebar_panel.py`: 공통 프로필과 패널 높이 배분.
- `ui/chat/projects.py`: 프로젝트 목록 탐색과 CRUD. 목록 조회는 사용량·설정 계산을 하지 않습니다.
- `ui/settings/pages.py`, `drafts.py`: 섹션별 표시와 공유 초안, 현재 프로젝트 저장 범위.
- `backend/observability/failures.py`: 저장된 실패 증거 분류, 읽기 전용 진단 캐시.
- 실제 PTK 키·마우스, 리사이즈, 초안 저장/취소, 프로젝트 전환과 실패 응답 표시를 검사합니다.
  외부 제공자는 호출하지 않으며 테스트 제공자가 구조화된 오류를 반환합니다.
- 세션 전환 직후 이전의 빈 화면 캐시가 남아 있을 때도 이동키를 보관하고 새 화면에 적용합니다.
  아직 출력이 그려지지 않았다는 이유로 입력한 스크롤이 사라지지 않도록 회귀 검사를 추가했습니다.

- WSL Linux Python 3.12.14, Linux 파일시스템 소스 스냅샷에서 실행했습니다.

  결과: `tests/llm/reports/ish-provider-t9hxixw5/hub.txt`, `focused.txt`.
- 백엔드 전체 **1,445개 통과**. 결과: `tests/llm/reports/ish-provider-rwe9aurz/suite.txt`.
  백엔드 실행의 선행 선택 모듈 지정 오류와 별개로 전체 suite는 종료 코드 0입니다.
  `llm/` 구현은 수정하지 않았습니다.

  검사는 수정 전 조건에서 실패하고 수정 후 통과하며, 최종 전체 실행에서도 위치 복원이 통과합니다.

  검증 후 변경은 이 결과 문서뿐입니다.
- 실제 PTK 렌더를 132×40, 80×24 크기로 검사하고 공통 프로필, 27% 프로젝트 영역,
  설정 섹션과 포커스 색상을 확인했습니다.
