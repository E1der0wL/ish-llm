# 홈 탐색과 요청 문맥

## 화면과 조작

- 기존 대화 페이지의 이름은 **홈**이며 상단 바도 프로젝트 이름 대신 홈을 표시합니다.
- 홈의 프로젝트·세션, 설정의 전역·프로젝트 카테고리는 **Tab / Shift+Tab**으로 이동합니다.
  ↑↓는 현재 목록 안에서만 움직이고 경계에서 멈춥니다. Space / Enter / →는 메인 영역으로 이동합니다.
  설정에서는 메인 영역의 탭 목록으로 진입합니다. ←→로 설정/정책을 전환하고,
  Enter/Space로 탭 내용에 진입하며 ESC로 탭 목록에 복귀합니다.
  마우스로 항목을 선택하는 동작은 유지하며 빈 공간을 클릭하면 포커스만 이동합니다.
- 프로필은 Ctrl+P 또는 클릭으로 진입합니다. 가운데 정렬된 **설정 또는 홈 / 프리셋**을
  ←→로 선택하고 Enter / Space로 실행합니다. 프로필에서 Tab / Shift+Tab·↑↓는 동작하지 않습니다.
  ESC는 패널 목록으로 돌아가며 최소화는 Ctrl+Q를 사용합니다. 열린 프리셋 목록은 위아래
  방향키로 선택하고 Enter/Space로 적용하며 ESC로 취소합니다.
- 추천 요청은 입력한 내용과 접두사가 일치하거나 입력창을 모두 지웠을 때 다시 보입니다.
  커서가 입력 끝에 있을 때 →로 나머지를 채우며 자동 전송하지 않습니다.
- 모든 페이지 오른쪽 상단의 일반 버튼 `` / ``는 재시작 / 최소화입니다.
  Ctrl+W는 팝업·태그 바·설정 편집 중에도 Hub 재시작을 요청하며 Ctrl+Q는 최소화입니다.
  재시작은 신규 접수를 막고 실행·예약·백그라운드 작업을 취소·정리한 뒤 Hub를 다시 엽니다.
  Ctrl+D 중단/재개는 홈 입력창에 포커스가 있을 때만 적용합니다.
- 수신된 응답 청크는 다음 출력 갱신에 전체를 렌더링합니다. 문자 단위 애니메이션이나
  완료 후 남은 글자를 표시하는 별도 큐는 없습니다. 출력 갱신 주기 설정은 그대로 유지합니다.

## 대화 이력과 중단

새 요청에는 완료된 이전 요청·응답만 포함합니다. 실패·중단·취소·일시 정지·응답 없는 요청은
화면과 저장된 이력에는 남지만 새 모델 입력에서는 제외합니다. 선택은 문맥 예산 적용 전에
이루어집니다. 편집·재시도 이력은 논리적인 요청 단위로 판단하며, 완료된 재개 이력과 현재
체크포인트의 도구 결과는 보존합니다.

Ctrl+D는 실행 중인 Run뿐 아니라 일시 정지된 최신 요청도 중단합니다. 헤더의 중단 중 표시와
입력창의 질문 숨김은 즉시 적용되고, 저장 후 스냅샷으로 확정합니다. 예약 요청은 취소하지 않습니다.

`llm.interrupt()`는 살아 있는 실행 작업만 대상으로 하므로, 일시 정지는 공개 API로 대기 중인
interaction을 취소하고 Session metadata의 `hub_stopped_runs`에 중단 시각을 저장합니다.
백엔드 Run과 체크포인트의 원래 `paused` 기록은 변경하지 않습니다. Hub의 출력·세션 상태·요청
목록·알림은 공통 변환으로 `interrupted`를 표시하며 재시작해도 유지됩니다. llm 원본 로그에는
원래 실행 상태가 남습니다.

중단된 최신 요청을 명시적으로 재시도하면 취소한 승인·질문을 다시 엽니다. 승인 없이 도구를
실행하지 않습니다. 이후 다른 요청이 진행된 경우 과거의 취소된 질문은 자동으로 복원하지 않으며,
요청 목록의 편집으로 다시 시작하도록 안내합니다. 질문 없는 체크포인트는 기존 재개 검증을 사용합니다.

## 공통화와 정리

- `SidebarList`가 목록 내부 이동·선택을, `TwoPanelPage`가 카테고리 순환을 담당합니다.
  프로젝트·설정에서 중복되던 경계 이동 코드를 제거했습니다.
- `ActionBar`를 프로필에도 재사용하고 `Button`에 동적 이름을 지원해 저장 버튼의 렌더링 재정의를 제거했습니다.
- 홈 헤더는 실제 표시하는 `HeaderBar` 하나를 사용합니다. 별도 임시 헤더 생성 함수는 제거했습니다.
- 사용하지 않게 된 `TurnIndex.context_records()`를 제거했습니다. 화면·Backend 경계를 유지하며
  중단 상태 변환은 `backend/execution/stopping.py`에 모았습니다.
- 추천 입력은 변경 이벤트를 관찰하지만 표시할 문자열이 같으면 불필요한 갱신 이벤트를 보내지 않습니다.

회귀 검사는 `tests/hub/test_home_navigation.py`, `test_context.py`, `test_paused_stop.py`,
`test_interrupt_feedback.py`, `test_followup.py` 및 기존 호스트·설정 키 테스트에서 수행합니다.

## 컴포넌트 설정 이동과 버튼 키 점검

`/tools config`, `/skills config`, `/mcp config`, `/rag config`, `/agents config`, `/workflows config`의
설정 버튼은 현재 프로젝트의 해당 컴포넌트 항목을 선택하고 첫 입력칸으로 이동합니다.
처음 프로젝트 설정을 불러오는 경우와 기존 설정 초안을 재사용하는 경우를 모두 검사합니다.
이 바로가기와 홈의 Loop 설정 보조 버튼은 이전 검색 필터를 해제하고 해당 페이지 전체를 보여줍니다.
좌측 패널에서 일반적으로 페이지를 전환할 때는 사용자가 적용한 필터를 유지합니다.

설정·프로필·일반 팝업·출력 확대 화면의 버튼은 `widget/actions.py`의 공통 키 처리를
사용합니다. ←→로 선택하며 양 끝에서 멈추고, Enter / Space로 실행합니다. ↑↓는 버튼
선택을 바꾸지 않습니다. 코드 뷰어에 추가되는 원문·코드 복사 버튼도 같은 규칙을 사용하며
하단 안내는 실제 키 바인딩에서 생성합니다.

Tab은 영역의 역할에 따라 동작합니다. 좌측 패널에서는 카테고리를, 설정 메인 영역에서는
설정 항목과 버튼 영역을, 일반 팝업에서는 입력칸·목록·버튼을 순환합니다. 프로필에서의
Tab / Shift+Tab은 기존처럼 무동작입니다. 도움말·로그는 읽기 전용이므로 이동키가 계속
내용 스크롤로 동작합니다.

`test_component_managers.py`는 관리 팝업의 실제 키 입력을 통해 선택 항목·필터 해제·포커스를
확인합니다. `test_input_contract.py`는 일반 팝업과 코드 확대 화면의 버튼 이동·안내·실행,
입력칸 복귀 및 기존 도움말·로그 키를 검증합니다.

Hub 입력칸의 초기 커서와 키보드 포커스 복귀 위치는 텍스트 끝입니다.
팝업·페이지 탐색은 `widget/focus.py`의 공통 처리를 사용합니다. 입력칸에 머무는 동안의
방향키·Home/End·마우스 위치 선택은 유지하며, 읽기 전용 출력에는 이 규칙을 적용하지 않습니다.
