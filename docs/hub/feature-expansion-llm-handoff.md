# Hub 기능 확장을 위한 llm 작업 지침서

작성일: 2026-11-01

대상: `llm/` 백엔드 작업자와 이후 Hub 연결 작업자.

목표는 이미지 표시 방식 선택, Workflow 시각적 편집, 터미널 관측·리뷰, 기본 스킬 확장,
실시간 양방향 음성, 스티어링 반응성 개선을 지원하는 것이다. 기존 공개 API를 재사용하고,
실제로 부족한 계약만 보강한다. 이 문서는 **후속 구현 지침이며 구현 완료 보고가 아니다.**

조사 기준은 HEAD `6a4cc00b9848e47a3d639c21c3f427fdca5ea35a`와 작성 당시 작업 트리다.
파일·프로세스 출력 계약 등에 별도 미커밋 변경이 있으므로, 작업 시작 시 최신 소스와 계약을
다시 확인한다. 기존 수정사항을 되돌리거나 과거 테스트 결과를 새 변경의 통과 근거로 사용하지 않는다.

## 1. 범위와 우선순위

| 기능 | 기존 API로 가능한 범위 | llm 보강 판정 | Hub 책임 |
| --- | --- | --- | --- |
| 이미지 표시 | Hub 이미지 출력 객체·ASCII 렌더러, Vision 등록·가공·OCR·모델 입력 변환 | 터미널 표시만을 위한 새 백엔드는 불필요. 관리 이미지의 효율적인 바이트 조회·수명 표현이 부족할 때만 보강 | ASCII/실제 이미지/자동 선택, 터미널 기능 확인, 배치·스크롤·화면 전환 정리 |
| Workflow 시각적 편집 | 그래프 빌더·스키마·구조 검증, handler 설정 스키마, CRUD·버전 충돌 검사, 실행 이벤트 | 실행하지 않는 편집용 통합 검증과 위치가 구조화된 진단이 필요. 기존 선언을 재사용하는 공개 진입점 보강 | 그래프 배치, 노드·간선 편집, 설정 폼, 검증 결과 강조, 실행 진행 표시 |
| 터미널 관측·리뷰 | 명령 실행·상태·출력 페이지·취소, Linux 시스템/프로세스 관측, 파일·Git 도구, Run/Step 조회 | 1차 기능에 새 실행 계층 불필요. 빠진 관찰 정보·구독 경계만 검증 후 보강 | 관측 대상 선택, 근거 조립·리뷰, ish에서 직접 실행한 명령을 관측하기 위한 Host 연동 |
| 기본 스킬 확장 | Skills 저장·조회·자료 읽기, Agent 도구·리소스 선택 | 원칙적으로 추가 API 불필요 | 스킬 내용·초기 제공·선택적 로딩·사용자 수정 보존 |
| 실시간 양방향 음성 | 기존 텍스트 요청·steering·예약·승인·질문·출력 이벤트 | 오디오 스트리밍 연결·형식·취소·연결 종료·사용량 계약 필요. STT→텍스트 Run→TTS와 네이티브 음성을 구분 | 마이크/스피커, 발화 감지, 자막, 재생, 장치 연결, 음성과 입력창의 일관된 조작 |
| 스티어링 반응성 | 같은 Run의 추가 지시, 대상 조회, 반영 영수증, Graph 미래 실행 예약 | 도구 사이의 안전한 반영 경계와 선택적 Provider 연동 보강 필요 | 전달 대상·방식 선택, 접수/반영 대기/반영/미반영 표시 |

권장 작업 순서:

착수 시 최신 공개 API·소유자·테스트 목록을 확인하고 없는 기능과 단순 미연결 기능을 분리한다.
그 뒤 다음 순서로 진행한다. 음성 전체가 끝날 때까지 기존 API를 사용하는 Hub 작업을 막지 않는다.

1. **기존 API로 가능한 Hub 기능**: 이미지 표시, 터미널 관측·리뷰, 기본 스킬과 기존 Graph 지시 예약을
   연결한다. 이미지·관측에서 입증된 공개 API 공백만 해당 소유자에 보강한다.
2. **Workflow 초안 검증**: 실행 없는 구조·정적 환경 검증과 위치 진단을 먼저 제공하고 편집기에 연결한다.
   실행 직전 확인과 재사용 가능한 순수 검증을 구분한다.
3. **Tool 사이 추가 지시 반영**: 미실행 호출의 기록·Provider 입력·체크포인트·재개 계약부터 확정한 뒤
   안전한 경계에서 재판단하도록 구현한다. 단순히 지시 확인 지점만 추가하는 것으로 완료하지 않는다.
4. **STT → 기존 텍스트 Run → TTS**: 장치/Provider 연결을 작게 검증하고 확정 발화의 접수·중복 방지,
   기존 승인·스티어링·명시적 완료 검토와 연결한다. 이 단계부터 구현할 음성 경로를 명시한다.
5. **필요할 때 네이티브 음성 Provider**: 실제 선택한 adapter의 지원 계약을 확인한 뒤 별도 단계로 진행한다.
   S2의 응답 중 지시 지원도 해당 Provider가 지원할 때만 추가한다. 모든 Provider의 필수 기능으로 만들지 않는다.

각 단계에서 관련 집중·소비자 회귀를 수행한다. 통합 완료 시 전체 llm·Hub 회귀를 실행하고,
네이티브 음성 등 보류한 범위는 구현 완료로 표시하지 않는다. 검증 범위와 증거 재사용은
[검증 정책](../llm/verification-policy.md)을 따른다.

일괄적인 Engine 재작성, 범용 관리 프레임워크 추가, GUI 컴퓨터 조작은 이 범위에 포함하지 않는다.

## 2. 유지해야 할 공통 계약

- Project → Session → Run → Step 소유 관계와 현재 Agent/수신 대상 실행 계약을 유지한다.
  Workflow·Agent 정의나 오디오 연결을 새로운 영속 실행 계층으로 만들지 않는다.
- Engine은 이벤트를 내보내고 서비스가 영속화를 소유한다. Hub는 백엔드 내부 파일을 읽거나 쓰지 않는다.
- 일반 `submit` 요청은 선택된 ConversationStore에 QUEUED로 기록한 후 스케줄링한다.
  file/memory 저장 차이와 memory 저장의 종료 후 소실 계약을 유지한다.
  `steer`는 별도 지시 영수증 경로를 유지하며 새 QUEUED 요청으로 바꾸지 않는다.
- 승인·효과 기록·체크포인트·명시적 재개의 정합성을 유지한다. 불확실한 Tool 효과를 자동 재실행하지 않는다.
  재개는 기존 공개 계획/검증 경로를 거치며 원본 Run을 덮어쓰지 않는다.
- Schema와 값의 의미는 해당 Owner 한 곳에서 정의한다. UI용 Schema나 오류 분류기를 별도로 복제하지 않는다.
  모델 설정은 선택 Agent/Provider, 실행 방식은 선택 Engine, 컴포넌트 설정은 해당 컴포넌트가 소유한다.
- 현재 Diagnostic·Checkpoint·Provider 정책을 재사용한다. 새 기능에 별도 무제한 retry loop를 추가하지 않는다.
  화면의 상태나 모델의 제안은 실행·승인 권한이 아니다.
- 관리 데이터의 변경 지원 경로는 정식 UI·Tool·공개 API다. 원본 문서/내부 JSON/DB의 무단 변경을
  감시하거나 자동 병합·재색인·복구하는 기능은 만들지 않는다. 기존 무결성·경로·참조 검사는 유지한다.
- 구 형식 자동 변환, 호환 별칭, 내부 레코드 수동 패치로 기능을 연결하지 않는다.
- 변경 신호는 관찰 수단이며 저장 상태가 원본이다. drop/재연결 뒤 공개 조회로 재동기화한다.
  표시 캐시를 실행 접수·승인·CAS 검사에 사용하지 않는다.
- UI는 Hub, 터미널·장치는 Host/Hub가 소유한다. 정책값·프리셋은 Application이 선택해 해당 공개 설정
  경로에 명시하고, Project가 소유하는 실행 정책은 Project에 저장한다. llm은 실행과 계약 검증·정책 집행을
  소유한다. llm에 PTK·터미널 escape 출력·장치 UI를 넣지 않는다.
- 버퍼 용량·유휴 시간·검증량·오류 개수 등 사용자가 조정할 실행 제한은 의미를 소유한 구현체의
  공개 설정으로 받는다. llm이 숨은 숫자 기본값을 넣지 않는다. 미설정 시 해당 제한을 추가하지 않으며,
  유한한 용량 등이 기능의 안전한 수행에 필수라면 명확한 설정 오류를 반환한다. SDK 옵션은 미설정이면
  전달하지 않는다. 프로토콜·취소 정리 등의 필수 invariant는 이유를 설명하고 사용자 정책값과 분리한다.

## 4. 스티어링 실행 경계 보강

### 기존 기능 재사용

같은 Run에 지시를 추가하는 `steer`와 일반 `submit`을 유지한다. 소비자 실행 ID와 Graph 경로를
구분하며, 종료된 대상 대신 다른 Agent를 고르지 않는다. 현재 Hub는 실행 중 Enter에서 지시/예약을
선택하고 여러 Agent 중 수신 Run을 선택한다. Graph 미래 노드 예약은 백엔드에 이미 있으므로
Hub 미연결을 백엔드 기능 누락으로 취급하지 않는다.

`pending/applied/unapplied/partially_applied` 의미와 대상별 영수증을 유지한다.
`applied`는 검증된 입력 준비의 저장 확인이지 Provider 수신이나 모델 이행의 증명이 아니다.
승인 대기·미지원 Engine·닫힌 Run의 현재 접수 제한은 별도 계약 변경 없이 완화하지 않는다.

### 보강할 계약

**S1. 더 세밀한 소비 경계**

현재 모델 호출이 A·B·C 도구를 요청한 상태에서 A 실행 중 지시가 도착하면, A 종료 후 B 실행 전에
지시를 확인하고 재판단으로 전환할 수 있는 경계를 설계한다. 지시를 발견하기만 하고 기존 묶음을
끝까지 실행하는 것을 반응성 개선 완료로 보고하지 않는다.

- 이미 시작한 A를 추가 지시만으로 강제 취소하거나 다시 실행하지 않는다.
- B·C를 보류/실행하지 않는 경우 기존 tool-call/result 연결을 완전하게 닫는 정식 표현이 필요하다.
  실제 실행 성공으로 꾸미거나 응답 메시지에서 호출을 조용히 삭제하지 않는다.
- 미실행 사유·효과 없음·지시와의 연결은 해당 Tool/Engine 계약 Owner가 검증하고 저장한다.
  영수증을 가진 완료 효과는 재개 후 재사용하고 미실행 상태와 혼동하지 않는다.
  재판단으로 실행하지 않은 옛 B·C 호출이 재개 때 자동으로 살아나지 않도록 처리한다.
- 선택·반영 ACK, 승인 기록, 효과 시작의 순서를 유지한다. 동일 지시의 중복 반영을 막는다.
- 순차/병렬 실행은 구분한다. 병렬 작업 중 이미 시작한 Tool까지 미실행으로 바꾸지 않는다.
- 지시로 필요한 도구가 바뀌면 기존 공개 도구 선택 경로로 다음 모델 호출의 노출 집합을 다시 정한다.
  도구 노출 변경으로 권한·승인·완료 효과 영수증을 변경하지 않는다.
- 제약상 안전하게 전환할 수 없는 Engine은 기존 경계를 유지하고 지원 범위를 명시한다.

**S2. 선택적 Provider 응답 중 지시 지원**

Provider가 공식적으로 지원하는 경우에만 진행 중 응답에 추가 입력을 연결한다. 미지원 Provider는
다음 안전한 Engine 경계에서 반영한다. 모델 이름 문자열만으로 기능을 추정하지 않는다.

지원 방식·접수 성공·처리 중 응답의 수명·추가 usage·연결 단절 시 결과 불확실성을 adapter가 소유한다.
논리적인 기존 Run과 Provider 내부 response ID는 구분한다. 현재 호출을 취소하고 새 요청을 보내는
방식을 모든 Provider의 steering으로 위장하지 않는다. 기존 Run/반복/토큰 예산을 우회하지 않는다.

**S3. 관찰 정보**

Hub가 지시 ID, 대상, 접수/반영 시점, 미반영 사유, 가능한 경우 현재 기다리는 경계를 조회할 수 있어야 한다.
기존 영수증·이벤트의 필드를 우선 사용하고, 대기 이유가 없다면 확장 지점을 소유자와 함께 정의한다.
서버 상태와 영속 상태를 구분하며 UI 전용 문구·아이콘은 백엔드에 넣지 않는다.

### Hub 연결 요구사항

- 입력 초안을 즉시 소비하고 접수 결과와 실제 반영 상태를 따로 보여준다.
- 긴 Tool/모델 처리 때문에 반영 대기 중인지 설명하되, 완료 시간을 추측하지 않는다.
- Graph 실행 대상과 미래 경로 예약을 구분한다. 다중 대상은 각 결과를 표시한다.
- 음성 확정 발화도 같은 경로를 사용한다. 지시를 예약 요청이나 승인 응답으로 자동 해석하지 않는다.

## 5. Workflow 편집용 계약 보강

### 기존 기능 재사용

`schema_version=1`, 공통 그래프 Schema, handler별 `describe_config`, 구조 검증과 CAS 저장을 유지한다.
branch·parallel/join·bounded loop·중첩 Workflow의 실제 실행 의미를 UI가 다시 정의하지 않는다.
화면 좌표·접힘·사용자 라벨은 허용된 `metadata`에 두며 실행 권한으로 해석하지 않는다.

### 보강할 계약

**W1. 실행 없는 초안 검증**

저장 전 JSON 초안과 선택된 Project/Engine의 공개 정의를 입력으로 받아 검증할 수 있게 한다.
Run 생성, Tool 실행, Provider 호출, MCP 연결, 패키지 설치, 승인 상태 변경을 일으키면 안 된다.
공개 메타데이터 조회는 허용하지만 실행 준비의 부작용 있는 경로를 그대로 호출하지 않는다.

검증 범위는 구분해 반환한다.

1. 구조: 노드·간선·분기·합류·제한된 반복·중첩·JSON pointer.
2. 정적 환경: 등록 handler, 참조 Workflow/Agent/Tool의 존재 및 버전, 선언된 설정 Schema.
3. 실행 때만 확인 가능한 항목: 자격 증명·외부 서비스 상태·동적 Tool 결과 등.

실행 때만 확인 가능한 부분은 미검증으로 남긴다. 미검증을 성공으로 표시하거나 UI를 열기 위해
실제 모델 호출을 하지 않는다. 편집 검증 성공은 실행 허가가 아니다. 실행 직전에는 현재 권한·승인·예산·
참조 상태와 실제 인자·제약·승인/재개 binding을 기존 실행 경계에서 확인한다.

순수 검증 결과는 [기존 검증 재사용 계약](../llm/storage-transactions.md)의 범위에서만 재사용한다.
검증한 입력 스냅샷과 결과에 영향을 주는 참조·설정·Schema·검증 구현의 동일성을 입증해야 한다.
변경되었거나 동일성을 확인할 수 없으면 다시 검증한다. UI의 성공 표시·객체 ID·revision·mtime만으로
검사를 생략하거나 영속 `validated` 플래그를 만들지 않는다. 기존 binding의 값/의미 검증과 선택된
Agent의 실행·재개 검증을 완화하지 않으며, 검증 Owner 밖에 새로운 캐시나 authority를 만들지 않는다.

**W2. 구조화된 진단**

오류 code, JSON 경로, 중첩 Workflow 경로, node/edge 식별 정보, Schema/handler 소유자,
사용자가 이해할 수 있는 설명을 기존 진단 계약의 적합한 구조로 전달한다.
오류 문자열을 Hub가 파싱해 위치를 추정하게 하지 않는다. 수집 가능한 독립 오류는 함께 반환하되
검증량·오류 개수·취소 경계를 명시한다. 사용자 조정 제한은 2절의 명시 설정 원칙을 따르며,
제한이나 취소로 미검증 항목이 남았으면 이를 성공으로 표시하지 않는다. 비정상 초안을 저장하면서 검증하지 않는다.

**W3. 편집 카탈로그와 버전**

기존 `workflow_handlers()`와 Schema 선언으로 편집 목록을 만들 수 있으면 그대로 사용한다.
직렬화 가능한 snapshot이나 변경 식별자가 부족할 때만 최소 조회 계약을 보강한다.
Schema가 없는 사용자 handler는 JSON 편집 등 제한된 편집 대상으로 명확히 구분한다.
모든 필드를 범용 문자열로 바꿔 제약을 잃거나 모르는 필드를 저장 시 삭제하지 않는다.

### Hub 연결 요구사항

Hub는 노드/간선 추가·삭제·연결, 노드별 설정 폼, 그래프 실시간 미리보기, 오류 위치 선택을 구현한다.
UI 계산은 합치거나 취소할 수 있고 최신 초안의 검증 결과만 반영한다. 초안은 저장 전까지 로컬 상태다.
실행 중 그래프는 Run이 사용한 정의·경로·반복 위치에 연결하고, 편집한 최신 정의를 옛 Run에 덧씌우지 않는다.
정의 변경 후 옛 체크포인트를 자동 재사용하지 않는다.

## 6. 터미널 관측과 리뷰

### 기존 API로 먼저 구현할 범위

Hub를 통해 실행한 명령의 상태·종료 코드·출력 페이지, 파일/Git 변경과 Run/Step 근거를 모아 리뷰한다.
`system_inspect/process_list/process_inspect`는 현재 권한으로 읽는 스냅샷이며 모든 컴퓨터 활동의
기록이 아니다. `process_write`는 pipe 입력이며 기존 ish PTY를 제어하는 기능으로 간주하지 않는다.

대용량 출력은 기존 Data/process-output 참조를 유지한다. UTF-8 문자 cursor와 byte 범위를 구분하고,
잘림·읽기 불가·삭제·종료·PID 재사용을 서로 구별한다. 재시작 후 저장 출력 조회와 프로세스 재실행도 구분한다.

### 조건부 보강

- Hub가 상태 변화를 구독할 공개 경로가 없다면 해당 소유자의 제한된 관찰 통지와 재조회 계약을 보강한다.
  기존 프로세스 실행·취소 구현을 UI용으로 복제하지 않는다.
- ish에서 사용자가 직접 실행한 명령을 수집하려면 ish/Host adapter가 명령 ID·시각·cwd·출력·종료를
  명시적으로 전달해야 한다. 모델이나 llm이 별도 셸의 과거 활동을 추측하지 않는다.
- 관측 대상·필드·근거 범위를 지정한다. 관측용 handle은 실행 권한을 부여하지 않는다.
  외부에서 읽은 명령을 Hub가 실행한 Tool로 저장하거나 완료/승인 이력을 만들어내지 않는다.

Hub는 리뷰 범위 선택과 근거 표시를 소유한다. 리뷰를 위한 조회·모델 호출도 기존 정책·예산을 따른다.
전체 환경변수나 모든 프로세스 출력을 기본 프롬프트에 덧붙이지 않는다.

## 7. 이미지 표시와 기본 스킬

### 이미지

기존 Hub `OutputParser`/`OutputBlock`/`RendererRegistry`와 이미지 렌더러를 유지한다.
ASCII/실제 이미지/자동 선택과 Kitty·Sixel 등 터미널 프로토콜 선택은 Hub/Host 기능이다.
llm은 터미널 escape를 생성하지 않는다. 모델은 데이터만 제공하며 렌더러 코드를 실행하지 않는다.

Vision의 등록·OCR·가공·모델 입력 API를 그대로 사용한다. `acompletion_content`는 모델 입력 표현이므로
그 존재만으로 효율적인 UI 미디어 조회 계약까지 충족됐다고 판단하지 않는다. 관리 이미지 표시에서
공개 조회가 실제로 부족하면 이미지 ID·revision·MIME·크기와 바이트/스트림 읽기 계약만 보강한다.
Hub에 내부 `assets` 경로를 조립하게 하지 않으며, 삭제·교체·참조 유지와 캐시 폐기 규칙을 명시한다.
이미지 조회를 위해 OCR/VLM을 실행하거나 표시할 때마다 전체 자료를 재등록하지 않는다.

### 기본 스킬

코드 수정·디버깅·테스트, 코드 리뷰, 명령 출력·시스템 진단, 대용량 자료 분석,
Workflow/RAG/Agent/Skill 생성 지침은 Hub 자산으로 작성한다. llm은 기존 Skills와 공개 도구로 처리한다.
스킬 지침은 실행 권한·Tool 결과·검증 성공을 대체하지 않는다.
기존 사용자가 수정한 스킬을 자동 덮어쓰지 않고 필요한 스킬/자료만 읽는다.
인사 요청에 전체 스킬 본문·전체 도구 스키마·추가 리뷰 호출을 강제하지 않는다.

## 8. 실시간 양방향 음성

### 구현 경로

1. 먼저 스트리밍 STT → 기존 텍스트 Agent/Run → 스트리밍 TTS를 구현한다.
   기존 Tool·승인·체크포인트 경로를 가장 많이 재사용하는 경로다.
2. 네이티브 음성 Provider는 필요할 때 별도 단계로 구현한다. 오디오 입출력과 Tool 호출을 지원하는
   adapter의 명시 계약으로 지원 모델/전송 방식을 확인하며 모든 Provider에서 동작한다고 가정하지 않는다.

어느 경로든 사용자가 말하는 동안 오디오를 받을 수 있고, 출력 재생 중에도 발화를 감지할 수 있어야 한다.
단순히 완성된 녹음 파일을 업로드하고 완료된 음성 파일을 받는 기능을 양방향 실시간 지원으로 보고하지 않는다.

### 백엔드 계약

- 오디오 형식·sample rate·channels·chunk 순서·종료, 부분/확정 transcript, 출력 chunk와
  Session/Run/응답의 상관관계를 선언한다. stream은 런타임 연결이며 새 영속 실행 계층이 아니다.
  확정 발화 ID와 접수 결과의 결합 증거는 아래 접수 계약에 따라 기존 저장 소유자가 관리한다.
- 부분 발화는 초안이고 확정 발화만 요청/steering/승인 답변으로 접수한다. 같은 확정 발화를 중복 접수하지 않는다.
  연결 단절로 접수 성공 여부가 불확실하면 아래 접수 계약으로 결과를 확인하고, 확인 없이 재전송하지 않는다.
- 사용자 발화 시 **재생 중단**, **모델 출력 취소**, **Run/Tool 중단**을 분리한다.
  말하기 시작했다는 이유만으로 Tool 효과를 취소하거나 요청을 새로 실행하지 않는다.
- Provider가 요청한 Tool은 기존 ToolExecutor·승인·정책·Step 경로를 통과한다. 음성 연결이 이를 우회하지 않는다.
- 승인/질문 답변은 기존 interaction ID와 선택지에 연결한다. 대기 중인 승인인지 확인하지 않은 발화를
  일괄적으로 승인 처리하지 않는다. 모호한 발화는 Hub에서 확인하거나 텍스트로 입력할 수 있다.
- `policy.final_review`가 명시적으로 활성화된 경우에만 기존 완료 검토의 공개 제한을 적용한다.
  검토 전 후보는 음성으로도 재생하지 않는다. 후보 전체의 검토 완료를 기다리는 데 따른 첫 재생 지연을
  별도로 계측한다. 내부 관찰용 후보를 사용자 음성 출력으로 우회 공개하지 않는다.
- `policy.final_review`가 미설정/Null이면 음성 기능 때문에 Reviewer나 대기를 자동 추가하지 않는다.
  기존 공개 가능한 출력과 Hub의 명시적인 재생 선택을 사용한다. 문장별 검토가 필요하면 전체 후보 검토와
  구분한 별도 계약을 먼저 설계하며, 현재 지원하거나 자동 활성화하는 기능으로 표시하지 않는다.
- bounded buffer, backpressure, 취소·close·재연결·유휴 정리, 종료 후 늦은 chunk 폐기를 정의한다.
  버퍼 용량·유휴 시간은 2절의 설정 소유권을 따르며 adapter 내부에서 임의의 제한값을 정하지 않는다.
  연결 handle·마이크 객체·asyncio Task는 저장하지 않는다. 원본 음성 보관은 별도 명시 선택이다.
- 인증·네트워크·형식·모델 미지원 오류와 usage를 기존 진단/관찰 경로로 전달한다.
  오디오 사용량을 측정하지 못했다면 0으로 꾸미지 않고 미확인으로 구분한다.

### 확정 발화의 접수·중복 방지 계약

현재 공개 `submit(content, *, recipients, request_context=...)`는 호출자가 지정하는 중복 방지 키를
받지 않고 접수 뒤 `RequestHandle`을 반환한다. 접수는 완료됐지만 응답을 받지 못한 경우까지 음성의
중복 접수 방지가 이미 제공된다고 가정하지 않는다. `request_context`에 ID를 넣는 것만으로도 보장되지 않는다.

음성 연결 구현 전에 다음을 기존 요청·지시·Interaction 접수 소유자의 공개 계약으로 확정한다.
새 API 이름이나 별도 영속 실행 계층을 이 문서에서 만들지는 않는다.

- 재전송에도 유지되는 확정 발화 ID와 Session·전달 방식·수신 대상·확정 내용의 결합 범위를 정의한다.
  같은 ID의 중복은 기존 접수 결과를 반환하고, 다른 내용/대상을 같은 ID로 보내면 거부한다.
- 확정 발화와 기존 요청/지시/Interaction 식별자의 결합 및 영수증 조회 방법을 정한다.
  접수와 중복 방지 증거의 저장 사이에 빈틈이 없도록 원자성·동시 접수·취소 경계를 검증한다.
  이 ID는 승인 자체를 대신하지 않으며 각 경로의 권한·Interaction·binding 검증을 유지한다.
- 연결 단절 시 해당 ID로 접수 결과를 조회한다. 미접수와 조회 실패/결과 불확실을 구분하고
  재전송 허용 조건을 명시한다. 이미 접수된 요청을 새 요청으로 만들거나 Tool 효과를 반복하지 않는다.
- 재연결·프로세스 재시작 시 보장 범위를 선택된 저장소에 맞춰 명시한다. file 저장의 결합 증거는
  기존 영속 소유자가 관리하고 memory 저장에는 종료 후 복구를 약속하지 않는다. adapter의 임시 목록만으로
  영속 중복 방지를 보장하지 않는다. 보존·삭제는 기존 소유자의 계약을 따르고 숨은 TTL을 추가하지 않는다.

### Hub와 Host 책임

마이크/스피커 선택, 음량·음소거, 발화 감지, 자막, 재생 큐, 입력 방식과 수신 Agent 선택은 Hub/Host가 소유한다.
WSL 또는 ETX → VM → SSH에서는 백엔드 호스트가 사용자 PC의 장치를 자동으로 볼 수 있다고 가정하지 않는다.
선택한 로컬 브리지의 연결·인증·연결 해제와 전달 지연을 별도로 검증한다. 장치 연결 실패 시 텍스트 UI는 유지한다.
음성 Provider·모델·API 주소·키를 임의 기본값으로 채우지 않는다.

## 9. Hub가 필요로 하는 공통 응답과 성능 조건

| 요구 | 기준 |
| --- | --- |
| 공개 결과 | Python UI 객체나 내부 파일 경로 규칙 대신 현재 공개 타입·JSON projection 사용 |
| 변경 통지 | 관련 Project/Session/Run/Step/자원 식별자, 변경 범위, 가능한 revision과 재조회 방법 |
| 상태·오류 | 진행/완료/미지원/미반영/실패 구분. 기존 Diagnostic code·원인·복구 정책을 보존 |
| 수명 | close/취소/프로젝트 전환 뒤 콜백·출력 유출 방지. 한 소비자 종료로 다른 실행 취소 금지 |
| 캐시 | 동일 revision의 읽기 전용 관찰만 재사용. mutation·event drop·재연결 시 무효화 |
| 비용 | 사용하지 않은 음성·그래프 편집·이미지 기능이 시작/일반 요청 준비에 추가 모델 호출·파일 전수 조회를 만들지 않음 |
| 큰 데이터 | 페이지·참조·보이는 범위만 읽음. 작은 데이터는 불필요한 참조 왕복을 늘리지 않음 |
| 설정 | 정책값·프리셋은 Application이 명시하고 llm은 검증·집행. 미설정/미지원 사유를 노출하며 기능 지원 여부와 실행 권한을 별도로 판정 |

성능 검증은 고정된 임의 초 수치 대신 같은 소스·설정·native Linux filesystem·Python 3.12.14에서
전후 cold/warm p50·p95·전체 표본과 조회/저장 횟수를 비교한다. Provider 대기·Tool 실행·내구성 저장·
Hub 화면 반영 시간을 분리한다. 검증·fsync·승인 경계를 생략해 지연을 줄이지 않는다.
스티어링은 접수→반영, 기존 도구 종료→다음 모델 호출의 시간을 추가로 기록한다.

## 10. 필수 테스트 기준

실제 외부 Provider 없이 결정적 fixture로 먼저 검증한다. 네트워크·장치·터미널별 실사용 검사는
분리하고, 실행하지 못한 환경을 통과로 기록하지 않는다. 새 테스트는 `tests/llm`, `tests/hub`에 둔다.
새 용량·시간·검증량 제한은 미설정 시 숨은 값이 생기지 않고, 필수 설정 부재는 명확히 실패하는지 검사한다.
App이 명시한 설정과 활성화한 완료 검토만 적용되는지도 해당 단계의 집중 테스트로 고정한다.

### 스티어링

- **S-T1** 같은 Run에서 여러 지시를 순서대로 반영하고 일반 예약 요청과 분리한다.
- **S-T2** 느린 Tool A와 미실행 B·C 중 A 이후 지시를 반영한다. 미실행 영수증과 Provider 입력의
  tool-call/result 쌍을 검증하고 A의 효과 횟수는 1이어야 한다.
- **S-T3** 선택/반영 저장 실패, 취소, 정상 종료 직전 접수 경합에서 유실·중복·다른 Run 전달이 없다.
- **S-T4** 병렬·중첩 Graph의 선택 대상/미래 경로 한 번 결합, 미도달·미지원·승인 대기 거절을 검증한다.
- **S-T5** 재개·프로세스 재시작·Session 복제에서 완료 효과와 지시 이력을 보존한다.
  미반영 지시/미사용 예약을 일반 요청으로 자동 재생하지 않는다. file/memory 차이도 검증한다.
- **S-T6** Provider-native 지원/미지원, 응답 종료 경합, 접수 후 연결 단절을 검증한다.
  기존 예산·승인·현재 요청/지시 문맥 보호가 유지되어야 한다.

기존 출발점: `test_loop_steering`, `test_engine_steering`, `test_steering_values`,
Hub `test_running_submission`, `test_request_routing`, `test_observation_reads`.

### Workflow

- **W-T1** 미완성 초안, 잘못된 간선·분기·합류·반복·중첩·pointer를 정확한 위치와 함께 진단한다.
- **W-T2** 기본/custom handler와 Schema 없는 handler, 삭제된 Agent/Tool/Workflow 참조를 구별한다.
- **W-T3** 편집 카탈로그/검증만 호출했을 때 Provider·Tool·MCP·설치·Run 생성 호출 횟수는 0이다.
- **W-T4** 조회 후 API를 통해 정의가 변경되면 CAS 저장을 거부하고 원본·사용자 초안을 보존한다.
- **W-T5** 저장·다시 읽기에서 실행 필드와 UI metadata를 보존한다. 실행 중 정의 편집이 현재 Run이나
  옛 체크포인트의 의미를 바꾸지 않는다. 빠른 연속 편집의 오래된 검증 결과를 UI에 적용하지 않는다.
- **W-T6** 기존 Owner의 범위 안에서 동일 입력·의존성의 순수 검증만 재사용한다. Schema·참조·설정·
  검증 구현 변경 또는 동일성 확인 불가 시 재검증하며, 실행 시 권한·승인·예산·실제 인자 확인은 생략하지 않는다.

기존 출발점: `test_workflow_format`, `test_graph_engine`, `test_graph_checkpoints`,
`test_graph_agent_contract`, `test_nested_graph`, Hub `test_resource_tools`, `test_agent_graph`.

### 관측·출력·이미지·스킬

- **O-T1** 명령 실행·종료·timeout·취소·자식 정리, 두 세션의 cwd/env·출력 격리.
- **O-T2** 30만 줄 출력, 매우 긴 한 줄, 분할 UTF-8, stdout/stderr cursor, 잘림·권한 거부·PID 재사용.
  메모리에 전체 출력이나 전체 프롬프트를 만들지 않고 저장 참조를 조기에 삭제하지 않는다.
- **O-T3** 구독 drop·재연결 뒤 조회로 복구하고 출력/종료를 중복 실행하지 않는다.
  수동 ish 활동은 Host 근거가 있을 때만 표시한다.
- **I-T1** 기존 이미지 등록·OCR·모델 입력 경로 회귀, 이미지 교체·삭제·조회 실패·자원 정리.
- **I-T2** 실제 이미지 미지원 터미널의 ASCII 전환, resize/스크롤/팝업/최소화/복귀 시 잔상·셸 오염 없음.
  이 항목은 Hub/터미널 수동 QA와 headless 계약 검사를 분리한다.
- **K-T1** 선택 스킬·자료만 읽고 사용자 수정은 보존한다. 인사·설명 요청에 무관한 작업 검증을 강제하지 않는다.

기존 출발점: `test_builtin_process_values`, `test_process_group_cleanup`, `test_streaming_files`,
`test_execution_observations`, `test_vision`, `test_agent_skills`, Hub `test_output`,
`test_render_pipeline`, `test_low_resource_observation`, `test_resource_tools`.

### 음성

- **V-T1** 부분 발화는 초안이고 최종 확정은 한 번만 접수한다. 부분/최종 이벤트의 중복·역순을 처리한다.
- **V-T2** 재생 중 발화가 와도 현재 Tool을 자동 재실행하지 않는다. 재생 중단·steering·예약·Run 중단을 각각 검증한다.
- **V-T3** 기존 interaction ID의 승인·질문만 처리한다. 모호한 음성/기한 지난 질문은 임의 승인하지 않는다.
- **V-T4** 완료 검토 활성 시 검토 실패/중단 또는 미완료 후보가 음성으로 재생되지 않는다.
  미설정/Null이면 음성 기능이 Reviewer나 검토 대기를 추가하지 않는다. 취소된 응답의 늦은 chunk는 두 경우 모두 폐기한다.
- **V-T5** reconnect·마이크 없음·지원하지 않는 형식·인증 실패·서버 오류·backpressure·종료 시 누수를 검사한다.
- **V-T6** 두 세션의 음성·자막·수신 Agent가 섞이지 않는다. raw 오디오 보관 선택과 usage 표기도 검증한다.
- **V-T7** WSL과 실제 SSH 장치 브리지에서 왕복 지연·재생 중 발화·장치 해제를 별도 기록한다.
- **V-T8** 접수 성공 직후 응답 유실, 동시 중복 접수, 재연결·프로세스 재시작에서 확정 발화 ID로
  기존 접수 결과를 찾는다. 같은 ID의 내용/대상 변경은 거부하고 요청·지시·승인 응답을 중복 생성하지 않는다.
  미접수와 조회 실패를 구분하고 file/memory 보장 차이 및 Tool 효과가 반복되지 않는지도 검증한다.

### 전체 회귀

모든 제품 변경이 끝나면 Linux Python 3.12.14에서 실행한다.

```sh
.venv-linux312/bin/python tests/llm/run_linux.py --full
.venv-linux312/bin/python tests/hub/run_linux.py
```

직접 unittest 발견이 필요하면 llm은 `-s tests/llm -t .`를 사용한다.
타이밍 검사는 `/mnt/c`, `/mnt/d`가 아닌 Linux 파일시스템의 해시 검증된 소스에서 수행한다.
집중 검사와 전체 결과를 구분하고 실패·skip·미실행 이유를 보존한다.
테스트 후 제품 코드가 달라졌다면 그 변경의 영향을 받는 검사를 다시 실행한다.

## 11. 인계 완료 조건

백엔드 작업자는 다음을 함께 전달한다.

1. 요구사항별 기존 API 재사용/보강 완료/보류 목록과 보류 이유.
2. 정확한 공개 import·함수 서명·결과 타입·Schema·기능 지원 조회 방법. 제안 이름과 실제 구현 이름 구분.
3. 상태 전이, 영속화 ACK, 자원 수명, event drop 후 재조회, 취소·재시작·재개 동작.
4. Hub가 내부 파일·private 메서드 없이 사용할 수 있는 최소 예제.
5. 기능별 fixture 테스트와 전체 회귀 결과, 성능 전후 원자료, 실제 Provider/장치 검사의 수행 범위.
6. 정규 계약 문서·architecture 변경 및 감사 기록. 검토하지 않은 파일을 일괄 완료 처리하지 않는다.

정규 문서는 `docs/llm`과 공개 API 옆 README에 갱신한다. 새 예제는 `examples/llm`,
검증 결과·스크립트는 `tests/llm/reports`에 둔다. 이 전달 문서를 실제 API 명세 대신 사용하지 않는다.

## 12. 구현 연결 상태 — 2026-11-02

사용자 후속 승인으로 1~4단계의 llm/Hub 구현과 집중 테스트를 진행했다.
정확한 API는 [Backend 계약](../llm/interactive-contracts.md), 사용법은

[현재 인계](../llm/handoff.md)에서 확인한다. 로컬 원자료는 배포에 포함하지 않는
`tests/llm/reports/feature-expansion-20261101/results.md`에 보관한다.

- Workflow: 무효과 초안 검증, 참조 snapshot revision, structured 위치, Schema/JSON 편집과 CAS.
- 추가 지시: Tool A 이후 미시작 B/C만 not_executed로 닫고 다음 모델 요청에서 재판단. Graph 예약은 기존 route 사용.
- 관측: public Builtin output 조회와 Run/Step 범위 선택. 새 프로세스 원장·수동 ish 활동 수집은 없음.

- 네이티브 audio-to-audio, Provider 응답 도중 steering, SSH 사용자 PC 장치 bridge는 조건부 후속 범위다.
- 자동 reconnect/재전송은 추가하지 않았다. 키를 가진 호출자는 기존 접수를 조회할 수 있으나,
  Hub 미접수 음성 초안의 재시작 outbox는 제공하지 않는다. 실환경 모델/장치 검증 결과를 추정하지 않는다.
