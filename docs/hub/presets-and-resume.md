# 설정 프리셋과 중단된 응답 재개

## 홈 입력과 재개

입력창 하단 오른쪽의 두 버튼은 **중단/재개**, **실행/추가지시·예약** 순서입니다.
보조 버튼과 같은 배경과 크기를 사용하며 Nerd Font에서는 중단 ``, 재개 ``,
실행·추가지시·예약 `` 아이콘으로 표시합니다. 일반 아이콘 모드에서는 각각 `■`, `▶`, `↑`입니다.
키보드 Ctrl+D와 Enter와 같은 처리 경로를 사용합니다. 실행 중 Ctrl+D는 현재 작업만
중단하며, 유휴 상태에서 마지막 요청이 중단되었다면 그 요청을 재개합니다.
완료·실패한 요청이나 예약 요청을 자동으로 재개하지 않습니다.

재개는 공개 `resume_plan`으로 가능 여부와 revision을 확인하고 `resume`에
`partial_output=True`를 전달합니다. Loop는 체크포인트의 완료된 도구 결과를 재사용하고
미완성 답변을 모델의 참고 자료로 제공합니다. 참고 자료는 완료된 작업이나 도구 실행
승인으로 취급하지 않습니다. 모델이 새로 생성한 답변은 기존 논리적 요청 위치에 이어
표시합니다. 토큰 생성 자체를 정확히 끊긴 바이트부터 되감는 기능은 아닙니다.

체크포인트가 없으면 백엔드가 안전한 처음부터 실행을 허용한 경우에만 `restart`를
사용합니다. 효과가 불확실한 작업을 임의로 다시 실행하지 않습니다.

전송 직후 저장 확인을 기다리는 동안 사용자 요청과 어시스턴트의 준비 상태를 화면에
먼저 표시합니다. 저장 성공 시 실제 메시지로 교체하고 실패 시 초안을 복구합니다.
임시 표시는 대화 저장소나 모델 입력에 추가하지 않습니다.

## 프리셋

프로필 영역은 **홈/설정 버튼 + 프리셋 DropdownBox**로 구성합니다. Ctrl+P로 진입하고
좌우 방향키로 선택합니다. 드롭다운은 Enter/Space로 열고 위아래 방향키로 항목을 고른 뒤
Enter/Space로 확정합니다. ESC는 변경 없이 닫습니다. 최소화는 Ctrl+Q로 유지합니다.

마지막 항목인 **새 프리셋 추가하기**를 선택하고 이름을 입력합니다. **JSON 편집** 버튼은
일반 설정의 에디터를 열며, 저장 버튼은 편집한 JSON을 검증한 후 프리셋으로 보관합니다.
동일한 이름은 덮어쓰지 않습니다. 생성 직후에는 현재 설정을 변경하지 않으며 목록에서
선택할 때 적용합니다.

**현재 설정을 프리셋으로 내보내기**는 현재 저장된 전역 설정과 선택 프로젝트 설정을
그대로 채웁니다. 이름을 지정하고 저장하면 되며 에디터를 열 필요가 없습니다.
미저장 설정 초안이 있으면 먼저 저장하거나 취소해야 합니다.

프리셋은 최초 Hub 루트의 `.hub/presets.json`에 보관합니다. 데이터 루트 변경 후에도
전역 설정과 같은 시작 루트를 사용합니다. 모든 프로젝트에서 같은 목록을 사용합니다.

```json
{
  "version": 1,
  "global": {"profile": {}, "appearance": {}, "general": {}},
  "project": {"config": {}, "components": [], "conversation_storage": "file"}
}
```

편집기는 현재 저장값으로 위 구조를 채워 줍니다. 프로젝트 이름·ID·세션·문서·실행 이력은
프리셋에 포함하지 않습니다. `_hub_title`과 호스트 고정 설정도 임의로 덮어쓸 수 없습니다.
실행/예약 작업이나 미저장 설정 초안이 있으면 적용을 보류합니다. 전체 유효성 검사 후 기존
설정 저장 서비스를 사용하며, 일부 저장이 실패하면 실제로 저장된 값과 오류를 표시합니다.
루트·언어 등의 재시작 요구사항은 기존 재시작 안내를 따릅니다.

선택했던 프리셋의 프로젝트 설정은 프로젝트가 하나도 없는 새 데이터 루트에서 최초
프로젝트를 만들 때도 사용합니다. 명시적인 설치 설정은 이 생성 기본값보다 우선합니다.
기존 프로젝트를 다시 열 때 자동으로 프리셋을 덮어쓰지 않습니다.

## Hub 초기값의 소유권과 저장 계약

Hub는 매번 사용자에게 입력을 요구하지 않고 새 프로젝트의 초기값을 제공할 수 있습니다.
금지 대상은 소유자·출처가 불명확한 숨은 기본값입니다. Hub가 선언하고 실제 Project 설정에
저장한 초기값은 Backend에 전달된 명시값이며, 사용자가 직접 입력한 값과 같은 검증을 받습니다.

1. **선언 소유자:** 해당 Hub 기능 또는 프리셋 구현체가 초기값을 한 곳에서 소유합니다.
   생성 코드는 그 선언을 조합하며 UI·Reader·실행 경로마다 값을 반복하지 않습니다.
   여러 도메인의 값을 전역 상수 파일 하나로 모으지 않습니다.
2. **생성 시 적용:** 새 프로젝트를 만들 때만 누락된 설정에 초기값을 적용하고 저장합니다.
   기존 프로젝트를 열거나 설정을 조회하거나 Run을 시작할 때 재주입하지 않습니다.
   프리셋 선언을 바꿔도 기존 프로젝트의 저장값은 바뀌지 않습니다.
3. **사용자 값 우선:** 명시한 설정이 생성 초기값보다 우선합니다. 0, False, None, 빈 목록도
   해당 필드가 허용하는 의미대로 유지합니다. `value or preset`으로 누락 취급하지 않습니다.
   허용되지 않은 타입/값은 Backend 오류로 거부하며 초기값으로 조용히 대체하지 않습니다.
4. **조회·편집:** 적용된 값은 Project의 정규 설정 조회·편집에 나타나야 합니다. UI에만 표시하고
   실행 시 다시 추측하는 값으로 두지 않습니다. 사용자가 수정한 값은 재접속 후에도 유지합니다.
5. **명시적 재적용:** 사용자가 기존 프로젝트에서 프리셋 적용을 선택하는 것은 설정 편집입니다.
   현재 Schema·CAS·활성 작업·미저장 초안 검사를 거칩니다. 프로젝트 재열기와 구분합니다.
6. **안전성:** 초기값도 Tool 승인·권한·실행 한도·retry eligibility·부모 제한·Host technical deny를
   우회할 수 없습니다. retry 횟수가 있다는 이유만으로 불확실한 효과를 재실행하지 않습니다.
7. **Backend 독립성:** Backend는 정규 설정 값과 계약만 검증·집행합니다. Hub 프리셋 이름·버전·
   선택 규칙을 읽거나 이름에 따라 정책을 분기하지 않습니다. Hub의 생성 출처 안내도 Hub 책임입니다.

예를 들어 Hub 프리셋이 `policies.tool_retry.max_retries=2`를 선언하면, 새 프로젝트에서 해당
키가 누락됐을 때 2를 저장할 수 있습니다. 사용자가 0을 지정하면 0을 저장하고, nullable인
이 필드에 None을 지정하면 null을 유지합니다. False는 이 integer 필드의 유효값이 아니므로
거부해야 합니다. False나 빈 목록을 허용하는 다른 필드에서는 그 값을 그대로 존중합니다.
필드별 허용 형식은 Backend Schema가 소유하며 Hub가 다시 정의하지 않습니다.

현재 main의 생성 조립은 `hub/backend/project/defaults.py:create_project`,
기존 프로젝트 선택은 `hub/backend/project/bootstrap.py:select_or_create`가 담당합니다.
`create_project`는 Tool retry 초기값을 구성해 공개 `projects.acreate(config=...)`에 넘기며,
`select_or_create`는 기존 프로젝트가 있으면 생성 코드를 호출하지 않고 반환합니다.
명시적 프리셋 적용은 `hub/backend/project/presets.py:PresetService`의 별도 경로입니다.

기존 관련 시험은 `test_bootstrap.test_concurrent_start_creates_once_and_reopen_preserves_edits`,
`test_response_reliability.test_creation_policy_is_editable_and_existing_projects_are_not_reseeded`,
`test_presets_widgets.test_export_save_apply_and_startup_template_preserve_identity`입니다.
각 시험의 통과를 모든 필드의 M/N/V 조합 검증으로 확대하지 않습니다. 후속 구현 gate에는
누락/0/False/None/빈 목록의 **유효 필드별** 생성·저장·조회·편집·재열기, 잘못된 타입 거부,
프리셋 변경 후 기존 값 보존과 승인/한도 우회 차단을 포함합니다.

## 재시작

Ctrl+W 또는 상단 재시작 버튼은 신규 요청을 막고 진행 중인 컴포넌트 명령을 취소합니다.
각 세션의 실행을 종료한 뒤 예약 요청을 취소하여 다음 작업이 시작되지 않게 하고,
승인 대기 작업은 중단 표시로 남깁니다. 정리가 끝나면 기존 런타임과 UI를 교체합니다.
저장된 프로젝트·세션·문서·체크포인트를 삭제하는 기능은 아닙니다.

오래 걸리는 정리는 10초 후 대기 이유를 표시하고 완료되면 자동으로 재시작합니다.
Hub와 ish가 같은 프로세스를 사용하므로 응답하지 않는 Python 스레드를 강제 종료하거나
저장소 잠금을 무시해 두 런타임을 동시에 실행하지 않습니다. 그런 도구의 완전한 강제 종료에는
백엔드의 프로세스 격리가 필요합니다.

## UI 공통 위젯

- `widget/tab_page.py`: 키·제목·컨테이너로 구성한 탭과 내용 전환. 탭 목록에서 ←→로
  전환하고 Enter/Space로 내용에 진입하며 ESC로 탭 목록에 복귀합니다.
- `widget/dropdown.py`: 단일 선택, 확정/취소를 분리한 DropdownBox.
- `widget/input_field.py`: 기존 입력 위젯을 감싸는 오른쪽 버튼형 InputField.
- `widget/composer_actions.py`: 키보드와 처리 경로를 공유하는 홈 실행 버튼.

컴포넌트 팝업은 PathInput을 InputField 안에 넣어 경로 자동완성을 유지합니다.
요청 목록의 편집칸도 Hub TextArea를 사용하여 드래그 선택·붙여넣기 교체를 공통 처리합니다.
설정 분류와 필드는 저장 경로를 유지하면서 화면 제목만 짧게 표시하며, 필터 결과가 없는
분류 제목은 숨깁니다.

설정 메인 영역은 **설정 / 정책** 탭으로 나뉩니다. 프로젝트 일반의 `config.policies`와
엔진·컴포넌트의 `policy`는 정책 탭에, 나머지 항목은 설정 탭에 표시합니다. 탭 아래 대제목은
완성 호출·프로바이더·실행 등의 하위 분류를 사용하고 이미 탭에서 구분한 config/policy는
항목 이름에서 생략합니다. 저장 경로와 미저장 초안은 탭 전환으로 바뀌지 않습니다.
좌측 패널의 Enter/Space/→는 선택된 탭 목록으로 이동합니다. 해당 탭에 항목이 없으면
빈 상태 안내를 표시하며 숨겨진 입력칸으로 포커스를 보내지 않습니다.

좌측 패널과 태그 바가 사용하는 SidebarList의 빈 공간을 클릭하면 포커스만 이동하고
선택은 유지합니다. 실제 항목 행을 클릭하면 기존처럼 해당 항목을 선택합니다.

## 중단의 경계

Run 중단이 종료 확인을 기다리는 동안 화면 조회용 잠금은 점유하지 않습니다.
취소 요청 즉시 Run 헤더와 RAG 작업 목록에 중단 중을 표시합니다. 종료 확인이
5초 이상 지연되거나 중단을 다시 요청하면, 실행 중인 호출과 저장 정리가 끝나기를
기다리고 있으며 현재 실행 방식에서 강제 종료할 수 없다는 안내를 표시합니다.
현재 llm API의 interrupt는 취소 요청과 종료 확인이며 프로세스 강제 종료 API는 아닙니다.
Hub·ish가 공유하는 프로세스나 실행 중 Python 스레드를 강제로 종료하지 않습니다.
RAG도 공개 취소 API와 로컬 등록 코루틴 취소를 사용하며 정리 완료 전 삭제를 허용하지
않습니다. 취소를 무시하는 외부 호출의 확실한 강제 종료에는 실행 격리와 백엔드 계약이
필요합니다.
