# 요청 목록

Ctrl+G는 `widget/forms/request_history.py`의 `RequestHistoryDialog`를 엽니다.
목록은 CheckboxList이며 방향키로 살펴보고 Space로 여러 요청을 체크합니다.
목록 아래의 TextArea에는 현재 살펴보는 사용자 메시지가 표시됩니다. 입력 초안은
항목별로 유지하며, 편집 버튼은 체크한 단일 항목의 초안으로 다시 실행합니다.
그 아래에는 응답과 실행 정보가 표시됩니다. Tab으로 입력 칸과 버튼 사이를 이동합니다.

- **삭제**: 여러 요청을 선택할 수 있습니다. 예약 요청은 취소하고, 나머지는 기존
  대화 삭제 API를 사용합니다. 미완료 체크포인트 참조가 있으면 재개 포기 확인이 필요합니다.
  예약 상태가 바뀌면 다시 확인합니다. 일부만 처리되면 처리되지 않은 이유를 안내합니다.
  확인 직후 출력과 태그 목록을 비우고, 하단 공용 진행 바에서 처리 건수를 표시합니다.
  최신 대화 조회가 완료되면 남은 대화를 글자 출력 애니메이션 없이 복원합니다.
  실행 중 응답도 복원 시점까지의 본문은 바로 표시하고, 이후 새로 수신된 글자만 순서대로 표시합니다.
  삭제된 요청은 입력 히스토리에서도
  제외하며, 다른 초안이나 다른 세션의 화면은 유지합니다.
- **편집**: 실행 중이 아닌 단일 요청(승인 대기 포함)을 수정하여 처음부터 실행합니다. 이미 수행한 도구의
  외부 효과는 되돌리지 않습니다. 실행·예약 작업이 남아 있으면 이력 변경을 막습니다.
- **재시도**: 단일 실패/중단 요청의 체크포인트를 재개합니다. 완료한 도구는 저장된 결과를
  재사용합니다. 체크포인트 생성 전 중단·실패하여 체크포인트 초기화 이력과 Step이 모두 없다면,
  원래 요청·엔진·엔진 옵션(셸 환경 포함)으로 처음부터 재시도합니다. 내부 Run은 새로 만들지만
  화면에서는 기존 요청 위치를 유지하고 이전 시도의 응답을 대체합니다.
  이미 초기화한 체크포인트의 유실, 재개 연결, 승인 대기, 실행 기록이 있으면 처음부터 재실행하지 않습니다.
  손상·권한 오류나 체크포인트를 지원하지 않는 엔진도 이 대체 경로로 우회하지 않습니다.
- **닫기**: 팝업만 닫습니다. 세션 복제는 기존 좌측 패널의 복제 기능을 사용합니다.

`backend/history.py`는 공개 Session/Run API만 호출합니다. 백엔드는 새 Run을 만들고
원본 기록을 보존합니다. `execution/turns.py`의 `TurnIndex`는 체크포인트의 `resume` 링크와
Hub가 요청 옵션에 넣는 `_hub_turn.source` 링크로 실행 시도들을 묶습니다.
화면과 요청 목록에서는 최초 요청의 위치와 식별자를 유지합니다. 편집 이후에는 새 사용자
메시지와 새 응답만 표시하고, 재개 시에는 기존 응답과 이어지는 내용을 함께 표시합니다.
예약된 재실행이 취소되면 이전 시도를 다시 표시합니다.

편집 링크는 QUEUED 메시지부터 저장되므로 재시작 후에도 별도 UI 파일 없이 순서를 복원합니다.
`EnvironmentEngine`은 Hub 전용 옵션을 실제 Engine에 넘기기 전에 분리합니다.
`HubContextBuilder`는 논리적 순서의 최신 시도만 문맥에 넣습니다. 예전 요청을 편집할 때
그 이후 대화는 편집 실행의 문맥에 포함하지 않으며, 이후 요청은 수정된 대화를 사용합니다.
복제에서도 최신 논리적 대화를 복사하고 편집/재개 연결을 정리합니다.

도움말·로그는 공통 `ReadOnlyDialog` 하단의 닫기 버튼과 Enter/ESC/Ctrl+L로 닫습니다.
출력 본문은 포커스를 받지 않으며 이동키로 스크롤합니다.

Ctrl+E와 엔진/Workflow 선택 팝업은 제거했습니다. `/engine <엔진명>` 직접 지정과
요청별 `engine_options` 백엔드 계약은 유지합니다. Graph 전용 페이지는 별도 구현 대상입니다.
