# Agent 설정·대화 상대 그룹 연결 검토

## 계약과 책임

- Engine 설정은 실행 방식과 정책을 소유한다. Hub는 모델·주소·인증을 Engine/Session 설정에서 찾지 않는다.
- 새 `assistant`의 모델 값은 사용자가 명시한 값만 `AgentDefinition.completion`에 저장한다. 기본 시스템 지침과 허용 도구는 Agent 정의에 둔다. 기존 Project를 열 때 재주입하거나 이전 형식을 변환하지 않는다.
- `AgentManagement`는 공개 `project.agents.adescribe(engine=...)`를 조회한다. `AgentEditor`는 기존 `SchemaForm`/설정 필드를 재사용한다. 화면에 펼쳐 표시하는 루트 속성과 원본 스키마 검증을 분리하여 `allOf`, 참조, 선택 Engine 제약을 제거하지 않는다. 저장은 공개 revision 기반 API로 처리한다.
- 자동 제목은 원본 대화 Agent의 현재 모델 옵션을 보조 호출에 맞게 골라 별도 제목 Agent로 실행한다. 원본 Session별 내부 Agent를 사용하여 동시 제목 작업이 모델 설정을 서로 덮어쓰지 않는다.
- 도구 인자 수정용 모델 호출은 현재 중첩 Agent 또는 원본 Run의 Agent binding을 사용한다. 모델이 없는 Graph Tool 노드는 다른 Agent의 모델을 빌리지 않는다. 명시적 호스트 수정안 선택기는 계속 지원한다.

## UI와 저장 경계

`ParticipantBar`는 `TagBar`의 공통 너비를 사용한다. Agent 작업 메뉴는 편집·그룹 이동·수신 대상 변경·추방, 그룹 메뉴는 수신 대상 변경·그룹 삭제를 제공한다. Enter/Space로 현재 강조한 메뉴 항목을 실행한다.

`ParticipantGroups`만 `Session.metadata.hub_participant_groups`의 `{그룹 ID: {title, members}}`를 해석한다. 실제 초대는 백엔드 `agent_ids`가 기준이다. 외부에서 제거된 Agent를 메타데이터 때문에 재초대하지 않는다. 한 Agent는 한 그룹에만 속한다. 그룹 삭제는 초대 목록을 보존하고 추방은 Project의 Agent 정의를 삭제하지 않는다.

그룹 변경은 활성·예약·제목 작업이 없을 때 공개 Session API로 저장하며, 세션 런타임의 분리·재연결 절차를 따른다. 수신 대상을 그룹으로 지정하면 현재 구성원의 ID를 명시적으로 전달한다. 빈 그룹은 전체 수신으로 바뀌지 않는다.

명령은 `/tool`, `/skill`, `/mcp`, `/rag`, `/agent`, `/workflow`, `/prompt`, `/memory`이다. 등록된 컴포넌트만 표시하고 Agent는 공개 Agent API로 관리한다. 인자는 받지 않으며 도움말은 공통 관리 창 내부에 둔다. 복수 별칭, `config`/`help` 하위 명령, `/agent ID` 경로는 제거했다. 미등록 `/` 입력을 일반 요청으로 보내는 기존 동작은 유지한다.

## 검증 범위

Linux Python 3.12.14의 소스 해시를 확인한 복사본에서 회귀 테스트를 실행한다. 새 검증은 Agent 설정의 실제 제공자 전달, 공개 스키마의 교차 제약, 편집 초안과 revision, 그룹 저장·재시작·삭제·추방·수신 대상, 실제 PTK 키 입력과 공통 사이드바 너비를 다룬다.

원본 로그와 스냅샷 해시는 `tests/hub/reports/agent-settings/`에 보관하며 Git·배포·자동 발견에서 제외한다. `llm/`의 379개 파일은 작업 시작 시점의 원본/정규화 해시와 일치한다. 시작 전에 있던 백엔드 변경은 그대로 유지했다. 기존 계약 감사 기록에서 영향을 받는 Hub 소비 경로만 재검토했다.

외부 API·사내 SSH 터미널과 실제 인증 정보는 자동 테스트 범위에 포함하지 않는다.

## 최종 검증 결과 (2026-10-26)

- Linux Python 3.12.14에서 Hub 전체 620개와 llm 전체 2,547개를 실행했다. 누락·건너뜀은 없다.
- Hub 첫 전체 실행은 617개 통과, 이전 명령/설정 경로와 누락된 테스트 import로 3개 오류였다. 해당 테스트를 수정한 뒤 관련 11개를 다시 실행하여 모두 통과했다.
- 공통 사이드바 폭을 적용할 때 두 버튼의 고정 너비 때문에 좁은 화면에서 `WindowTooSmall`이 발생하는 문제를 추가로 수정했다. 14·18·24칸 렌더링과 참가자·그룹·마우스 검사 35개가 통과했다.
- llm 첫 전체 실행은 2,544개 통과, 작업 중 사본의 이전 감사 증거/인덱스를 읽은 검사 3개 실패였다. 최종 코드와 갱신한 증거를 대상으로 구조·계약·문서 검사 44개를 다시 실행하여 모두 통과했다. 백엔드 실행 동작의 실패나 백엔드 코드 수정은 없었다.
- 전체 실행과 최종 재검증의 테스트 ID를 대조하여 Hub 620개, llm 2,547개 모두 통과 이력이 있고 미해결 실패가 없음을 확인했다. 전체 실행 결과 자체를 성공으로 덮어쓰지는 않았다.
- 환경·문서·S1–S7·전체 계약 검사가 통과했다. 제품 649개 파일, 계약 후보 15,519개에 미분류·오래된 증거·위반 항목이 없다.
- 최종 검증 사본과 Hub 파일 270개 및 자동 검사 파일 122개의 정규화 해시가 일치한다. llm 379개 파일은 작업 시작 시점의 원본 바이트와 일치한다.

실행은 Linux 파일시스템의 격리 사본에서 `python -m tests.llm.run_regression --suite hub`와 `--suite llm`으로 수행했다. 원본 결과는 `tests/hub/reports/agent-settings/{hub,llm,fixture-recheck,sidebar-recheck,audit-recheck}.json`, 최종 대조 기록은 같은 디렉토리의 `final-validation.json`에 있다. 보고서는 배포와 Git에서 제외한다.
