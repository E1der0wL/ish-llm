# Completion 상태와 스트리밍 진단

Hub의 `ChatMessage.status`는 저장된 메시지의 수명 주기를 유지합니다. 별도 `phase`는
실행 관찰을 표시하는 값이며, 대화 기록에 저장하거나 LLM 입력에 넣지 않습니다.

- 요청 접수 직후: 준비 중.
- Completion 시작, 첫 본문 대기 또는 새 생각 요약 수신: 생각 중.
- 사용자에게 공개되는 본문 델타 수신: 응답 수신 중.
- Completion 종료 후 도구 등 후속 작업: 실행 중.
- Run 종료: 실제 완료·실패·중단 상태.

`ThinkingPhases`가 Completion/출력 이벤트를 관찰하고, `SnapshotReader`가 메시지에
표시 단계를 부착합니다. 관찰 이벤트가 유실되면 저장된 Completion 상태를 사용합니다.
`MessageRenderCache`는 phase 변경 시 헤더만 다시 만들고 Markdown 본문을 재사용합니다.
생각 중이라는 상태는 모델 호출 진행을 뜻하며, 생각 요약 텍스트의 반환을 보장하지 않습니다.
생각 중 아이콘은 Nerd Font에서 ``, 일반 문자 스타일에서 `◌`를 사용합니다. 경과 시간은 소수점 이하를
버려 `소요 1분 2초`처럼 표시하고, 시간만 변할 때 헤더 캐시도 초 단위로 갱신합니다.
저장된 실행 시간의 정밀도와 본문·진행 바의 갱신 주기는 유지합니다.

모델이 공개한 생각 요약은 본문 델타가 시작되어도 지우지 않습니다. 도구 호출 전후와
승인 후 재개된 실행의 요약을 모아 하나의 응답 바로 위에 유지합니다. 최종 완료·실패·중단
상태에서 표시를 제거하되, 완료·실패 뒤 최종 답변이 비어 있으면 이미 공개된 생각을
유지하고 답변이 생성되지 않았음을 안내합니다. 승인 대기 중에도 유지합니다. 관찰 유실이나 세션 재선택 시에는
저장된 모든 Completion의 공개 요약으로 복구합니다. 모델에 추가 사고 내용을 생성하도록
요청하거나 비공개 내부 사고를 추출하지 않습니다.

생각 영역 제목은 `참여 Agent 표시 이름 • 생각 과정`으로 통일합니다. 모델 ID나
상태·경과 시간을 덧붙이지 않습니다. 실제 응답 헤더의 상태와 시간은 기존대로 표시합니다.
중단 작업을 재개하면 같은 응답 위치에 `재개 준비 중`을 즉시 표시합니다. 새 Run 관측 후에는
실제 실행 상태로 바뀌며, 재개 거부 시 원래 상태를 복원합니다. Markdown 준비가 밀려도
활성 응답 헤더를 별도로 표시하므로 이전 `중단됨` 표시로 되돌아가지 않습니다.
컨텍스트 요약 행과 압축 중 재시도 표시는 ` 컨텍스트 압축`으로 표시합니다.
생각 과정 안의 요약 행은 주석 색 1, Agent 응답 헤더는 압축 상태를 포함해 강조 색 1을
사용합니다. 일반 문자 아이콘 스타일에서는 `⇲`를 사용합니다. 요약 행은 독립적으로 캐시됩니다.

생각 영역에는 저장된 Tool Step의 이름·상태도 간단히 표시합니다. 최근 5건과 이전 건수만
표시하며 인자·코드·결과 본문은 포함하지 않습니다. 공개 생각 요약이 없는 모델도 Tool
이력은 볼 수 있습니다. 승인 후 재개 시 Step ID를 기준으로 이전 이력을 합치고, 새로
열거나 세션을 전환하면 공개 Step 조회로 복원합니다. 응답 종료 시 생각 영역과 함께
숨겨지며 원본 Tool 이력은 백엔드의 Run/Step 및 로그 조회에 남습니다.

## Gemini의 생각 요약

생각에 토큰을 사용하는 것과 생각 요약을 반환하는 것은 다른 옵션입니다.
Gemini의 공개 요약은 `includeThoughts` 요청이 필요하며, 반환된 요약만 표시할 수 있습니다.
원시 내부 사고나 thought signature를 텍스트로 변환하지 않습니다.

2026-10-11에 확인한 WSL의 LiteLLM 1.101.0은 Gemini 3 계열에서
`reasoning_effort`를 `thinkingLevel` 및 `includeThoughts`로 변환합니다.
프로젝트의 다음 항목에 `medium` 또는 모델에서 지원하는 강도를 입력할 수 있습니다.

```text
/agent → Agent 편집 → completion.reasoning_effort
```

`/agent` → 사용할 Agent 선택 → 편집 → `completion.reasoning_effort`에서 Enter로 값 편집 →
`medium` 입력(따옴표 없음) → Enter → 저장 버튼으로 저장합니다. 새 호출부터 적용됩니다.
Graph는 모델을 직접 소유하지 않으므로 Workflow가 호출하는 개별 Agent 설정을 확인합니다.
Hub는 기존 프로젝트의 추론 강도나 토큰 예산을 자동으로 변경하지 않습니다.

공개 요약은 실행 중 본문 위에서 유지됩니다. 정상적인 최종 답변이 완료되면 숨기고,
최종 답변이 비어 있는 경우에는 진단에 필요한 공개 요약을 보존합니다.

참고: [Gemini 생각 요약](https://ai.google.dev/gemini-api/docs/generate-content/thinking),
[LiteLLM Gemini 매핑](https://docs.litellm.ai/docs/providers/gemini).

## 청크 단위 출력

WSL의 최근 완료된 일반 Run에는 86개의 본문 델타가 기록되어 있었고, 각각 13–84자,
중앙값 53.5자였습니다. 해당 Run의 공개 reasoning 텍스트는 0자였으며 프로젝트와 일반
세션 설정에는 reasoning_effort가 없었습니다. 설정 파일과 이벤트의 본문·인증 정보는
진단 결과에 포함하지 않았습니다.

llm의 provider 브리지는 받은 청크를 전달하고 엔진은 그 텍스트를 델타로 내보냅니다.
Hub의 활성 화면 관찰 주기는 기본 0.1초이고, 사이에 들어온 델타는 한 화면 갱신에
합쳐질 수 있습니다. 문자별 출력 제한 없이 수신된 내용을 다음 프레임에 표시합니다.
저장·모델 실행은 화면 표시를 기다리지 않습니다.
이전에 저장된 대화를 열거나 세션을 전환하면 전체 내용을 즉시 표시합니다.
Markdown 표나 XML 객체는 구문이 완성되어야 나타날 수 있습니다.
저장된 델타에는 수신 시각이 없으므로, 과거 기록만으로 네트워크 수신 간격과 화면 표시
지연을 정확히 나눌 수는 없습니다.

`tests.hub.test_completion_display`는 실제 provider → 엔진 → 서비스 → Hub 경로에서
각 청크를 gate로 보류하고 다음 청크/종료를 기다리지 않고 중간 결과를 관찰할 수 있는지,
생각 요약과 본문의 반복 전환 및 헤더만 바뀔 때 본문 캐시 재사용을 검증합니다.
외부 모델 호출이나 비용은 발생하지 않습니다.

## 추천 요청의 화자

`<hub-next>` 안의 화자는 사용자, 수신자는 어시스턴트입니다.
예: `이 수정에 대한 회귀 테스트를 추가해줘.`
`테스트를 추가해 드릴까요?`처럼 어시스턴트가 묻는 문장은 이 용도가 아닙니다.
Completion 지침에 양쪽 예시를 명시하고, 사용자 정보·선호·승인을 기다리는 경우에는
태그를 생략하도록 합니다. 사용자의 답변이나 승인을 추정하지 않습니다.
추가 모델 호출 없이 생성되며, 오른쪽 방향키는 입력칸에 채우기만 합니다.
임의 자연어의 화자를 결정적으로 판별하지 않으므로 모델의 지침 준수 여부는 별도입니다.
