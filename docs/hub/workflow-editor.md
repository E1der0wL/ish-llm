# 그래프 중심 Workflow 편집기

`/workflow`에서 생성 또는 편집을 선택한다. 노드 목록, 그래프 캔버스, 선택 노드의
설정 폼을 같은 높이로 표시한다. 좁은 터미널에서는 목록과 설정의 너비를 줄인다.
JSON은 **고급 JSON** 버튼에서 전체 초안을 편집하는 기능으로 남긴다.

## 편집 순서

1. **노드 추가**에서 ID와 종류를 선택한다. 제어 노드는 공개 Workflow 스키마에서,
   action 종류와 설정은 선택한 Graph Engine의 handler 선언에서 얻는다.
2. 그래프 또는 목록에서 노드를 선택하고 오른쪽 폼을 편집한다. Enter로 필드 편집을
   시작·완료한다. **적용**, 다른 노드 선택, 저장 전에 변경값을 로컬 초안에 반영한다.
   값 해석에 실패하면 초안을 지우거나 다른 노드로 이동하지 않는다.
3. **간선 추가/연결 편집**에서 출발·도착 노드와 분기 포트를 지정한다. 분기 조건과
   입출력 매핑은 설정 패널의 전용 폼으로 편집한다. 입력 매핑은 상태에서 값을 읽고,
   출력 매핑은 노드 결과에서 값을 읽어 상태 키에 기록한다. 동적 값의 존재는 실행 시 검증된다.
4. 반복 노드는 **반복 본문 열기**로 내부 그래프를 편집한다. **상위 그래프**로 돌아온다.
   별도로 저장된 Workflow 참조는 ID를 편집하며 그 원본은 자동으로 수정하지 않는다.
5. **실행 없이 검증** 후 오류 위치를 선택해 해당 노드/중첩 그래프로 이동한다.
   연결 오류는 해당 연결 편집을, 시작점 오류는 그래프 설정을 연다.
   오류가 없으면 같은 버튼에서 참조 버전과 미검증 항목을 확인할 수 있다.
6. **저장**만 영속 저장을 요청한다. 실패·버전 충돌 시 초안과 읽어 온 버전을 유지한다.

## 키보드와 마우스

이름·노드 목록·작업 영역·메인 버튼을 구분하며 비활성 영역은 흑백으로 표시한다.
위·아래 도구 버튼은 편집기 전체 너비의 가운데에, 이름·좌표 정보는 하단 왼쪽에 둔다.
Tab/Shift+Tab으로 영역을 이동한다. 노드 설정에서는 필드와 적용/취소 영역 사이를
전환한다. Enter로 필드 편집을 시작·완료하며 편집 중이 아닐 때 ↑/↓로 필드를 이동한다.
ESC는 편집 중이면 편집을 끝내고, 이후에는 그래프 → 노드 목록 → 메인 버튼 → 닫기
순서로 이동한다. 도구 버튼이나 노드 설정에서는 그래프로 돌아온다.

캔버스에 포커스가 있을 때:

| 키 | 동작 |
|---|---|
| 방향키 | 해당 방향의 노드 선택 |
| Tab | 노드 설정으로 이동 |
| a / s | 위 / 아래 도구 버튼 영역으로 이동 |
| Alt+방향키/Home/End/PgUp/PgDn | 스크롤 |
| Ctrl+Z / Ctrl+Y | 로컬 편집 되돌리기 / 다시 실행 |
| ? | 조작법 팝업 |

버튼 영역 안에서는 ←/→로 버튼을 선택하고 Enter/Space로 실행한다. **연결 관리**는
입력·출력 매핑을 한 팝업의 두 탭으로 제공한다. Tab/Shift+Tab 순서는 탭 영역,
연결 목록, 이름 입력, 경로 입력, 생성/적용/삭제 영역, 확인/취소 영역이다.
생성/적용/삭제에서 Tab은 확인/취소로, 확인/취소에서 Shift+Tab은 생성/적용/삭제로
이동한다. 같은 영역의 버튼을 Tab으로 하나씩 순회하지 않는다.
내용 영역의 ESC는 탭으로 복귀하고 탭 또는 최하단 버튼의 ESC는 팝업을 취소한다.
확인은 Workflow 초안에만 반영하고, 최종 **저장**이 공개 backend API를 호출한다.
하위 팝업을 열어도 편집기와 그 초안·포커스는 아래에 보관한다.

버튼으로도 동일한 작업을 수행한다. 마우스로 노드를 선택·드래그하고, 빈 캔버스를
드래그하면 화면을 이동한다. 빈 곳을 클릭하기만 하면 선택을 바꾸지 않는다.
휠은 캔버스를 세로로 이동한다. 공통 마우스 캡처로 캔버스 밖에서 버튼을 놓는 경우도
처리한다. 한 번의 드래그는 한 번의 되돌리기 항목이다.

## 소유권과 계약 감사

| 소유자 | 책임 |
|---|---|
| `WorkflowEditor` | 화면 조립, 선택, 비동기 카탈로그/검증 결과 수명, 기존 CAS 저장 진입점 |
| `WorkflowDraft` | JSON 원본 보존, 국소 변경, 중첩 본문 경로, 로컬 undo/redo |
| `WorkflowCatalog` | backend 공개 스키마를 폼과 노드 종류로 투영 |
| `WorkflowCatalogData` / `WorkflowInspectionRequest` / `WorkflowInspectionResponse` | Hub 공개 JSON 경계의 단일 선언, backend `WorkflowInspection` 읽기·직렬화 |
| `WorkflowInspector` / `WorkflowDialogs` | 공통 SchemaForm, 연결·조건·매핑·JSON 입력 |
| `WorkflowBindings` / `WorkflowNavigation` | 입력·출력 연결 초안, 네 포커스 영역과 편집기 키 이동 |
| `GraphCanvas` / `CanvasWindow` | 셀 배치, 선택·드래그·스크롤, 키 선언과 조작법 |

노드의 `metadata.hub_graph.title`과 `metadata.hub_graph.position: [x, y]`는 Hub 표시 정보다.
다른 metadata·사용자 정의 handler 필드·빈 값과 누락의 구분을 보존한다. 기존의 비객체
metadata를 임의로 덮지 않고 고급 JSON에서 해결하도록 안내한다. 노드 삭제 시 entry,
연결 또는 조건을 자동 수정하지 않는다. 미완성 초안은 backend 검증에서 진단한다.

검증은 기존 `workflow_catalog`와 `inspect_workflow` → `WorkflowData.ainspect` 경로를
사용한다. 검증 도중 초안/엔진이 바뀌거나 편집기가 닫힌 경우 오래된 결과를 적용하지 않는다.
Backend의 구조·handler 스키마·권한·참조 검증을 복제하지 않는다. 검증 성공은 실행 허가가
아니며 모델/도구를 호출하거나 Run·Step·checkpoint를 만들지 않는다. 단일 노드 재실행이나
실행 중 snapshot 변경은 추가하지 않았다. `llm/`은 변경하지 않는다.

그림은 초안 revision·선택·viewport·크기·진단이 같으면 재사용한다. 렌더링 중 JSON 파싱이나
서비스 조회가 없으며 화면 밖 좌표가 커도 보이는 셀 크기만 할당한다. 배치/undo 한도는 UI
자료 관리이고 backend 실행·데이터 제한이 아니다. 상태/진행 표시는 기존 팝업 최하단을 사용한다.

## 검증 경로

`tests.hub.test_popup_button_navigation`은 실제 키 입력, 그룹 재진입,
숨김 항목, 모달 입력 수신기, 연결 관리의 두 버튼 영역을 검사한다.
버튼 줄만 있는 안내 팝업에서는 Tab이 같은 버튼에 머문다. 입력/목록이 있으면
Tab으로 본문과 버튼 영역을 오간다. 버튼 간 선택은 ←/→만 사용한다.
중첩 팝업은 부모 초안·자원·포커스를 보존하고 최소화/복원 후에도 현재 자식을 유지한다.
최신 감사와 전체 회귀 결과는 [Workflow UI 감사](workflow-ui-audit.md)에 기록한다.
아래 최초 검증 기록은 이후 변경의 통과 결과가 아니다.

`tests/hub/test_workflow_editor.py`는 초안 보존, 구조 스키마, CAS 요청, 잘못된 JSON 보존,
중첩 그래프, stale 결과, 위치/폼 충돌, 되돌리기, 실제 키 입력과 작은 화면을 검증한다.
`tests/hub/test_mouse_widgets.py`는 ish 호스트의 SGR 마우스 입력 경로를 검증한다.
기존 definition 통합 검사는 실제 backend CRUD·저장 충돌·검증을 유지한다.

수동 캡처는 `python -m tests.hub.manual.workflow_capture`로 실제 PTK 셀을 PNG로 저장한다.
캡처의 Workflow·Agent ID는 예제이며 실제 모델 실행이나 사용자 프로젝트 변경은 하지 않는다.
기록과 이미지는 `tests/hub/reports/workflow-editor/`에 둔다.

### 2026-11-02 검증 기록

- Linux Python 3.12.14의 해시 기록 스냅샷에서 전체 Hub 회귀 987개를 실행했다.
  예전 Agent 카탈로그 응답을 Workflow에도 사용하던 팝업 테스트 자료 오류 1건과,
  WSL 공용 X11 소켓 때문에 Xvfb가 시작하지 못한 환경 초기화 오류 1건이 나왔다.
- 팝업 자료와 이름 행 배치 검사를 현재 화면에 맞췄다. 이후의 JSON 내성·오류 위치 이동
  보강을 포함한 최종 소스를 새 Linux 스냅샷에 복사하고, 변경 관련 UI·저장·최소화/복원·
  실제 마우스·언어팩·X11 검사를 다시 실행해 **62개 모두 통과**했다.
  X11은 일회성 user/mount/network namespace에서 검사했다. 기존 데스크톱과 소켓은 변경하지 않았다.
- 전체 987개 검사를 최종 소스로 반복 실행한 것은 아니다. 전체 실행 로그와 최종 재검사 로그,
  두 스냅샷의 근거는 reports 경로에 구분해 보관한다. 문서 링크/코드 블록 검사도 통과했다.
- 캡처는 실제 PTK 렌더링이며 예제 데이터를 사용한다. 실제 외부 모델로 Workflow를
  실행한 검증과 구분한다. `llm/` 소스와 실행·승인·저장 계약은 변경하지 않았다.
