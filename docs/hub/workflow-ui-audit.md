# Workflow UI 계약 감사

2026-11-02의 그래프 편집기, 중첩 팝업, 버튼 영역 탐색 변경을 대상으로 검토했다.
`llm/` 제품 코드와 저장·실행 정책은 변경하지 않는다.

## 검토와 보완

- 새 편집기의 Workflow 필드 직접 표기를 공개 `WorkflowDocument`, `WorkflowNode`,
  `WorkflowEdge`, `WorkflowCase`, `WorkflowBindings`, `SchemaKeyword` 선언으로 통합했다.
  JSON Pointer 해석도 기존 Owner를 사용한다.
- Hub 카탈로그·검증 요청은 명시적 타입에서 JSON으로 변환한다. 검증 응답은 backend의
  `WorkflowInspection`, `Diagnostic`, `ResourceRef`로 읽는다. 기존 공개 JSON 모양은 유지한다.
- 편집 중 JSON은 미완성/잘못된 값을 포함할 수 있는 사용자 초안이다. 이 경계는 저장 기록의
  호환 Reader가 아니다. 원본 필드·metadata·누락과 명시값을 보존하며, 저장은 기존
  Component API와 expected revision CAS를 거친다. 실행 권한·handler 검증은 복제하지 않는다.
- 화면 그리기는 로컬 초안·viewport만 사용한다. 렌더링 중 Backend 조회, 모델/Tool 실행,
  Run·Step·checkpoint 생성 또는 Backend 소유 파일 접근을 추가하지 않았다.
- `DialogController`가 부모 팝업의 자원 수명과 포커스를 보유한다. 자식만 닫으면 부모를
  복원하고, 전체 종료/교체 시 보유 자원을 정리한다. 최소화는 종료와 구분한다.
  교체·종료로 폐기된 Workflow 편집기는 닫힘 상태를 확정하여 늦은 카탈로그/검증 응답을 무시한다.
- `ButtonNavigation`이 공통 버튼 영역을 선언하고 `DialogController`가 Tab 목적지를 고른다.
  숨긴 영역을 제외하고 선택 버튼을 기억한다. 입력 자동완성과 전용 편집기 키 처리는 유지한다.
- 팝업별 버튼 위 고정 여백 override는 추가하지 않았다. 외곽 여백은 공통 Dialog,
  편집기 내부 구획 간 여백은 해당 레이아웃이 소유한다.

## 감사 범위

기존 감사 근거 중 실제 바뀐 Hub 소비자·테스트·문서의 해시만 다시 검토하여 갱신한다.
검사 규칙·예외 조건은 완화하지 않는다. 저장소 전체의 미검토 파일을 일괄 승인하지 않으며,
계약 전체 목록의 `complete=false`와 이번 변경의 경계 검토 결과를 구분한다.
함께 진행 중인 `dok/` 변경과 해당 문서는 이번 감사·커밋 대상이 아니다.

## 검증

Linux Python 3.12.14, Linux 파일시스템의 해시 고정 복사본을 사용한다.
X11 검사는 독립 user/mount/network namespace의 소켓을 사용해 실제 데스크톱 상태를
건드리지 않는다. 명령·로그·소스 manifest는
`tests/hub/reports/workflow-audit-20261102/`에 보관한다.

최초 집중 검사 100개에서 이전 이름 필드 위치를 기대한 자료 1건을 확인해 현재 레이아웃에
맞췄다. 기존 컴포넌트 삭제 확인 검사의 Shift+Tab 선택도 새 ←/→ 계약으로 갱신하여
해당 모듈 6개를 재검증했다. 제품 코드를 바꿔 예전 키를 복구하지 않았다.
폐기 후 지연 응답 보호가 필요한 점을 추가 발견했으므로 최초 전체 실행은 490개 완료
시점에 중단했다. 해당 로그는 삭제하지 않았으며 통과한 전체 실행으로 세지 않는다.

최종 제품 소스의 집중 검사 **104개 통과**, 아키텍처 S1~S7의 미해결 후보·근거 오류는
**0개**다. 감사 목록은 730개 파일을 기록하며 오래된 해시·구조 오류는 0개다.
전체 목록의 미검토 116개는 이번 작업으로 일괄 승인하지 않아 `complete=false`를 유지한다.

## 최종 결과

- 최종 제품·테스트 소스는 `/home/user/.cache/ish-workflow-review-4cg9o782`에 고정했다.
  전체 Hub **1,012개**를 발견하고 모두 실행했다. 최초 결과는 1,010개 통과,
  로컬 HTTP 테스트 2개 시간 초과였다.
- 원인은 X11 격리용 network namespace의 loopback이 DOWN 상태인 검사 환경이었다.
  호스트 네트워크를 바꾸지 않고 격리 공간의 loopback만 활성화한 뒤 동일 소스의
  HTTP·Provider 메시지·X11 모듈 **16개 모두 통과**를 확인했다.
- 최종 테스트 ID별 결과는 **1,012 passed, 누락·Skip·미해결 실패 0**이다.
  최초 전체 실행 1,526.45초와 환경 재검 14.41초의 기록을 보존하며,
  단일 전체 실행이 오류 없이 끝난 것으로 표현하지 않는다.
  `final-summary.json`에 각 테스트의 통과 근거를 연결했다.
- 아키텍처 S1~S7 검사 통과. 감사 목록 정합성 8개 검사 통과. 문서 검사에서
  이번 Hub 문서의 오류는 0개다. 별도 `dok` 작업 문서의 로컬 보고서 링크 25개는
  reports를 제외한 테스트 복사본에 없어 전역 문서 검사에는 그대로 남는다.
- 검증 코드 1,215개 파일이 작업 트리와 일치한다. `llm/` 393개 파일은 작업 시작 시
  원본 바이트와 동일하다. `dok/`·해당 테스트/문서·임시 캡처/보고서는 커밋하지 않는다.
