# Hub 마우스 동작

Hub가 표시되는 동안 접속 방식과 관계없이 Prompt-Toolkit의 마우스 보고를 활성화한다.
터미널이 자체 처리하는 붙여넣기는 마우스 보고와 함께 사용할 수 있다. 최소화와
플러그인 제거 시 기존 ish 설정으로 돌아간다. 터미널이 버튼 없는 이동 이벤트
(VT100 1003 / SGR)를 보내면 호버를 사용할 수 있다. 이동 보고를 지원하지 않는
터미널에서는 클릭·휠 등 실제로 수신한 이벤트만 처리한다.

## 공통 위젯과 책임

- `widget/controls.py`의 Button, RadioList, TextArea, ScrollbarMargin,
  ScrollablePane은 PTK 위젯을 상속하고 Hub 스타일과 마우스 동작을 공유한다.
- `widget/mouse.py`의 MouseController는 화면별 수명, 호버 대상, 드래그 캡처,
  팝업 경계와 좌표를 관리한다. 핸들러는 렌더링된 셀마다 생성하지 않고 이벤트가
  도착한 셀에 대해서만 감싼다. Hub 외부의 PTK 클래스나 ish 위젯은 변경하지 않는다.
- ScrollbarGeometry는 표시와 드래그에 같은 손잡이 크기·위치 계산을 제공한다.
- WindowScroll은 창의 스크롤을 기존 논리 커서·선택과 분리한다. 출력 컨트롤에
  `scroll_to(line)`이 있으면 그 API를 사용하여 저장 위치와 자동 스크롤 상태를
  보존한다. 일반 PTK 창은 해당 인스턴스의 스크롤 계산만 감싸며, 키보드가 커서를
  이동시키면 다시 커서를 따라간다.

## 조작과 포커스

포커스 가능한 버튼·입력칸·목록을 클릭하면 해당 영역이 포커스를 받는다.
CheckboxList와 SidebarList의 항목 아래 빈 행은 포커스만 이동한다. PTK가 빈 행을
마지막 항목의 좌표로 변환하기 전에 공통 마우스 처리에서 차단하여 체크·선택 상태를 유지한다.
좌측 패널의 세션 목록·전역 설정·프로젝트 제목은 공통 `SidebarHeading`을 사용한다.
제목은 강조색·볼드로 표시하며 비활성 패널에서는 다른 내용과 함께 회색으로 표시한다.
설정한 배경색이 있는 부분만 비활성 회색 배경으로 바꾸고, 투명 배경은 유지한다.
일반·보조·드롭다운 버튼은 해당 FocusRegion이 이미 활성화된 경우에만 공통 Button의 호버 콜백으로 포커스를 얻으며 실행하지는 않는다. 보조 버튼 사이를 이동해도
최초 진입 전 컨트롤을 기억하고 ESC로 복귀한다. 이전 드롭다운이 닫혀 보이지 않는 경우에는
페이지의 기본 복귀 영역으로 이동하여 숨은 목록에 포커스가 남지 않게 한다. 입력칸·목록의 호버는
강조만 하며 포커스를 이동하지 않는다. 팝업/오른쪽 사이드바의 포커스 경계와
드래그 중 대상은 호버 포커스보다 우선한다. 기존
`UIControl.is_focusable()`이 False인 대화 출력, 읽기 전용 팝업 본문,
승인·질문 선택지는 마우스로도 포커스를 얻지 않는다.

휠은 포인터 아래 영역을 3줄씩 스크롤하며 키보드 포커스를 옮기지 않는다.
설정 영역 위에서는 내부 입력칸 대신 설정 페이지가 스크롤된다. 스크롤바의
화살표는 한 줄, 트랙 클릭은 한 페이지씩 이동한다. 손잡이를 잡으면 막대 바깥에서도
드래그가 이어지고, 버튼을 놓으면 끝난다. 팝업·최소화 등으로 대상이 사라지면
캡처를 해제하고 놓기 이벤트가 다른 버튼을 실행하지 않도록 한다.

팝업이 열린 동안 뒤쪽 페이지는 조작할 수 없다. 크기 변경과 스크롤 영역 안의 위젯은
실제 화면의 가시 영역에 맞춰 판정한다. 새로운 출력 컨트롤은 포커스 정책을 그대로
유지하면서 `scroll_to(line)`과 Hub ScrollbarMargin을 제공하면 같은 조작을 재사용한다.

키보드로는 `Alt + 이동키`를 사용한다. ↑/↓는 한 줄, PageUp/PageDown은 한 화면,
Home/End는 처음과 끝, ←/→는 가로로 넘치는 내용을 이동한다. 줄바꿈한 본문은
화면에 접힌 줄 단위로 이동한다. 목록 선택·체크, 입력 초안과 포커스를 보존한다.
홈 입력 중에는 출력 창을, 질문·승인 입력 중에는 상세 본문을 스크롤한다.
열린 자동완성 목록, 드롭다운, 스크롤 가능한 좌측 패널과 우측 사이드바는 각각 자기 목록을 스크롤한다.
설정 화면에서는 현재 입력칸의 넘치는 내용 또는 설정 본문을, 팝업에서는 현재 위젯이나
읽기 전용 본문을 대상으로 한다. 도움말·로그에서는 일반 이동키도 사용할 수 있다.

`ScrollNavigation`이 현재 표면의 대상을 고르고, 각 표면의 기존 `scroll()`을 호출한다.
일반 PTK 목록·텍스트 창은 `WindowScroll`을 사용한다. `Dialog.scroll_target_for()`는 팝업의
선택적 `scroll_target`을 조회해 버튼 등에 포커스가 있을 때 사용할 본문을 제공한다.
사용자 정의 팝업은 기존 컨테이너·포커스 계약으로 동작하며 본문의 읽기 전용 창도 조회 대상이다.
복합 팝업의 수동 포커스 불가 본문은 현재 팝업의 body 안에서 찾으며 프레임용 빈 창과
숨겨진 탭은 제외한다. 접힌 한 줄 안에서도 화면 행 단위로 이동할 수 있다.
커서가 움직이면 기존 커서 추적을 재개한다. 표의 머리글은 같은 가로 오프셋을 읽는다.

두 페이지의 `PanelEdge`는 좌측 패널 우측 경계를 드래그하여 너비를 조절한다.
드래그 중에는 화면만 갱신하고, 놓을 때 너비만 기존 전용 저장 API로 저장한다.
맨 위 `SidebarHeading`은 고정한다. 아래 제목과 구분선만 공통 `SidebarPanel`의
높이 드래그를 연결한다. 카테고리 포커스가 없어도 드래그할 수 있으며 포커스와 선택을
바꾸지 않는다. 제목 위에 포인터가 있어도 구분선에 `PanelEdge`와 같은 호버 스타일을 쓴다.
기존 포인터 캡처 경로를 사용하여 창 밖으로 이동해도 마우스 놓기를 처리하며,
제목 옆 보조 버튼은 높이 드래그 대상에서 제외한다. 목록 선택과 키 탐색은 변경하지 않는다.
프로필 높이는 유지하고 두 목록의 최소 높이를 제한한다. 홈과 설정의 높이 비율은
`SidebarHeights`가 선언하고 `.hub/sidebar-heights.json`에 마우스를 놓을 때만 저장한다.

드롭다운 목록은 바깥의 왼쪽 클릭으로 선택을 확정하지 않고 닫힌다. 팝업 바깥 클릭도
목록은 닫지만 팝업 뒤 화면의 조작으로 전달하지 않는다. 바깥 클릭의 누르기와 놓기를
함께 소비하여 뒤쪽 버튼 실행이나 같은 드롭다운의 즉시 다시 열기를 방지한다.
`DropdownLayer`는 스크롤 영역과 팝업을 그린 다음 버튼의 실제 화면 좌표에 목록을 표시한다.
아래 공간을 우선 사용하고 부족할 때 위로 열며, 양쪽 모두 부족하면 더 넓은 쪽에
높이를 제한한다. 스크롤 영역의 끝이 화면의 끝으로 오인되어 위로 열리지 않게 한다.
저장 작업은 너비와 같은 Worker 큐를 거치며 전체 설정 저장이나 백엔드 재조회는 하지 않는다.
원래 높이로 돌아온 드래그나 단순 클릭은 저장하지 않는다.
화면 너비와 기존 18~60칸 범위로 제한한다. 패널 항목은 글자 뒤 공백까지 클릭할 수 있다.
설정 메인 영역은 입력칸뿐 아니라 설명·여백·버튼 테두리·하단 상태 행을 클릭해도
메인 포커스를 복구한다. 개별 필드/버튼 클릭은 해당 위젯을 선택하며, 입력칸·목록의 호버는 포커스를 바꾸지 않는다.
설정 필드의 편집은 다른 곳을 클릭하거나 포커스를 잃으면 종료하고 입력값을 보존한다. `FocusRegion`의 클릭 영역을 공유 마우스 디스패처가 모달 범위 안에서만 처리한다.

`output/selection.py`의 `SelectableControl`은 출력·확대 보기·표에 공통 텍스트
범위 선택을 제공한다. 화면 셀 너비를 문자 인덱스로 변환하므로 한글과 넓은 문자도
선택할 수 있다. 포커스를 받지 않으며 렌더링된 가시 행에만 선택 스타일을 덧씌운다.
마우스를 놓으면 선택이 유지되며 Ctrl+C로 시스템/터미널 클립보드에 복사한다.
Hub의 `SystemClipboard`는 WSL·Wayland·X11 전송을 비동기로 수행하고 OSC 52로
대체할 수 있다. X11 명령 도구가 없거나 실패하면 `x11_clipboard.py`가 시스템 libX11을
사용하는 `_x11_selection.py`를 실행한다. 별도 Python 프로세스가 CLIPBOARD 소유권과
TARGETS/TIMESTAMP/MULTIPLE, UTF-8/기존 X11 문자 형식, INCR 전송을 처리한다.
메인 UI는 Xlib를 호출하거나 전역 환경을 바꾸지 않는다. 프로세스 간에는 파이프로만
텍스트를 전달한다. 소유권은 최소화 중에도 유지하며 다른 복사·플러그인 종료·호스트
종료 시 회수한다. X11 연결 실패와 시간 초과는 UI를 멈추지 않는다.
Ctrl+V로 시스템 값을 읽으며 최소화 시 셸의 원래 레지스터를 복원한다.
전송 도구는 ish의 현재 환경을 사용하며 복사와 읽기는 순서대로 처리한다. 터미널의
bracketed paste도 내부 레지스터에 반영하지만 시스템으로 다시 보내지는 않는다.
클립보드 성공·실패 알림 팝업은 표시하지 않는다. 외부 읽기에 실패하면 오래된 내부 값을
대신 붙여넣지 않는다. SSH/VM용 사용자 지정 연결 도구와 환경변수는
[클립보드 안내](../../hub/README.md)에 설명한다.
확대 보기에서는 기존 `c` 키로도 선택 부분을 복사하고, 선택이 없으면 전체 raw를
복사한다. 너비 변경, 세션 전환, 표 정렬/필터 및 raw 모드 전환 시 오래된 선택을 지운다.

태그 바가 열려 있으면 마우스 범위를 태그 바에 한정한다. 바깥 클릭은 소비하며
항목 클릭은 선택과 위치 이동만 수행한다. Tab·Space·Enter로 전용 확대 창을 연다. 사용자 요청 항목은 확대하지 않는다.
표의 열 머리글 클릭은 정렬, 본문 클릭은 셀 선택이며 키보드 포커스는 받지 않는다.

편집 가능한 `controls.TextArea`는 `text_editing.TextEditing`의 GUI 편집 키를 공유한다.
현재 Hub에서 실제 포커스를 받고 쓰기 가능한 BufferControl에만 적용하며, 설정 항목의
탐색 상태/읽기 전용 출력/최소화 후 셸에는 적용하지 않는다. Ctrl+X는 선택 영역 잘라내기,
홈 입력창의 Ctrl+D는 작업 중단/재개, 모든 Hub 화면의 Ctrl+W는 재시작이다.
Ctrl+Y는 다시 실행이며 붙여넣기는 Ctrl+V다.
입력 드래그는 PTK의 프롬프트·줄바꿈·문자 폭 좌표 매핑을 그대로 사용한다. 입력창 바깥으로
드래그해도 캡처를 유지하며 모달/최소화로 대상이 사라지면 기존 공통 캡처 해제 규칙을 따른다.

## 클립보드 검증

Linux Python 3.12.14에서 `tests.hub.test_clipboard`는 WSL/Wayland/X11 경로 선택,
명시한 연결 도구 우선권, 입력 선택, 비동기 전송 순서와 터미널 붙여넣기를 검증한다.
`tests.hub.test_x11_clipboard`는 별도 Xvfb를 시작하고 독립 클라이언트인 xclip과
한글·이모지·빈 값·긴 INCR 텍스트를 양방향으로 주고받는다. Hub 최소화/재열기,
호스트 강제 종료 시 소유 프로세스 정리, 원격 로케일 누락도 포함한다.
사용자의 DISPLAY나 실제 클립보드로 테스트하지 않는다.

```sh
.venv-linux312/bin/python -m unittest -v tests.hub.test_clipboard tests.hub.test_x11_clipboard
```

Xvfb와 xclip이 PATH에 없으면 각각 `HUB_TEST_XVFB`, `HUB_TEST_XCLIP`으로 테스트용
실행 파일을 지정할 수 있다. 둘 다 준비되지 않으면 X11 상호운용 테스트만 건너뛴다.
이는 테스트 의존성이며 Hub의 X11 직접 연결에는 libX11만 필요하다.
