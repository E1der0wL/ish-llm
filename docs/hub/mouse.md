# Hub 마우스 동작

일반 설정의 `mouse_mode`는 `auto`가 기본값이다. 로컬에서는 Hub가 표시되는 동안
Prompt-Toolkit의 마우스 보고를 활성화하고, SSH에서는 터미널 고유 선택·붙여넣기를
보존하도록 보고를 끈다. `hub`는 항상 Hub 클릭·휠·드래그를, `terminal`은 항상
터미널의 마우스 처리를 선택한다. 저장 즉시 적용하며 셸의 마우스 설정과 독립적이다. 최소화와
플러그인 제거 시 기존 ish 설정으로 돌아간다. 터미널이 버튼 없는 이동 이벤트
(VT100 1003 / SGR)를 보내면 호버를 사용할 수 있다. 이동 보고를 지원하지 않는
터미널에서는 클릭·휠 등 실제로 수신한 이벤트만 처리한다.

## 공통 위젯과 책임

- `widget/controls.py`의 Button, RadioList, TextArea, ScrollbarMargin,
  ScrollablePane은 PTK 위젯을 상속하고 Hub 스타일과 마우스 동작을 공유한다.
- `widget/mouse.py`의 MouseController는 화면별 수명, 호버 대상, 드래그 캡처,
  팝업 경계와 좌표를 관리한다. 핸들러는 렌더링된 셀마다 생성하지 않고 이벤트가
  도착한 셀에 대해서만 감싼다. Hub 외부의 PTK 클래스나 ish 위젯은 변경하지 않는다.
- ScrollbarGeometry는 표시와 드래그에 같은 손잡이 크기·위치 계산을 제공한다.
- WindowScroll은 창의 스크롤을 기존 논리 커서·선택과 분리한다. 출력 컨트롤에
  `scroll_to(line)`이 있으면 그 API를 사용하여 저장 위치와 자동 스크롤 상태를
  보존한다. 일반 PTK 창은 해당 인스턴스의 스크롤 계산만 감싸며, 키보드가 커서를
  이동시키면 다시 커서를 따라간다.

## 조작과 포커스

포커스 가능한 버튼·입력칸·목록을 클릭하면 해당 영역이 포커스를 받는다.
좌측 패널의 세션 목록·전역 설정·프로젝트 제목은 공통 `SidebarHeading`을 사용한다.
제목은 강조색·볼드로 표시하며 비활성 패널에서는 다른 내용과 함께 회색으로 표시한다.
설정한 배경색이 있는 부분만 비활성 회색 배경으로 바꾸고, 투명 배경은 유지한다.
호버는 강조만 하며 포커스 이동·버튼 실행·목록 선택을 하지 않는다. 기존
`UIControl.is_focusable()`이 False인 대화 출력, 읽기 전용 팝업 본문,
승인·질문 선택지는 마우스로도 포커스를 얻지 않는다.

휠은 포인터 아래 영역을 3줄씩 스크롤하며 키보드 포커스를 옮기지 않는다.
설정 영역 위에서는 내부 입력칸 대신 설정 페이지가 스크롤된다. 스크롤바의
화살표는 한 줄, 트랙 클릭은 한 페이지씩 이동한다. 손잡이를 잡으면 막대 바깥에서도
드래그가 이어지고, 버튼을 놓으면 끝난다. 팝업·최소화 등으로 대상이 사라지면
캡처를 해제하고 놓기 이벤트가 다른 버튼을 실행하지 않도록 한다.

팝업이 열린 동안 뒤쪽 페이지는 조작할 수 없다. 크기 변경과 스크롤 영역 안의 위젯은
실제 화면의 가시 영역에 맞춰 판정한다. 새로운 출력 컨트롤은 포커스 정책을 그대로
유지하면서 `scroll_to(line)`과 Hub ScrollbarMargin을 제공하면 같은 조작을 재사용한다.

설정 메인 영역의 Alt + 이동키는 포커스·편집 값·커서를 유지한 채 설정 페이지만
스크롤한다. 위/아래는 한 줄, PageUp/PageDown은 한 화면, Home/End는 처음/끝이다.
좌우 키도 소비하지만 설정은 너비에 맞춰 줄바꿈하므로 가로 이동은 없다.

두 페이지의 `PanelEdge`는 좌측 패널 우측 경계를 드래그하여 너비를 조절한다.
드래그 중에는 화면만 갱신하고, 놓을 때 너비만 기존 전용 저장 API로 저장한다.
화면 너비와 기존 18~60칸 범위로 제한한다. 패널 항목은 글자 뒤 공백까지 클릭할 수 있다.
설정 메인 영역은 입력칸뿐 아니라 설명·여백·버튼 테두리·하단 상태 행을 클릭해도
메인 포커스를 복구한다. 개별 필드/버튼 클릭은 해당 위젯을 선택하고 호버는 포커스를
바꾸지 않는다. `FocusRegion`의 클릭 영역을 공유 마우스 디스패처가 모달 범위 안에서만 처리한다.

`output/selection.py`의 `SelectableControl`은 출력·확대 보기·표에 공통 텍스트
범위 선택을 제공한다. 화면 셀 너비를 문자 인덱스로 변환하므로 한글과 넓은 문자도
선택할 수 있다. 포커스를 받지 않으며 렌더링된 가시 행에만 선택 스타일을 덧씌운다.
마우스를 놓으면 선택이 유지되며 Ctrl+C로 시스템/터미널 클립보드에 복사한다.
Hub의 `SystemClipboard`는 WSL·Wayland·X11 전송을 비동기로 수행하고 OSC 52로
대체할 수 있다. Ctrl+V로 시스템 값을 읽으며 최소화 시 셸의 원래 레지스터를 복원한다.
전송 도구는 ish의 현재 환경을 사용하며 복사와 읽기는 순서대로 처리한다. 터미널의
bracketed paste도 내부 레지스터에 반영하지만 시스템으로 다시 보내지는 않는다.
시스템 전송 실패는 경고 알림으로 구분한다. 외부 읽기에 실패하면 오래된 내부 값을
대신 붙여넣지 않는다. SSH/VM용 사용자 지정 연결 도구와 환경변수는
[클립보드 안내](../../hub/README.md)에 설명한다.
확대 보기에서는 기존 `c` 키로도 선택 부분을 복사하고, 선택이 없으면 전체 raw를
복사한다. 너비 변경, 세션 전환, 표 정렬/필터 및 raw 모드 전환 시 오래된 선택을 지운다.

태그 바가 열려 있으면 마우스 범위를 태그 바에 한정한다. 바깥 클릭은 소비하며
항목 클릭은 선택과 위치 이동만 수행한다. Tab·Space·Enter로 전용 확대 창을 연다. 사용자 요청 항목은 확대하지 않는다.
표의 열 머리글 클릭은 정렬, 본문 클릭은 셀 선택이며 키보드 포커스는 받지 않는다.

편집 가능한 `controls.TextArea`는 `text_editing.TextEditing`의 GUI 편집 키를 공유한다.
현재 Hub에서 실제 포커스를 받고 쓰기 가능한 BufferControl에만 적용하며, 설정 항목의
탐색 상태/읽기 전용 출력/최소화 후 셸에는 적용하지 않는다. Ctrl+X는 선택 영역 잘라내기,
Ctrl+W는 홈의 작업 중단이다. Ctrl+Y는 다시 실행이며 붙여넣기는 Ctrl+V다.
입력 드래그는 PTK의 프롬프트·줄바꿈·문자 폭 좌표 매핑을 그대로 사용한다. 입력창 바깥으로
드래그해도 캡처를 유지하며 모달/최소화로 대상이 사라지면 기존 공통 캡처 해제 규칙을 따른다.
