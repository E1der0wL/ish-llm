# 핵심 설정 화면과 전체 JSON 편집

Hub 설정 화면과 Agent 생성·편집 창은 자주 바꾸는 항목만 표시한다.
보조 버튼의 JSON 편집기는 전체 설정을 계속 편집하며, 기존 에디터·검증·저장
revision/CAS 경로를 사용한다. 화면에 보이지 않는 값도 저장·취소·프리셋에서 유지된다.

## 표시 기준

| 범위 | 화면에서 편집 | JSON에서 편집하는 대표 항목 |
|---|---|---|
| 전역 | 프로필, 언어팩, 에디터, 저장 위치, 알림, 복원, 자동 스크롤, Tool 누적 문맥 한도, 오류 복구 사용 여부 | 진단 길이, 복구 호출·입력·출력 세부 예산 |
| 모양 | 색상, 아이콘, 패널 너비 | 출력·진행률 최대 갱신율 |
| 프로젝트 | 이름, Tool 호출 한도, 실행 시간, 재시도 횟수, 문맥 문자 한도 | 프로젝트별 승인·허용 도구·사용량 정책, 저장 방식, 세부 재시도 |
| Loop | 반복 횟수, Provider 시도 횟수, 컨텍스트 토큰 상한·응답 여유 | 요청·Tool별 제한, 버퍼, 완료 검증, 세부 재시도 |
| Graph | 단계 한도; Agent에서는 Workflow 선택 | 동시 실행·시간 제한, 이벤트 버퍼, 종료 대기, 중첩 깊이 |
| Agent | 표시 이름·ID, 역할·설명·지침, Engine, 모델/API 연결, 추론 강도·출력 한도, 자원 | 개별 도구 목록·실행 한도, seed/top_p/temperature, SDK 확장 인자, 입출력 스키마, 출력 형식 |
| Memory | 요약 모델/API 연결 | 처리 사용 정책, 캐시, 임계치, 요약 입력 크기·후보 수·반복 예산 |
| RAG | 모델/API 연결, 검색 방식·리랭크 | 관계 확장, 결과 수, 실패 정책, 재시도, 청크 크기, 캐시, 배치 |
| 기타 | Tools 활성화, Vision 모델/OCR 선택, 파일 접근 범위 | Goals/Refinement 정책, 구현별 세부 처리 옵션 |

알 수 없는 확장 Engine/Component는 제공된 필드를 유지한다. 스키마에서 필수로
선언한 필드 역시 표시한다. JSON 편집 후에도 같은 기준으로 화면을 다시 만든다.
필터는 표시 항목만 검색하며, 결과가 없더라도 고급 항목의 JSON 편집 경로를 안내한다.
설정값 변경·기본값 주입과 항목 숨김은 별개다. 기존 프로젝트의 RAG 제안값은
표시하는 항목에만 제공하며, 숨긴 고급 항목에 새 값을 몰래 저장하지 않는다.

## 소유권과 값 보존

- `widget/forms/visibility.py`의 `EssentialSettings`는 **표시 정책만** 소유한다.
  실행 정책·기본값·백엔드 스키마를 바꾸지 않는다.
- `SchemaForm`은 전체 스키마와 원본 초안을 보관한다. `visible_fields`는 렌더링과
  키 탐색에만 쓰며, 값 조립에는 원래 필드와 알 수 없는 JSON 키도 남긴다.
- 단순 `object | null` 스키마는 핵심 하위 필드를 표시할 수 있다. 원본 missing/null은
  실제 수정 전까지 유지하며, union/ref/조건부 스키마는 임의 분기를 평탄화하지 않는다.
- 숨긴 항목도 전체 공개 스키마로 검증한다. Host 고정값, 자원 참조, Engine별 제약,
  저장 revision/CAS는 기존 소유자가 계속 집행한다. JSON 저장 오류도 경로를 보존한다.
- 새로운 이름이나 모델/API 값을 기본값으로 채우지 않는다. 기존 실행·승인·재개·저장
  계약과 `llm/` 구현은 변경하지 않는다.

## 입력 조작

설정 입력의 첫 클릭은 선택이고, 이미 포커스된 입력을 클릭하면 편집을 시작한다.
편집 중에는 일반 커서 이동·드래그를 유지한다. 읽기 전용 또는 저장 중인 필드는
클릭으로 편집되지 않는다. Enter 편집/완료, d 비우기, e 외부 에디터는 유지한다.
두 화면이 `SettingField`와 Hub 마우스 디스패처의 같은 연결을 사용한다.

## 탭과 목록

페이지나 카테고리를 열면 첫 번째 사용 가능한 탭을 선택한다. 화면 갱신이나 입력 중에는
탭을 초기화하지 않는다. 필드가 없는 설정·정책 탭은 만들지 않으며, 설정할 항목이 없는
컴포넌트와 `_hub_` 내부 엔진은 좌측 목록에서 숨긴다. 빈 컴포넌트 관리 창에서 설정으로
이동하면 프로젝트 일반 화면에서 표시할 항목이 없음을 안내한다. 전체 JSON 경로는 유지한다.
Agent의 역할·설명·지침은 일반 페이지에 모으고 필드 제목에서 공통 경로 접두사는 제외한다.

편집 중 다른 곳을 클릭하거나 포커스를 이동하면 입력값을 보존하고 편집만 종료한다.
일반·보조·드롭다운 버튼의 호버 포커스는 해당 영역이 이미 활성화된 경우에만 허용한다.
프로필의 통계 텍스트는 내용 높이에 맞추며, 그래프는 강조 색 5 배경을 사용한다.

## 앞선 핵심 설정 변경 검증 기록

WSL Python 3.12.14의 Linux 파일시스템 복사본에서 검증했다.

- 설정·JSON·Agent·실제 PTK 마우스 집중 검사: 91개 통과.
- 전체 Hub 실행: 944개 실행, 939개 통과. 5개는 기존의 전체 필드 노출·초기 탭·필터
  기대값을 사용하던 테스트였다. 숨긴 설정을 다시 노출시키지 않고 테스트를 새 UI 기준으로
  보완했다. 일부 하위 사례는 첫 기대값 실패 후 팝업이 남아 연쇄 실패했다.
- 변경한 5개 모듈 전체 재검증: 35개 통과. 전체 실행과 재검증의 제품 소스는 동일하며,
  차이는 해당 테스트와 그 감사 해시에만 있다. 나머지 909개는 전체 실행에서 통과했다.
  두 실제 보고서를 대조해 944개 모두 검증 근거가 있고 미해결 실패·누락·skip이 없음을 확인했다.
- 아키텍처 S1–S7, 계약 인덱스/검토 자료, 문서 검사 통과. 기존 감사의 미검토 잔여 항목을
  전체 완료로 바꾸지 않았으며, 이번 변경의 근거만 갱신했다.
- 작업 시작 대비 `llm/` 및 호스트 431개 파일의 원본 바이트 동일성 확인.

실행 기록은 `tests/hub/reports/essential-settings-20261101/`에 보관한다.
`full/hub.json`은 최초 실패를 그대로 남기고, `corrected/hub.json`은 재검증 결과,
`verification-summary.json`은 동일 제품 소스의 검사 범위를 대조한 기록이다.
최초 전체 실행 자체가 통과한 것으로 기록하지 않으며 이전 작업의 결과도 승계하지 않는다.


## 탭·포커스 보강 검증

이번 검증 기록은 `tests/hub/reports/settings-polish-20261101/`에 별도로 보관한다.
빈 탭 제거·활성 영역 호버·편집 종료·메타데이터 숨김·Agent/RAG 생성 시각을 검증하며,
전체 JSON 초안·revision·프리셋·재개 동작과 변경 없는 `llm/` 원본도 확인한다.

- WSL Linux 파일시스템의 Python 3.12.14에서 마지막 집중 검사 43개 통과.
- 전체 Hub 950개 실행: 947개 통과, 기존 UI 기대값을 사용하던 3개 실패.
  빈 Skills 페이지 노출, 최소화 후 편집 모드 유지, `completion.model` 접두사 표시는
  이번 요구사항과 달라 테스트를 보완했다. 최소화 시 초안·커서는 보존되고 편집 모드만
  종료되며, 복귀 후 다시 편집할 수 있는지도 확인했다.
- 해당 3개 모듈 전체 15개 재검증 통과. 전체 실행 이후 제품 코드는 동일하며 변경은
  세 테스트 파일뿐이다. 한 테스트 이름을 새 동작에 맞춰 변경한 내역까지 대조하여
  950개 모두 통과 근거가 있고 미해결 실패·누락·skip이 없음을 확인했다.
- S1–S7 아키텍처, 계약 인덱스, 감사 근거 검사 16개와 문서 검증 통과.
  기존 미검토 감사 항목은 그대로 남겼고 전체 감사를 완료한 것으로 기록하지 않는다.
- 작업 시작 대비 `llm/`과 호스트 431개 파일의 원본 바이트 동일성을 확인했다.

`full/hub.json`은 최초 실패를 그대로 보존하고 `corrected/hub.json`은 재검증 결과다.
두 결과와 제품 소스 동일성은 `verification-summary.json`에 대조해 기록했다.
RAG 목록 날짜는 본문을 읽지 않고 기존 Job 조회에서 얻은 등록 작업 생성 시각을 사용한다.
