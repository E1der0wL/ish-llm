# Hub 계약 감사 기록 갱신과 회귀 검증

2026-11-01, `f556828b` 이후 작업 트리 기준이다. 이전 성능 실험의 통과 기록을
이번 변경의 검증으로 승계하지 않는다. 기존 계약과 규칙은 유지하고 현재 코드에
대한 감사 근거를 갱신한다. `llm/` 실행 코드는 수정하지 않는다.

## 검토 범위와 소유권

오래된 파일 검토 16개는 과거 검토 해시와 일치하는 Git 버전 또는 Linux 검증
복사본을 찾아 현재 소스와 비교했다. 변하지 않은 후보 661개의 개별 판단은
의미와 사용 위치를 대조해 유지하고, 제거된 후보 13개는 기록에서도 제거했다.
새 후보 58개는 각각 소유자와 근거를 기록했다. 신규 `ParticipantManager`는
전체 선택·비동기 콜백·중첩 팝업·닫기 경로를 읽고 제품 목록과 감사 기록에 추가했다.

| 경로 | 유지하는 계약 |
|---|---|
| 대화 상대 관리·그룹 | 화면 목록은 관측값이며 화면 그리기 중 서비스 조회를 하지 않는다. 여러 Agent의 초대·이동·추방은 전체 선택을 검증한 뒤 기존 공개 서비스로 저장한다. 그룹 메타데이터는 Agent를 초대할 권한이 없다. |
| Agent 직접 편집 | 공개 READ로 받은 버전 있는 레코드를 기존 편집기로 연다. Schema/CAS 저장을 유지하고, 원래 팝업의 선택·포커스를 복원한다. 늦은 읽기 결과가 다른 팝업을 덮지 않는다. |
| 팝업·출력 확대 | 한 줄 진행/상태 공간과 키 바인딩은 공통 위젯이 소유한다. Ctrl+C는 선택 복사 또는 무동작이며 닫기로 해석하지 않는다. 제거한 단축키의 기능은 명시 버튼을 통해 제공한다. |
| 제목·통계·목록 | 제목의 강조색·볼드는 공통 테마를 소비한다. 사용량 그래프는 표시 영역만 소유하고 집계 범위·미확인 토큰 판단을 바꾸지 않는다. 빈 목록 영역 클릭은 포커스만 바꾼다. |
| 도구 구성 | 공개 `ToolRegistry.derive()`로 동일 스키마의 문법 검증 근거만 재사용한다. 변경 스키마·실행 인자·handler·승인·저장 확정 검증은 백엔드에 남는다. |

새 대화 상대 위젯의 빈 표시, 그룹 목록 표시 형식, 단일 Agent 편집 개수는
해당 위젯의 선언부로 옮겼다. 표시 내용·키·마우스 동작·저장 형식은 유지한다.
그 밖의 제품 코드는 이번 감사에서 바꾸지 않는다.

## 감사 근거의 범위

`docs/llm/contract-coverage-reviews.json`은 개별 판단,
`docs/llm/contract-coverage-index.json`은 현재 제품 파일 목록과 해시를 소유한다.
`tests/llm/fixtures/architecture_reviews.json`의 변경된 근거도 실제 코드와 테스트를
확인한 뒤 갱신한다. 검사기의 규칙이나 예외 조건을 완화하지 않는다.

현재 기록의 오래된 해시와 누락은 정리하지만, 기존에 미검토였던 다른 67개 파일은
미검토로 남긴다. 따라서 목록 일치·기능 회귀·아키텍처 검사 통과를 저장소 전체의
전수 소유권 감사 완료로 해석해서는 안 된다. `complete` 표시는 그 구분을 유지한다.

## 실행 및 증거

Linux Python 3.12.14와 WSL의 Linux 파일시스템에 고정한 소스 복사본을 사용한다.
원본과 복사본의 해시는 `tests/source_tree.py` 기준으로 기록한다. 전체 Hub 회귀는
`python -m tests.llm.run_regression --suite hub`로 실행하며, llm 전체 회귀는 반복하지 않는다.
아키텍처 S1~S7 검사에는 개별 검토 근거를 명시하고, 계약 기록 검사와 문서 검사도 수행한다.

과거 보고서와 스냅샷은 수정하지 않는다. 이번 변경 비교, 개별 판단, 고정 소스 manifest,
검사 명령·결과는 `tests/hub/reports/contract-refresh-20261101/`에 보관한다.
테스트는 격리된 데이터와 로컬 테스트용 모델을 사용하며 실제 사용자 workspace나
사내 모델·인증 정보는 변경하지 않는다.

## 최종 결과

- 아키텍처 S1~S7: 개별 검토 근거 65개가 현재 소스와 일치하며, 미해결 후보와
  검토 오류 0개. 그룹 일괄 변경의 `not identifiers or any(...)`는 기본값 선택이
  아니라 잘못된 선택을 거부하는 조건임을 실제 저장 전 검증 경로와 통합 테스트로 확인했다.
- 계약 기록 테스트 16/16 통과. 제품 파일 704개, 오래된 해시·감사 구조 오류 0개.
  앞서 명시한 미검토 67개는 그대로 남으며 `complete=false`를 유지한다.
- 문서 검사 통과. 기존 계약 문서와 검사 규칙은 완화하지 않았다.
- 전체 Hub 발견 대상 **957개를 최종 확인**했다. 최초 전체 실행은 948개 통과,
