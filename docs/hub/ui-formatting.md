# 공통 표시 형식

2026-11-04 사용자가 실제 PTK 렌더러의 샘플 화면을 확인하고 구성을 확정했다.
검사는 Linux Python 3.12.14의 격리된 소스 복사본에서 수행한다.

## 소유권

| 소유자 | 표시 책임 |
| --- | --- |
| `widget/captions.py::Caption` | 대상·상태·부가 정보를 ` • `로 연결하고 빈 항목을 생략 |
| `locales/Language.status`, `asset/icon.py::IconSet.for_status` | 상태 번역과 상태당 한 아이콘. NerdFont/Unicode 선택 유지 |
| `widget/transcript/header.py::OutputHeader` | 사용자·Agent·생각 과정·시스템·Tool의 헤더 구성 |
| `widget/list_presentation.py::ListPresentation` | 목록의 이름·수정 시각·설명 구성. 날짜가 없으면 추측하지 않고 `—` 표시 |
| `widget/sidebar.py::SidebarList` | 실제 할당 너비에 맞춘 말줄임과 기존 선택·빈 공간 클릭 규칙 |
| `widget/notices.py::NoticeText`, `Notice` | 제목·설명·다음 행동의 비대화형 표시, 짧은 상태 안내와 빈 목록의 공통 표현 |
| `widget/forms/field_layout.py::FieldLayout` | 제목·설명·타입·입력 위젯·관측 안내·한 줄 간격 |

## 헤더와 상태

기본은 `대상 • 아이콘 상태 • 부가 정보`다. Agent 헤더는 소요 시간을,
사용자 헤더는 요청 시각을 유지한다. Tool은 기존 도구 아이콘과 이름을 대상으로
표시하고 인자는 같은 행의 부가 정보로 둔다. 너비를 넘은 인자는 말줄임하고
결과 미리보기까지 최대 4행으로 제한하는 기존 규격은 유지한다.

Hub가 조립하는 `•` 구분자는 양옆 한 칸을 사용한다. Workflow 위치 안내와
조작법도 `Caption`의 공통 구분자를 사용한다. 사용자가 입력한 본문·모델 응답의
공백을 일괄 치환하지 않는다.

생각 과정은 상태를 중복하지 않고 `Agent 별명 • 생각 과정`, 시스템은
`시스템 • 날짜 시각`을 유지한다. 질문·설명·답변은 각각 별도 행이며 카드나
새 헤더를 추가하지 않는다. 추가 지시의 준비 중·반영 대기·반영됨은 실제
관측 상태만 표시한다. 재시도·초안·요약·RAG 진행 단계에도 같은 아이콘 선택을 사용한다.

번역 템플릿의 `{icon_*}` 자리만 제거한 뒤 공통 아이콘을 붙인다. 표시 문자열을
검색해서 상태를 추측하거나 아이콘을 정규식으로 지우지 않는다. 사용자 언어팩은
아이콘을 하드코딩하지 않고 기존 `{icon_*}` 자리표시자를 사용한다. 알려지지 않은
상태는 원문과 중립 정보 아이콘으로 표시하며 실행 중·성공으로 재분류하지 않는다.

## 목록과 설정

Agent·Tool·RAG 등 컴포넌트 목록은 이름 아래에 수정 시각과 설명을 주석 색으로
표시한다. 대화 상대 그룹도 같은 부가 정보 경로를 사용한다. 요청 목록과 세션
복제 목록은 동일한 요청 요약·상태·터미널 셀 너비 말줄임을 사용한다.
Sidebar 제목·설명은 각각 한 행을 차지해 키보드 위치와 마우스 클릭 좌표가
긴 설명의 자동 줄바꿈 때문에 어긋나지 않게 한다. 선택 값과 항목 ID는 바꾸지 않는다.
빈 목록 안내는 선택할 수 있는 데이터처럼 강조하지 않으며 클릭 시 목록 포커스만 받는다.

설정 화면·Agent·Workflow의 기존 `SettingField`/`SchemaForm`이 공통 FieldLayout을
사용한다. Agent의 엔진 드롭다운도 같은 제목·설명·타입 형식을 따른다. 제목은
강조 색 1과 볼드체, 설명·타입은 주석 색 1이다. 입력 동작, 누락/null 구분,
스키마 제약, host-fixed 값, JSON 편집과 검증 예외 전달은 그대로다.

## 안내와 계약 경계

빈 컴포넌트 목록은 항목 없음과 기존 가져오기 안내를 표시한다. 빈 설정·검색·
Workflow 선택 영역은 같은 비포커스 안내 위젯을 사용한다. 오류의 원인·권장 행동은
기존 `ui/error_presentation.py`와 ErrorInfo에서 가져오며 공통 위젯은 표시만 한다.
서버 상세·모델 설명은 계속 리터럴로 처리한다.

실행/승인/재개/체크포인트·오류 분류는 backend 소유다. 이 변경은 `llm/`,
저장 레코드, 모델 입력, 재시도 횟수, 자동 승인 조건에 손대지 않는다. 렌더링 중
서비스 조회나 모델 호출을 추가하지 않는다. 헤더/본문의 별도 캐시, 변경 신호 기반
렌더링, 팝업의 단일 하단 상태 행, 포커스·스크롤 동작은 유지한다.

미리보기 자료는 `tests/hub/reports/ui-format-preview-20261103/`에 보관한다.
검증 기록은 `tests/hub/reports/ui-format-validation-20261104/`에 보관한다.
최초 집중 검사에서 긴 요청 제목을 두 번 줄이는 문제가 발견되어, 요청 목록과
세션 복제 목록은 최종 표시 너비에서 한 번만 말줄임하도록 수정했다.
최초 전체 검사에서 상태 아이콘 추가 전의 문자열을 기대한 테스트 2건과
NerdFont 문자가 잘리는 실제 표시 오류 1건을 발견했다. 상태 테스트는 새 표현에
맞췄고, 말줄임은 Unicode private-use 문자를 유지하며 터미널 제어 문자는 계속
제외하도록 수정했다. 수정 후 집중 검사 152개가 통과했다.
이 정적 검사 결과는 기존 전체 소유권 감사의 미검토 항목까지 완료했다는 뜻이 아니다.

## 2026-11-04 감사 근거 갱신

사용자가 지목한 기존 해시 불일치 12개는 이전 Git 소스에서도 불일치하던
bootstrap, execution의 environment·steps·trace, interactions의 question_values·questions,
observability의 run_display·snapshot, widget의 question·answer_feedback·preparing·thought_trace다.
이번 UI 공통화로 추가된 20개를 합쳐 32개 Hub 파일을 검토했다. 각 파일의 저장된
검토 해시와 정확히 일치하는 Git 버전을 찾아 변경분과 호출 경계를 대조했다.

| 변경 묶음 | 확인한 소유권과 계약 |
| --- | --- |
| bootstrap·EnvironmentEngine | 추가 지시 판단은 격리된 일반 Agent/Run과 공개 steer/redirect를 사용한다. 언어 지침은 기존 CompletionProcessor를 통해 전달하며 모델 설정·승인·실행 권한을 대체하지 않는다. |
| Step·질문·Snapshot·RunDisplay | Tool/질문 데이터는 관측값이다. checkpoint 존재 플래그는 조회 여부를 판단할 뿐 재개 허가가 아니다. 공개 interaction 조회·캐시 무효화·가지치기를 유지한다. |
| 답변·준비 피드백 | 입력한 답변은 임시 표시이며 접수 확정은 기존 콜백에서 받는다. 실패·중단 상태를 성공으로 바꾸거나 저장된 대화를 수정하지 않는다. |
| 설정·관리 팝업 | 공통 표시로만 교체한다. Schema·누락/null·host-fixed·CAS·승인 옵션과 공개 저장 경로를 유지한다. |
| 목록·헤더·오류 안내 | 문자 조합·아이콘·말줄임·빈 안내만 소유한다. 오류 분류·재시도 횟수·예산·승인 판단은 기존 소유자에게 남는다. |

동일한 의미와 사용 위치의 기존 판단 857개를 유지하고, 새 후보 76개에 개별
소유자·근거를 기록했다. 마지막 NerdFont 수정의 Unicode 범주 선언 1개도 별도로
검토했다. 제거된 후보 14개를 정리하고 기존에 미분류였던 13개는
미분류로 유지했다. `docs/llm/contract-coverage-reviews.json`과
`docs/llm/contract-coverage-index.json`은 현재 소스 기준으로 갱신했으며 검사 규칙은
완화하지 않았다. 갱신 직후 제품 파일 756개, 오래된 해시·구조 오류·기록된 위반은 0개다.
미검토 파일 141개를 포함한 전수 감사는 여전히 `complete=false`이며, 이번 변경 검토와
구분한다. 과거 보고서·스냅샷 및 `llm/` 구현은 수정하지 않았다.

각 파일의 이전 revision·해시·diff, 유지/신규/제거/미검토 후보는 검증 기록의
`coverage-source-diff.json`, `diffs/`, `coverage-*.json`에 보관한다.
`coverage-origin.json`은 기존 12개와 이번 변경 20개를 별도로 기록한다.

## 최종 검증

Linux Python 3.12.14에서 해시로 고정한 Linux 파일시스템 소스 복사본을 사용했다.
외부 모델을 호출하지 않고 네트워크·X11을 격리했으며 실제 사용자 워크스페이스는
사용하지 않았다. 전체 Hub 검사에는 기존 백엔드 연동 테스트가 포함된다.

| 검사 | 결과 |
| --- | --- |
| 변경 영역 집중 검사 | 152개 통과 |
| 전체 Hub 회귀 검사 | 1,082개 통과, 약 25분 52초 |
| 감사 근거·인덱스 검사 | 16개 통과 |
| 엄격한 아키텍처 S1~S7 검사 | 71개 검토 근거 유효, 신규·오래된 항목·미해결·검토 오류 0 |
| 문서 예제·링크 검사 | 오류 0 |

전체 회귀 검사의 실패·오류·건너뜀·누락·중복 실행은 모두 0이다.
`focused-final.json`, `full-final.json`, `audit-tests-final.json`,
`architecture-verified.json`, `docs-final.json`과 `summary.json`에 결과를 남긴다.
`summary.json`은 테스트한 Hub 코드와 현재 소스의 일치 여부 및 작업 시작 이후
`llm/` 원본 바이트·파일 목록의 불변 여부도 확인한다.
