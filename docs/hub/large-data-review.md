# 대용량 Tool 연결 검토 기록

## 범위와 소유권

- Hub의 생성 기본값, 공개 Builtin runtime capability 연결, 설정 설명과 분석 지침을 변경했다.
  `llm/` 구현을 수정하지 않았다. 기존 미커밋 Backend 변경은 입력으로만 사용했다.
- `ToolDataSetup`은 새 Project 기본값과 명시적인 저장의 기본 Data 패키지 준비를 소유한다.
  기존 Project를 열 때 설정이나 저장소를 재주입하지 않는다. 사용자 읽기 권한과 빈 제약
  맵을 보존하며, 불완전하게 명시한 권한을 넓은 기본 권한으로 채우지 않는다.
- `HubBuiltinTools`는 ComponentData 핸들을 Project별 런타임에만 유지한다. 원문·출력 관측·참조
  무결성은 Backend 소유다. UI 도구 토글은 `enabled`만 바꾸고 원문 목적지와 정책을 보존한다.
- 일반 파일의 예전 root 상대 경로 변환기를 제거했다. 읽기·쓰기·cwd 권한은 Backend가
  독립적으로 검증한다. 테스트 공간 원본 선택의 변환만 해당 어댑터에 남겼다.
- 승인·Run/Step·체크포인트·효과 영수증을 Hub에서 복제하거나 다시 실행하지 않는다.
  실제 명령 효과 횟수와 재시작 후 저장 원문 조회를 통합 테스트에서 확인했다.

## 검증 환경과 범위

WSL Linux 파일시스템의 해시 기록 복사본과 Python 3.12.14를 사용했다. 실행 스크립트·원본
로그·소스 해시는 로컬 `tests/hub/reports/large-data-integration/`에 있으며 배포와 자동
discovery에서 제외된다. 모델 응답은 결정적인 테스트 구현이다. 외부 모델 API는 호출하지 않았다.

- `focused-current.txt`: Hub 대용량 통합, 기본 생성, Memory, ish 환경, 질문/승인과 Backend의
  신규 streaming/path 계약을 포함한 53개 통과. 실제 30만 줄 출력의 작은 Provider 입력,
  승인 전 효과 없음·이후 1회 실행, 원문 후반부 조회와 재열기를 포함한다.
- `routing-and-creation.txt`: 설정 라우팅은 재검증 통과. 비활성화 준비의 Data 참조 오류는
  이 실행에 남아 있으며 통과한 실행으로 바꾸지 않는다.
- `creation-fixed.txt`: 공개 configure로 출력 참조를 먼저 해제한 뒤 비활성화를 시험하도록
  준비를 수정했다. 기존 설정 보존·생성·재열기 계약 6개 통과. 참조 보호는 완화하지 않았다.
- `final-consumers.txt`: 최종 소스의 대용량·설정 이동·생성/재열기 11개 통과. 범위가 겹치는
  집중 실행들의 개수를 합쳐 전체 시험 수로 표현하지 않는다.
- `full-current.txt`: 중간 소스 복사본에서 Hub 전체 707개 실행, 오류 14건(하위 사례·정리
  오류 포함), 환경 부족으로 X11 9개 건너뜀. 전체가 통과한 기록은 아니다. 설정 이동 9건과
  Data 비활성화 준비 2건은 위 최종 집중 검사에서 수정 후 통과했다.
- `full-failures-recheck.txt`: 나머지 경로 팝업과 동시 세션 재시도 2개도 최종 소스에서
  통과했다. 전체 실행에서는 각각 설정 로딩 3초, 동시 작업 10초 제한에 걸렸다. 후자는
  종료 전에 테스트 임시 디렉터리가 정리되면서 추가 저장소 종료 오류가 발생했다.
  이 두 테스트의 제한·판정이나 제품 코드를 바꾸지 않고 재검증했다. 따라서 이번 범위의
  실패 사례는 모두 재검증했지만 전체 실행의 시간 민감성까지 해결했다고 주장하지 않는다.
- `architecture-pinned.json`: LF 정규화한 소스와 개별 근거로 S1–S7 통과. new/stale/required
  outstanding/review errors 모두 0. 영향받은 기존 감사 항목 다섯 곳만 재검토해 갱신했다.
- `docs.json`: 문서 링크와 Python 예제 문법 검사 통과. 이후 추가한 문맥 관리 검토 절은
  구현 완료 주장과 분리했다.

전체 검사 종료 후 `docs-final.json`으로 문서 검사와 `git diff --check`를 다시 수행했다.
작업 시작 시 기록한 `llm/` 385개 파일의 해시가 유지된다. 제품·시험·자산 소스는
최종 집중 검사 복사본과 대조했으며, 전체 검사를 최종 소스로 다시 실행한 것은 아니다.

초기 `smoke`, `large`, `recheck`, `settings-routing` 실패 기록은 보존했다. 새 output 설정을
ToolSelection에 그대로 전달한 문제, 격리 공간의 절대 원본 경로, 직접 registry 테스트의
lifecycle 핸들 누락, 스킬 버전 기대값과 최초 설정 로딩 대기를 수정하고 해당 범위를 재검사했다.

## 추가 요청의 문맥 관리 검토

[처리 계약과 추가 보강 방향](large-data-tools.md#문맥-관리-검토-지침과-코드의-역할)에 정리했다.
이번 연결은 단일 Tool 결과 저장·크기와 경로 권한을 코드로 제어한다. 전체 문맥의 누적과
서로 다른 모델 호출의 토큰 예산을 자동으로 관리하는 새 계층까지 구현한 것은 아니다.
기존 Memory의 참조/요약과 CompletionPolicy의 최종 예산 검사를 재사용하는 것이 우선이다.
