# 전역 화면과 테마 위젯의 색상 쌍

## 소유권과 적용

`HubTheme`는 팔레트 값·검증·기본값·색상 역할을 소유하고 `ThemeStyle`은 PTK selector를
그 역할에 연결한다. 전역 화면은 `foreground`/`background`, 테마 위젯은
`widget_foreground`/`widget_background`를 반드시 한 쌍으로 사용한다.

| 영역 | 기본 전경·배경 |
| --- | --- |
| 홈 본문·입력창, 기본 패널, 팝업 바탕, 보조 버튼 줄 | 전역 전경·배경 |
| 설정 입력 필드, 일반 버튼, 드롭다운·완성 메뉴, 팝업 목록·본문, 그래프, 코드·사용자 말풍선, 상하단 바 | 테마 전경·배경 |
| 선택한 완성 항목, 하단 키 설명 | 테마 전경·배경의 반전 |

제목·위험도·설명·포커스·선택 강조의 의미 있는 전경색은 유지한다. 테마는 RGB 색상값을
혼합하거나 이름이 붙은 팔레트를 덮어쓰지 않는다. 비활성 영역의 기존 흑백 처리는 유지한다.

`appearance.mode`는 `auto`, `dark`, `light` 중 하나다. 다크는 `white` 전경과
`bright_black` 배경, 라이트는 그 반대다. 전역의 `default`는 계속 터미널 설정을 따른다.
따라서 밝은 위젯 테마를 선택해도 사용자가 지정한 홈의 전역 배경을 밝은 색으로 바꾸지 않는다.

`TerminalTheme`는 자동 모드일 때 `COLORFGBG`의 마지막 배경 인덱스가 7 또는 15이면
라이트, 그 밖에는 다크를 선택한다. 이는 터미널이 제공한 힌트이며 실제 팔레트 응답을
조회하는 기능은 아니다. 원격 호스트의 OS 테마를 SSH 클라이언트 테마로 오인하지 않는다.
현재 ish에는 OSC 색상 응답의 공개 수신 경로가 없으므로 stdin을 읽거나 PTK parser를
교체하지 않고, 질의·외부 프로세스·타임아웃 대기도 추가하지 않는다.

`HubView.theme`는 사용자 설정 원본, `render_theme`는 자동 감지를 해석한 불변 표시 사본이다.
스타일·Rich Markdown·팝업 렌더러가 같은 표시 사본을 쓴다. 감지는 생성/설정 적용 시에만
수행하며 재그리기 중 반복하지 않는다. JSON 편집·저장·내보내기는 사용자 설정을 사용한다.
표시 사본의 `dark`/`light`를 저장하여 사용자의 `auto` 선택을 지우지 않는다.

저장 형식은 기존의 현재 필드 집합 검증을 그대로 사용한다. 기존 저장 레코드·프리셋에
`mode`가 없다면 명시적으로 새 필드를 추가해야 하며 자동 변환/이전 키 호환은 제공하지 않는다.

## 실행 중 세션 스피너

세션 상태는 기존 공개 관측값으로 계산하며 저장된 Run 상태를 바꾸지 않는다. Rich `dots`
스피너의 프레임 하나를 같은 틱의 실행 세션들에서 공유하고, PTK가 한 프레임 동안 반복
요청하는 목록·커서·크기 계산에는 같은 행 사본을 재사용한다. 언어/아이콘 변경, 새 관측,
프로젝트/선택 변경과 다음 렌더링 프레임에서는 필요한 표시를 다시 만든다.

렌더 후 PTK의 실제 표시 행과 스피너 행이 겹칠 때만 다음 타이머를 예약한다. 설정 화면,
팝업, 최소화, 종료 또는 화면 밖의 실행 세션만 있는 경우에는 타이머를 취소한다.
간격은 사용자의 `progress_refresh_interval`과 Rich 프레임 간격 중 더 긴 값이다.
주기마다 백엔드 조회나 저장을 하지 않는다. 이벤트 기반 화면 갱신과 최대 주사율 제한은 유지한다.

## 검증 결과

`tests/hub/reports/theme-pairs-preview-20261109/`의 실제 PTK 화면을 사용자가 확정했다.
집중 검사 45개의 실패를 확인해 수정하고 해당 모듈 재검사까지 통과했다. 새 색상 검사의
PTK 복합 selector 표기와 실제 스피너 행의 화면 노출 조건을 바로잡았다. 설정 저장 연동의
새 작업 공간 준비는 오류 없이 약 18초에 끝났으므로 이 구간만 기존 `backend_ready`를
사용한다. UI 조작 시간 제한·제품 설정은 늘리지 않았다. 구조·계약·문서 검사도 통과했다.

색상 쌍, 자동/명시 선택·저장 원본 보존, Rich/팝업 표시, 스피너의 표시 행·수명·재사용을
검증했다. 실행 세션 40개의 목록·커서·크기 계산이 같은 프레임을 공유하고 Rich 프레임
계산이 한 번만 수행되는 것도 확인했다.

Linux Python 3.12.14와 Linux 파일시스템의 격리된 소스 사본에서 전체 Hub 1,185개를
실행했다(`full01`, 약 28분 33초). 첫 검사에서는 1,178개가 통과했고, 실패 7개는 새
테마 선택·색상 쌍·표시 사본에 맞지 않는 기존 기대값 5개와 실제 사용자 홈의 설정에
의존하던 테스트 2개였다. 후자는 임시 작업 공간을 명시하여 실제 사용자 설정과 격리했다.
제품 코드나 사용자 설정을 바꾸지 않고 검사 자료를 수정했으며, 해당 5개 모듈 전체
33개가 재검사에서 통과했다(`expectations04`, 약 50초).

`validation.json`은 전체 검사 ID의 누락·중복·skip이 없고 미해결 실패가 0개임을 확인한다.
또한 `hub/`, `llm/`, `tests/hub/`의 987개 소스 해시를 대조해 전체 검사 후 제품 코드가
변하지 않았고, 변경된 테스트 모듈은 모두 최종 해시로 재검사됐음을 기록한다.
구조·계약 검사 39개와 strict 구조/완전성/문서 검사는 통과했다. 계약 감사 대상 802개
파일의 해시 불일치·미검토·위반·불완전 계약은 모두 0개다.

검증 자료는 `tests/hub/reports/theme-pairs-validation-20261109/`에 보관한다.
`llm/`과 호스트 실행·입력·승인 계약은 변경하지 않았다. 커밋·업로드는 수행하지 않았다.
