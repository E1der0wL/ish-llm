# 전체 검사 자료와 UI 대기 검증

## 검사 입력의 소유권

Linux 실행기 `tests/llm/run_linux.py`는 `tests/source_tree.py`로 검증 복사본을 만든다.
두 플러그인의 소스·테스트·자산, 공통 문서, Linux 의존성 lock, 참조 호스트의 설정·소스,
문서가 참조하는 CI 자료를 함께 포함한다. 개인 스크립트와 과거 보고서는 제외한다.
`--hub`는 Hub 전체 검사의 실행 여부만 결정한다.

복사본은 독립적인 Git index를 사용한다. 실제 저장소를 수정하지 않고 신규 파일까지 포함한
제품 목록을 검사한다. 삭제된 제품 파일은 현재 목록에서 제외하며 남은 검토 기록은 orphan으로
검출한다. 문서의 현재 목록을 갱신하되 과거 실행 보고서·스냅샷은 수정하지 않는다.

텍스트 검토 해시는 CRLF를 LF로 정규화한다. 다른 바이트 변경은 그대로 검출한다. 복사 manifest는
원본 바이트 해시와 Linux 복사본 해시를 모두 남긴다. 이는 저장 데이터의 무결성 검증이 아니라
개발 소스 검토의 줄바꿈 기준이다. 백엔드 저장 기록·체크포인트 해시는 변경하지 않는다.

참조 호스트가 Git checkout이 아닌 경우 `git -C ish.platform rev-parse HEAD`는 상위 저장소의
커밋을 반환했다. 의존성 lock의 입력은 실제 호스트 설정·소스의 내용 해시로 고정한다. 이번 변경은
lock의 입력 fingerprint만 갱신하며 패키지 버전·배포 파일 해시는 바꾸지 않는다. CI의 별도 호스트
revision 검증은 계속 적용한다.

## UI 검사의 수명주기와 동기화

미리보기 Application은 실행 종료·취소 시 자신이 소유한 HubView를 닫는다. 테스트에서
`create_preview()`를 사용한 뒤 `app.exit()`만 호출하더라도 렌더링 작업과 스레드가 남지 않는다.
실제 ish의 prompt 반복 수명주기와 BackendWorker 종료 계약에는 영향을 주지 않는다.

실행 중 추가지시·예약 테스트의 가짜 모델은 10초 뒤 자동으로 끝나는 대신 테스트가 명시적으로
해제하는 이벤트를 기다린다. 모든 실패 경로에서도 `finally`에서 이벤트를 해제한다. 느린 환경에서
추가지시를 확인하기 전에 가짜 실행이 끝나는 경쟁 조건을 없애며 UI 동작에 대한 assertion은 유지한다.

전체 실행은 공통 `tests.llm.run_regression`의 발견/실행/누락/중복/Skip 판정을 사용한다.
선택한 모듈만 검사한 결과와 전체 결과를 구분하며, 진행 JSONL에는 테스트 ID·시작/종료·소요 시간·
스레드 수를 기록한다. 120초 이상 실행되는 테스트는 스택을 기록하되 강제로 종료하지 않는다.
실패나 대기가 다시 생기면 마지막 미완료 ID와 스택으로 실제 대기 지점을 확인할 수 있다.

컨텍스트 압축 행은 Tool 행과 같은 `이름 • 상태` 형식으로 표시한다. SnapshotReader는 이미 조회한
Step의 상태·ID·시간만 투영하고 UI가 현행 언어로 표시한다. 압축이 끝나도 현재 응답의 생각 과정에는
완료/실패/중단 결과가 남으며, 응답 종료 시 기존 생각 과정 수명주기를 따른다. 내부 요약 본문이나
오류 분석용 추론은 노출하지 않는다. 이벤트만 먼저 관측된 경우의 실행 중 표시도 실제 Step이
조회되면 중복 없이 대체한다. 새 조회 루프나 저장 파일은 추가하지 않는다.

## 증거 범위

색상 옵션 `comment2`, `accent4`, `accent5`의 현재 선택적 필드 계약과 호스트의
`_library_available` API에 맞춰 오래된 테스트 기대값을 갱신했다. 제거된 API의 별칭이나
저장 형식 호환 코드는 추가하지 않았다.

변경된 파일의 현행 소유권 검토를 갱신했다. 기존에 미검토인 파일·후보는 미검토로 남아 있으므로
현재 목록 일치와 아키텍처 게이트 통과를 전수 소유권 감사 완료로 해석하지 않는다.
실행별 상세 결과는 `tests/llm/reports/`에 보관한다. 검증 환경과 실행 명령은
[테스트 안내](../../tests/README.md)를 따른다.
