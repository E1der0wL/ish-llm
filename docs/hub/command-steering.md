# 장시간 명령 중 추가 지시

## 실행 경계

Hub의 기본 대화용 Loop는 Agent가 이미 허용한 `process_start`, `process_status`,
`process_output`, `process_cancel`을 함께 사용할 수 있을 때, 동기 `shell_execute`
대신 이 도구들을 다음 모델 호출에 노출한다. Agent의 도구 선택 상한·프로젝트 권한을
확장하거나 기존 설정을 다시 저장하지 않는다. 시작은 기존 승인 API를 거치며 명령은
한 번만 실행한다. 반환된 process_id로 상태와 출력을 조회한다.

`process_status`에 Hub가 선언한 선택 인자 `wait_seconds`를 추가한다. 이 대화용
Loop 안에서는 기본 30초 이내로 기다리며 종료 또는 추가 지시 접수가 관측되면 먼저
반환한다. `wait_seconds=0`은 즉시 조회다. 다른 실행 경로의 생략값은 기존 즉시
조회이며, 명시한 대기 시간은 관측에만 적용된다. 프로세스 실행 제한·Tool/Run
기한·취소는 기존 백엔드 정책을 따른다. Hub 기본 대기 간격은 `HubDefaults`가 소유한다.

추가 지시는 `run.steer()`가 영속 접수를 완료한 뒤 해당 Project/Session/Run의
관측 대기를 깨운다. 지시 소비·반영 영수증은 기존 Loop/Run이 소유한다. Hub가
지시를 먼저 소비하지 않는다. 현재 UI는 [추가 지시 판단](instruction-cards.md)을 위한
별도 내부 모델 호출로 steer/redirect를 선택하지만, 원 작업을 새 Run으로 대체하지 않는다. 실제 모델이
추가 지시를 보고 답변하는 시간은 모델 호출 속도와 실행 정책에 영향을 받는다.

`shell_execute`의 완료 대기 계약 자체는 바꾸지 않는다. 동기 도구만 허용한 Agent,
사용자 지정 Tool selector, Graph의 기존 ToolNode 실행은 이 노출 전환 대상이 아니다.
이미 시작한 동기 호출을 도중에 비동기로 바꾸지는 못한다. 대화용 프로세스 도구 역시
동작 중 명령을 자동 수정하지 않으며, 중단하려면 기존 `process_cancel`과 그 승인
정책을 사용한다. Run 중단/종료가 백그라운드 프로세스 종료를 뜻하지는 않는다.
프로세스 자원은 기존 Toolkit이 소유하며 Hub 종료 시 정리한다. 출력 보존·페이지
조회·cwd/env·승인·프로세스 제한은 백엔드 소유다.

## 입력 선택과 말풍선

실행 중 Enter 팝업은 **추가 지시 → 예약** 순서이며 추가 지시를 기본 선택한다.
예약은 명시적으로 선택했을 때만 새 요청으로 접수된다. 여러 실행 대상이 있으면
기존 대상 선택을 유지하며 닫으면 입력 초안을 복구한다.

추가 지시는 원래 사용자 요청의 말풍선 하단에 본문·접수 시각·반영 상태를 붙인다.
`InstructionMessageRecord.input_message_id`와 기존 재개 연결을 이용해 소유 요청을
찾는다. 인접한 예약 요청에 임의로 붙이지 않는다. 저장된 Message, 지시 영수증,
모델 입력은 합치거나 덮어쓰지 않는다. 부모가 없는 부분 이력에서는 지시를 독립적으로
보존한다. 재접속 시에도 같은 영수증으로 표시를 복원한다.

표시 데이터는 `InstructionDisplay`와 `UserInstructions`가 소유한다. 일반 대화의
증분 투영은 변경된 지시의 부모까지 갱신 범위를 확장하고, 응답 본문 캐시는 재사용한다.
말풍선 본문 캐시 키에는 부착된 지시를 포함해 접수/반영 상태 변경이 누락되지 않게 한다.
이 투영은 실행 권한이나 재개 판단에 사용하지 않는다.

## 검증 범위

`tests/hub/test_command_steering.py`는 실제 Linux 프로세스를 한 번 시작한 뒤
승인·재개·추가 지시·명령 종료 전 응답·완료 출력 보존을 로컬 모델 대역으로 검증한다.
`test_instruction_display.py`, `test_running_submission.py`, `test_render_pipeline.py`는
기본 선택, 예약 요청과의 구분, 재개 위치, 반영 상태 갱신과 렌더 캐시를 검증한다.
실행 결과는 `tests/hub/reports/command-steering-20261103/`에 기록한다.
사내/외부 모델을 호출하거나 실제 사용자 작업 공간을 변경하는 검사가 아니다.

### 2026-11-03 검증 결과

Linux Python 3.12.14의 해시 검증된 Linux 파일시스템 소스 사본에서 실행했다.
전체 Hub 검사 1,049개 중 1,045개가 통과했다. 기존 기본 선택·독립 지시 말풍선을
가정한 UI 검사 3개와, 기본 도구 노출에 동기 셸을 가정한 승인 이력 검사 1개를
새 요구사항에 맞게 수정했다. 동기 셸 이력 검사는 해당 도구를 명시적으로 선택한
Agent로 기존 승인·재시작·실행 영수증 검증을 그대로 수행한다.

최종 소스에서는 실패 4개를 포함한 관련 19개 모듈 171개가 모두 통과했다.
장시간 명령 종료 전 실제 화면에 답변이 보이는 검사와, 안내가 실제 노출된 도구만
참조하는 검사도 포함한다. 전체 실행 기록과 최종 재검 기록은 각각 `full.json`,
`verified.json`이며, 이는 최종 소스로 전체 검사를 다시 한 번 통과했다는 의미는 아니다.

원본 대비 `llm/` 파일 해시 변경은 없고, 변경한 Hub 코드의 신규 정적 감사 후보도
없다. 전체 정적 감사에는 이번 작업 전부터 있던 `docs/hub/questions-tools.md`의
검토 해시 불일치가 남아 있어 전체 정적 감사 통과로 표시하지 않는다. 근거는
동일 보고서 디렉터리의 `change-audit.json`, `guard.json`에 기록한다.

위 내용은 최초 검사 당시의 결과다. 이후 감사 해시·이동한 발생 위치의 개별 검토는
[승인·추가 지시 감사 근거 재검토](contract-audit-refresh.md#2026-11-03-승인추가-지시-감사-근거-재검토)에 기록한다.
