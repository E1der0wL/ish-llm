# 공통 UI 규격

## 팔레트

`HubTheme`는 강조 색 1–5를 각각 `#98C379`, `#528BFF`, `#D19A66`,
`#A8B2BF`, `#1D2035`로 생성한다. 지정된 전경·배경·강조 색을 그대로 사용한다.
Dark/Light 모드, 색 혼합과 명도에 따른 전경 자동 선택은 제거했다.
일반 버튼·드롭다운 배경은 강조 색 5, 글자는 강조 색 4다. 요청 목록 체크리스트 배경도 강조 색 5,
상단 바와 상단 바의 버튼 배경은 강조 색 5다.
프로필 바는 강조 색 5 배경에 별명은 강조 색 2, 계정은 주석 색 1을 사용한다.
보조 버튼 배경은 포커스 여부와 관계없이 터미널 기본색(`default`)으로 투명하게 표시한다.
일반 버튼 글자와 보조 버튼 아이콘은 포커스 시 강조 색 2를 쓴다. 마우스 클릭 또는
Enter/Space 실행 시 공통 Button에서 강조 색 1로 0.15초간 반응한 뒤 포커스 색으로 돌아온다.
동작 자체를 기다리게 하지 않는다.
일반 버튼도 마우스 호버로 포커스를 받는다. 팝업·대화 상대·태그 바의 모달 경계를
벗어나지 않으며, 호버만으로 버튼의 동작을 실행하지 않는다.
Agent 생성·편집 화면의 왼쪽 목록은 설정 페이지처럼 통합 배경색을 사용한다.
컴포넌트 관리 팝업의 항목 목록은 기존 팝업 전용 배경색을 유지한다.
설정 변경 후 재시작 확인, Ctrl+W 및 상단 재시작 버튼은 같은 작은 팝업(60×9,
좁은 터미널에서는 축소)을 사용한다. 확인해야 중단·예약 취소·재연결을 시작하며,
Esc나 취소는 현재 작업과 저장한 설정을 유지한다. 설정 저장 뒤에는 중복 확인하지 않는다.
하단 키 설명 배경은 강조 색 4, 설명 전경은 강조 색 5, `<>` 안의 키 전경은 강조 색 2다.
스크롤 조합은 `Alt + <←↓↑→>`로 표시하며 실제 Home/End/PageUp/PageDown 지원도 유지한다.
하단 바 자체는 강조 색 5 배경이다. 키 설명 앞쪽 화살표는 강조 색 5 전경과 강조 색 4 배경,
뒤쪽 화살표는 강조 색 4 전경과 강조 색 5 배경을 쓴다.
설명 그룹 밖의 `Ctrl +`·`Alt +` 표시는 강조 색 4 전경을 사용한다.
설정 입력칸·코드·메시지 등 일반 위젯 배경은 강조 색 5다. 홈 입력창은 통합 배경색
`background`를 따르며 기본값은 투명(`default`)이다. 사용자 메시지 박스 글자는 강조 색 4이며,
본문 Markdown의 링크·제목·코드에도 같은 전경·배경을 적용하고 굵기 등 서식은 유지한다.
자동완성·드롭다운의 현재 항목은 강조 색 4 배경과 강조 색 5 글자를 쓴다.
일반 버튼과 드롭다운 버튼 글자는 항상 볼드체이며, 드롭다운/자동완성 목록은 볼드체를 사용하지 않는다.
자동완성·드롭다운 스크롤 트랙은 강조 색 5, 핸들은 호버 상태에도 강조 색 1이다.
설정 입력 필드는 포커스·편집 여부와 관계없이 강조 색 5 배경을 유지한다.
포커스 스타일도 설정 입력 필드의 하위 선택자를 사용해 통합 배경색으로 초기화되지 않게 한다.
페이지와 팝업 바탕은 `background`, 기본 글자는 `foreground`를 따른다.

비활성 영역은 기존 `FocusRegion`에서 최종 전경·배경을 흑백으로 자동 계산한다.
터미널 기본색과 투명 배경은 채우지 않으며 활성 팔레트를 변경하지 않는다.
기존에 저장한 색은 기본값으로 덮어쓰지 않는다. 새 `accent4`, `accent5`는 생략하면
소유자의 초기값을 사용한다. 제거된 `mode`는 더 이상 유효한 설정이 아니며,
설정/프리셋 Reader는 이전 계약처럼 미지원 필드를 자동 변환하거나 버리지 않는다.
업데이트 전에 기존 `.hub/preferences.json`의 `appearance.mode` 및 프리셋 JSON의
`global.appearance.mode`를 지워야 한다. 나머지 설정·프로젝트·대화는 지울 필요가 없다.

## 버튼과 팝업

`widget/controls.py::Button`은 텍스트에 정렬용 공백을 붙이지 않는다.
실제 할당된 터미널 셀 너비에서 PTK Window가 한 번만 가운데 정렬한다.
한글·아이콘·동적 저장 버튼도 같은 경로를 사용하며, 여백의 홀수 셀 차이는 1칸 이내다.

`widget/dialog.py::PopupSize`가 일반 팝업 크기를 소유한다.

| 크기 | 기준 | 용도 |
| --- | --- | --- |
| 작음 | 60 × 9칸 | 안내·재시작 확인, 프로젝트·세션 이름 변경 |
| 보통 | 100 × 36칸 | 도움말·로그·선택·입력·컴포넌트 관리·요청 목록 |
| 큼 | 터미널에서 가로·세로 각각 4칸 제외 | Workflow/Agent 편집 |
| 맞춤형 | 본문 위젯·제목·버튼의 필요한 너비와 높이 | 찾기 |

모두 터미널 크기로 제한한다. 작음으로 요청해도 본문에 포커스 가능한 입력·목록이
있으면 보통으로 승격한다. 프로젝트·세션 이름 변경은 명시적으로 요청된 예외로,
한 줄 입력과 확인·취소 버튼을 작은 크기에 배치한다. 그 외 입력 팝업의 승격은 유지한다.
안내의 확인/닫기 등 하단 버튼은 본문과 구분한다.
맞춤형은 입력 위젯의 선호 너비, 줄바꿈 및 버튼 배치를 측정하고 공통 패딩·테두리·
하단 상태 행만 더한다. 입력 가능한 팝업도 불필요한 빈 공간 없이 표시할 수 있다.
대화 상대의 편집·그룹·수신 대상·추방 메뉴도 맞춤형 크기를 사용한다.
하단 상태 행 바로 위 버튼 영역은 공통 `ActionBar(equal_width=True)`로 가장 긴
버튼에 맞춰 너비를 통일한다. 본문 안의 탭·입력 보조 버튼은 이 규칙의 대상이 아니다.
폭이 부족하면 같은 너비를 유지해 다음 줄로 내려가며, 본문 목록은
남은 높이에 맞춰 줄어든다. 읽기 전용 팝업의 이동키는 계속 스크롤을 담당한다.
태그 항목의 전체 화면 확대는 이 팝업 규격이 아닌 기존 출력 검사 페이지다.

홈의 프로젝트·세션 카테고리 제목 옆에는 생성·복제·이름 변경·삭제 보조 버튼이 있다.
공통 `SidebarActions`가 기존 카테고리 CRUD 동작을 호출하며 삭제 확인도 유지한다.
패널 최소 너비는 제목·버튼·프로필의 실제 표시 너비로 정한다. 버튼에 포커스가
있으면 해당 카테고리를 활성 영역으로 표시한다. 목록의 Tab 카테고리 이동은 그대로다.

`Dialog.status_bar`가 진행/상태 행의 유일한 위치이며 본문과 버튼 뒤, 테두리
바로 위에 놓인다. `DialogController`는 별도 상태 행이 없는 일반 팝업에도 이
영역을 연결한다. 로딩 전용 팝업은 `loading()`을 사용하고 본문에 중복 문구를
넣지 않는다. `PopupBody`는 남은 높이를 확보하되 별도 빈 위젯과 높이를 나누지
않으며, 고정 높이가 없는 단일 목록/텍스트 위젯은 본문 전체를 채운다.
한 줄 입력처럼 명시적으로 높이가 정해진 위젯의 입력 동작은 유지한다.

작음·보통·맞춤형 팝업의 본문은 위·좌우에 한 칸 패딩을 두고, 상태 행 바로 위도 한 줄 비운다.
상태 행 자체는 최하단을 유지한다.
큰 Agent/Workflow 편집기는 위·좌우 바깥 패딩 없이 렌더링한다. Agent 편집기는
설정 페이지의 `TwoPanelPage` 본문을 재사용하며 상태 행만 팝업 하단으로 전달한다.
Agent 보조 버튼과 저장/취소 프레임은 붙여 놓고 그 그룹 위에 한 줄을 비운다.

팝업의 CheckboxList·RadioList·TextArea 및 컴포넌트/Agent 팝업의 SidebarList는
강조 색 5 배경을 사용한다. SidebarList는 팝업 전용 선택자에만 적용하여 홈과
설정 페이지의 배경은 유지한다. 항목명·카테고리는 공통 `Heading` 또는 제목
선택자로 강조 색 1과 볼드체를 사용하며, 설명·상태 문구는 제목과 구분한다.
`PopupSurface`는 할당 영역을 공백으로 먼저 덮고 팝업 내용을 렌더링한다.
PTK의 투명 그림자는 사용하지 않아 이전 화면의 텍스트가 여백에 남지 않는다.
RadioList·CheckboxList의 ConditionalMargin, 드롭다운, 자동완성 메뉴까지
Hub 공용 ScrollbarMargin을 사용하고 조건부 표시 및 마우스 드래그를 유지한다.

드롭다운은 버튼의 실제 렌더링 너비를 사용한다. 목록도 같은 너비로 줄여 표시한다.

이번 팝업 표면·전송 선택·스크롤바·보조 버튼 변경은 Linux Python 3.12.14의
격리 사본에서 영향 범위를 검사했다. 최초 96개 검사에서 발견한 테스트 fixture
2건을 수정하고, 추가 팔레트 검사에서 새 포커스 색 기대값을 갱신한 뒤 재검증했다.
추가 검사를 합친 테스트별 최종 결과는 99개 통과다. 전체 저장소 검사의 통과를
뜻하지 않으며 최초 실패 로그도 보존한다. 결과와 대표 PTK 렌더링 이미지는
`tests/hub/reports/popup-interaction-final/`에 있다. 최종 소스·테스트 1,097개 파일을
Linux 사본과 대조했으며 `llm/` 원본은 변경하지 않았다.
하단 키 안내는 실제 바인딩을 정렬해 사용하며, 키와 동작을 색상 구획으로 나누고
Ctrl 조합만 왼쪽, Alt 조합만 오른쪽에 표시한다. 일반 키는 실제 바인딩을 유지하되
이 바에서 표시하지 않는다. 각 항목은 ``로 감싸고 앞 구분자는 색상을 반전한다.
단축키는 강조색 3을 사용한다. 좁은 화면에는 전체 항목 단위로 줄인다.

컴포넌트 관리 창은 불러오기 버튼 없이 설정·생성/편집/삭제·도움말·닫기 동작을
제공한다. 가져오기 설명은 컴포넌트와 파일/경로 종류만 표시한다. 버튼은 테두리와
조작 안내 주석 없이 공통 `ActionBar`로 배치한다. 진행률과
상태는 창 최하단의 한 줄을 공유한다. Workflow/Agent 생성·편집은 계속 큰 창이다.

## Agent 편집과 설정

Agent 편집은 공개 `project.agents.adescribe(engine=...)`의 스키마를 사용한다.
`SettingsEditorLayout`이 `SidebarList`, `TabPage`, `SchemaForm`, `SettingsPane`,
`ContentInset`, `ActionFrame`/`ActionBar`를 조합한다. 원본 스키마의 제약과 revision
검증, Engine별 초안, 입력값 보존은 기존 계약을 유지한다. Engine 변경 시 드롭다운의
선택 값도 함께 바뀐다. 패널은 홈/설정과 같은 너비 설정을 사용하며 에이전트
카테고리 안에 항목을 배치한다. 본문 제목은 `에이전트 • 현재 페이지`, 버튼 제목은
`에이전트 : 이름`이며 일반 필드도 본문 너비를 채운다. 빈 하단 여백은 없다.

- 좌측 ↑↓로 항목을 선택하고 →/Enter/Space로 탭 목록에 진입한다.
- 탭은 ←→로 전환하고 Enter/Space로 내용에 진입한다.
- 항목은 ↑↓로 이동하고 Enter로 편집·확정, d로 비우기, e로 등록된 외부 에디터를 사용한다.
- Tab/Shift+Tab은 설정 내용과 하단 버튼 영역을 이동한다. 버튼은 ←→로 이동한다.
- ESC는 편집 내용에서 탭으로, 탭/버튼에서 패널로 복귀한다. 팝업 패널에서 ESC는 닫기다.
- 설정 내용과 오른쪽 경계 사이에는 공통 여백이 있다.

설정 페이지의 하단 버튼은 저장·취소다. 진단과 오류 복구는 전역의 디버깅 페이지에
표시한다. 저장 계약을 바꾸거나 별도 설정 사본을 만들지 않고 General과 동일한
초안을 공유하므로 페이지 전환 시 변경 사항이 사라지지 않는다.

백엔드가 닫힌 빈 객체로 선언한 설정은 입력칸을 만들지 않는다. 편집할 필드가 없는
페이지/탭은 안내를 표시한다. 확장 가능한 객체·nullable·union·ref는 값의 의미를
보존하기 위해 JSON 편집을 유지한다.

## 승인 정책

기존 승인 설정은 **현재 프로젝트 → 일반 → 정책 → 승인**에 있다.
`config.policies.approval`을 공개 프로젝트 설정 API로 저장한다. 동일한 전역 정책이나
Hub 자체 승인 우회 경로를 추가하지 않는다.

- `enabled=false`: 승인 대상으로 선언된 도구마다 사용자 확인.
- `enabled=true`: `risk_scheme`과 `rules`에 맞는 작업만 자동 승인.
- Hub 기본 평가 척도는 `hub-model-risk-v1`, 카테고리는 `tool.execute`다.
  낮음 20, 보통 60, 높음 100이며, 예를 들어 낮음까지 자동 승인하려면
  `rules`를 `[{"id":"low-risk","category":"tool.execute","max_risk":20}]`로 지정한다.
- 위험도를 알 수 없거나 부작용이 불확실한 재실행은 자동 승인 대상이 아니다.
  사용자 정의 호스트 평가기를 쓰면 해당 평가기의 척도·카테고리를 사용한다.

## 목록 클릭

스크롤바의 트랙과 위·아래 화살표는 소속 위젯의 배경색을 상속한다. 손잡이의
강조색은 유지한다. Window margin, 조건부 목록 margin, 자동완성 및 ScrollablePane은
공통 스크롤바를 사용하며 팝업 전용 목록 배경이 홈·설정 페이지 목록에 전파되지 않는다.

실행 중인 세션에서 Enter로 요청하면 맞춤형 전송 팝업에서 예약 또는 추가 지시를
선택한다. 팝업은 닫기 버튼과 최하단 진행·상태 행을 갖는다. 예약만 일반 요청으로
접수하며, 추가 지시는 공개 Run 상태를 다시 조회한 뒤 지정된 실행에 보낸다. 여러
수신 Agent가 실행 중이면 사용자가 하나를 명시적으로 고른다. 조회 도중 닫거나 실행이
이미 끝났다면 추가 지시를 임의로 예약으로 바꾸지 않는다. 닫으면 입력 초안을 복원한다.

공통 `SidebarList`는 빈 공간 클릭 시 포커스만 이동한다. 항목 클릭은 선택하고,
이미 선택된 항목을 다시 클릭하면 그 목록의 Enter/Space 동작을 호출한다.
세션 목록은 입력창으로 이동하고 태그 바는 확대, 대화 상대는 작업 메뉴를 연다.
별도 활성화 동작을 등록하지 않은 목록은 기존 선택 동작을 유지한다.
