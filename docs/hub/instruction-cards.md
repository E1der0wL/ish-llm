# 추가 지시 판단과 공통 실행 미리보기

## 사용자 조작

실행 중 Enter의 선택은 **추가 지시 / 예약**으로 유지한다. 전체 중단은 별도 조작이다.
추가 지시의 대상 Run을 정하면 원래 사용자 요청 아래에 **준비 중**을 바로 표시한다.
별도 모델 호출이 새 입력을 보충 지시인지 즉시 방향 전환인지 판단한다. 사용자에게
steer/redirect 구분을 요구하지 않는다. 판단 호출의 추가 지연·비용은 사용자 선택 사항이다.

판단은 대상 Run에 저장된 Agent binding의 모델 연결 설정을 사용한다. 모델이 없는 Graph
조정자는 선택된 활성 Agent Step의 저장된 binding에서 모델을 빌린다. 여러 대상이면 그중
첫 모델 설정을 사용하며 현재 편집된 Agent나 기본 Agent로 임의 대체하지 않는다. 짧은 원 요청,
현재 Step 관측과 새 지시만 제공하며 Tool은 제공하지 않는다. `_hub_instruction` 엔진과
내부 Agent/Session의 일반 Run·Step을 사용하므로 Provider 호출·사용량·오류 기록의
소유권을 유지한다. 운영 로그는 원 Run과 판단 Run의 ID를 연결한다. 내부 Session은
처리 후 종료·soft delete하며, 판단 원문은 백엔드 기록과 보존 정책을 따른다.

보충은 공개 `steer()`, 방향 전환은 공개 `redirect()`로 전달한다. **반영 대기**는
이 API가 저장한 영수증을 받은 뒤에만 표시한다. 같은 request_key 재전송은 저장된
종류로 같은 API에 보내 내용·대상 검증과 중복 방지를 유지한다. 판단 실패, 대상 종료,
지원하지 않는 redirect 등은 기존 오류 안내와 입력 초안 복원 경로를 사용한다.
실패를 성공으로 바꾸거나 예약/새 작업으로 자동 대체하지 않는다.

## 실행 경계

판단 모델은 실행 권한·위험도·승인 여부를 결정하지 않는다. `redirect()`는 **접수 순간**
해당 대상에서 실행 중인 호출에 취소를 요청한다. 판단 당시의 Step과 다를 수 있으므로
모델만 취소하거나 특정 Tool을 반드시 건너뛴다는 보장은 없다. 모델에 이 한계도 알린다.
백엔드의 취소 정리, 불확실한 Tool 효과, 승인, checkpoint/resume 검증을 유지하며 Hub가
Tool을 자동 재실행하거나 불확실한 기록을 초기화하지 않는다. 원 Run의 실패·일시 정지와
승인·재개 안내는 기존 저장 상태 조회를 따른다. 동기 호출이나 원격 서버의 즉시 중단을
보장하는 기능은 아니다. 프로세스 관측 대기 해제도 기존 장시간 명령 어댑터를 사용한다.

`applied`는 모델 입력에 포함되었다는 뜻이며 이행·완료의 증거가 아니다. 여러 Graph 대상은
대상별 상태·미반영 이유를 표시하고, 혼동되는 ‘일부 반영’ 종합 문구는 표시하지 않는다.
저장된 종합 상태와 개별 영수증은 변경하지 않는다.

## 미리보기와 표시 성능

`ToolDetails`는 이미 관측한 Step의 선언된 인자·결과·오류 필드만 읽는다. 화면용
`compact` 투영은 `TextPreview`가 명령·경로·검색어와 본문·표준 출력 등의 대표 값을
선택하며, 그 외 객체도 제한된 키·값 텍스트로 표시한다. 도구별 폼이나 실행용 스키마
변환은 없다. 테두리·배경·입력/결과 제목 없이 주석 색 1을 사용하며, Tool 하나는
이름·상태·입력과 결과/오류를 합쳐 **최대 4행**으로 표시한다. 이름·상태·입력은 첫 행에만
표시하고 너비를 넘으면 `…`로 자른다. 결과/오류는 나머지 최대 3행에 표시하며 초과한
마지막 행은 `…`로 자른다. 값 선택은 최대 700자, 컨테이너 6항목/깊이 3의 표시 예산을 쓰며
전체 큰 객체를 먼저 직렬화하지 않는다. 별도 모델 요약·참조 파일 읽기를 추가하지 않는다.
Tool 인자·실제 결과·원문 보존·컨텍스트 정책은 바꾸지 않는다. 추가 지시 판단에 사용하는
기존 `ValuePreview` 투영(1,600자/12행)은 이 UI 축약과 독립적으로 유지한다.

`TraceItem`의 불변 details와 기존 항목별 렌더 캐시를 사용한다. 변화 없는 미리보기·응답은
재사용한다. Tool 입력·결과는 터미널 제어문자를 제거한 평문이며, 질문·답변은 Markdown의
읽을 수 있는 텍스트만 추출해 같은 주석 색으로 질문·설명·답변을 각각 별도 행에 표시한다.
설명이나 답변이 없으면 해당 행을 만들지 않는다. 로컬 답변 전달 중 표시는 저장 확인과 구분한다.
별도 포커스 영역이나 입력창을 추가하지 않는다.

`ask_user`는 현재 Step ID로 질문과 입력창 답변을 연결한다. 답변 전달 중의 로컬 피드백은
그 카드만 갱신하며, 저장 완료로 가장하지 않는다. 이후 Step에 저장된 인자·결과가 우선한다.
native 입력 Interaction은 공개 `ainteraction_views()`로 질문·응답을 읽는다. 질문·답변 카드도
생각 과정의 공통 표시 정책을 따른다. 정상 답변 완료 후 생각 과정이 숨겨지면 함께 숨기며,
카드만 남기는 예외는 두지 않는다. 재개·재조회 시에도 같은 정책과 원본 ID를 적용한다.
이력은 현재 표시 범위에서만 상세 조회하고, 완료된 Step/질문 관측을 캐시한다.
시간·생각 표시에서 이미 읽은 checkpoint 존재 여부와 Run 핸들을 재사용한다.
화면 밖 이력을 미리 읽거나, 변경 없는 이력의 Step을 매번 다시 읽지 않는다.

## 언어

기존 사용자 언어 설정을 답변·질문·공개된 생각 요약·진행 설명의 지침으로 제공한다.
기존 Agent의 저장된 시스템 프롬프트는 덮어쓰지 않는다. 번역 호출을 만들지 않으며
코드·경로·식별자·Tool 원문을 번역하지 않는다. 모델이 공개하는 내용·언어의 한계는 유지된다.
언어 변경의 적용 시점은 기존 전역 언어 설정의 재시작 규칙을 따른다.
호출 시 언어 코드와 읽을 수 있는 언어명을 함께 전달하고 첫 공개 생각 요약부터
적용하도록 안내한다. 영문 시스템 지침·도구 설명은 언어 선호를 바꾸지 않는다.
이는 Provider가 공개한 요약의 언어 지침이며, 비공개 추론의 추가 공개나 강제 번역을
요구하지 않는다. 실제 모델의 언어 준수 여부는 별도이며 지침만으로 보장하지 않는다.

## 검증

`tests.hub.test_execution_cards`, `test_question_tools`, `test_command_steering`,
`test_instruction_display`, `test_approval_continuation`, `test_render_pipeline`이 공통 카드,
입력 즉시 피드백, 기록 복원, 실제 native redirect의 효과 불확실성, 일반 지시/예약과
승인 재개 보존을 검증한다. 모의 모델만 사용하며 실제 Provider 취소 지연은 별도다.
이번 실행 자료는 `tests/hub/reports/conversation-cards-20261103/`에 보관한다.

### 2026-11-03 실행 결과

- Linux Python 3.12.14, Linux 파일시스템의 해시 고정 사본과 격리한 네트워크·X11 공간을 사용했다.
- 전체 Hub 1,069개 실행: 1,066개 통과, 테스트 3개에서 오류 4건이 발생했다.
  모의 Session·Step 자료를 현재 조회 계약에 맞추고, 질문 복원에 필요한 Run 조회의 중복을 제거했다.
  기존의 반복 I/O 방지 조건을 유지하며 화면 밖 Step을 읽지 않는 조건도 확인했다.
- 최종 소스의 영향 경로 201개와 시간·캐시·화면 범위 조회 18개를 다시 실행해 **219개 모두 통과**했다.
  테스트 ID별 최종 결과는 발견 대상 1,069개 전체를 덮으며 미검증·Skip은 없다.
  최종 소스로 전체 검사를 다시 한 번 실행했다는 뜻은 아니다. 최초 오류도 보고서에 보존했다.
- 엄격한 S1~S7 검사: 개별 검토 근거 70개, 새 후보·오래된 근거·검토 오류 0개.
  기존 Hub 근거의 소스 해시만 재검토했고 규칙·baseline은 변경하지 않았다.
  별도의 저장소 전체 소유권 감사 완료를 의미하지 않는다.
- 최종 재검 소스와 현재 `hub/`, `tests/hub/`, `llm/` 918개 파일이 일치한다.
  `llm/` 398개 파일은 작업 시작 시의 원본 바이트와 동일하다.

최초 결과는 `full.json`, 최종 재검은 `final-focused.json`·`final-repair.json`,
테스트별 결과 출처와 소스 대조는 `final-summary.json`에 기록한다.
실제 서비스 모델을 호출하지 않았으므로 판단 품질·실제 Provider 취소 지연은 실사용 확인 대상이다.

### 질문 카드 표시 정책 후속 정정

완료 후 질문 카드만 남기던 예외를 제거했다. 실행·일시 정지·빈 최종 답변의 표시 여부는
기존 생각 과정 정책을 그대로 따르며 정상 답변 완료 시 함께 숨긴다. 저장 기록은 삭제하지 않는다.
Linux Python 3.12.14에서 관련 4개 모듈 **35개 검사**와 엄격한 계약·문서 검사를 통과했다.
이번 표시 정책 수정에서는 전체 회귀를 반복하지 않았다.
결과는 `tests/hub/reports/question-visibility-20261103/`에 보관한다.

### 간결한 미리보기 UI — 확정 및 검증 완료

카드 테두리·배경을 제거하고 Tool 최대 4행, 질문·설명·답변을 각각 별도 행에 주석 색 1로
표시하도록 변경했다. 추가 지시의 pending 문구는 `반영 대기`로 줄였으며 저장된
접수 결과를 기다리는 조건은 그대로다. `tests/hub/reports/execution-preview-lines-20261103/`의
이미지는 실제 PTK 렌더러에 예시 데이터를 넣은 화면이며 실서비스 실행 기록은 아니다.
사용자가 화면을 확정하고 Tool 제한을 4행으로 지정했다.

- Linux Python 3.12.14, 격리된 Linux 파일시스템 사본에서 집중 검사 **82/82**와
  전체 Hub 회귀 **1,074/1,074**를 통과했다. 전체 실행 1,529.15초, 실패·오류·Skip·누락·중복 0개다.
- Tool 입력 한 줄 말줄임, 결과를 포함한 최대 4행, 한글 표시 너비, 질문·설명·답변 분리,
  주석 색 1과 원문/판단 입력의 보존을 검증했다. 기존 승인·재개·질문·추가 지시 연동도 포함한다.
- 엄격한 S1~S7 검사는 현재 소스와 Hub만 포함한 커밋 후보에서 모두 통과했다.
  검토 근거 70개, 새 후보·오래된 근거·미해결·검토 오류 0개다. 다른 미검토 영역의 전수 감사로
  확대 해석하지 않는다. 규칙·baseline은 변경하지 않았다.
- 문서 검사 226개, Python 예시 181개, 상대 링크 1,454개, 앵커 47개에서 오류가 없었다.
- 전체 검사 후 `hub/`, `tests/hub/`, `llm/` 코드 919개가 검증 소스와 일치하며,
  `llm/` 398개 파일의 원본 바이트는 작업 시작 상태와 같다.
- 공용 감사 파일의 별도 백엔드 작업은 작업트리에 보존하고 Hub 근거만 커밋 대상으로 분리했다.
  이후 변경은 이 검증 결과 문서뿐이며 제품 코드와 테스트는 바꾸지 않았다.

최종 결과는 `tests/hub/reports/execution-preview-final-20261103/`의 `full.json`,
`focused.json`, `architecture.json`, `commit-architecture.json`, `docs.json`,
`final-summary.json`과 `final-source.json`에 있다. 실제 서비스 모델 호출은 하지 않았다.
