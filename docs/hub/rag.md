# Hub RAG 사용 안내

## 등록과 검색 설정

`/rag config` → **설정**에서 현재 프로젝트의 RAG 설정을 엽니다.
설정 원본은 `config.parameters.components.rag`입니다. 사내 연결은 선택한 모델에 맞는
`config.embedding_params`와 `config.rerank_params`의 model/api_base/api_key를 지정합니다.
새 프로젝트는 hybrid 검색·리랭킹·청크 1200자·결과 5개·후보 20개를 기본으로 제공합니다.
리랭커를 쓰지 않으면 `config.search.rerank=false`로 바꿉니다.

관계 검색까지 사용하려면 `config.extraction_params`의 모델을 지정하고
`policy.extraction.failure_policy`를 `required` 또는 `best_effort`로 설정합니다.
기본값 `disabled`는 관계 추출 모델을 호출하지 않습니다. 임베딩/추출의 재시도는 RAG 자체의
`policy.provider`로 설정하며 Loop 재시도 설정을 상속하지 않습니다.

`/rag config`에 문서 경로를 입력하고 Enter를 누릅니다. 실패한 Job은 목록에서 선택해
재시도하거나 삭제할 수 있습니다. 취소한 Job은 삭제만 가능합니다. 재시도 중 모델·청크 설정이
변경되어 백엔드가 체크포인트 재사용을 거부하면 기존 작업을 삭제한 뒤 원문을 새로 등록합니다.
[진행·삭제 계약](component-managers.md#rag-등록진행재개)을 참고하세요.

재개 가능 여부는 백엔드의 `aresume_plan`으로 확인하고, 실행 시 같은 `revision`을 전달해
변경 여부와 실행 잠금을 다시 검증합니다. 목록을 처음 열 때 계획을 확인하되, 주기적 진행률
조회에서는 체크포인트 전체를 검사하지 않습니다. 아직 확인하지 않은 항목은 재개 가능으로
단정하지 않고 재시도 시 확인합니다. queued 작업은 새 등록 실행이며 체크포인트 재개와 구분합니다.
실패 이력 `failures`는 보존되지만 현재 오류는 현재 Job 진단만 사용합니다. 재개 중이나 완료 후에
이전 시도의 오류를 현재 실패로 표시하지 않습니다. 취소·재개 포기·계획 버전 충돌은 자동 우회하지 않습니다.

## 이미지 문서

PNG/JPEG 경로를 입력하면 **OCR / 모델 분석 / Vision 설정 / 취소** 창을 엽니다.

- OCR: `config.parameters.components.vision.config.ocr.backend`를 사용합니다. 새 프로젝트는
  `tesseract`를 선택하며, Linux 호스트에 실행 파일과 언어 데이터가 필요합니다. 한국어는
  `vision.config.ocr.backends.tesseract.language`에 설치된 언어에 맞춰 `kor+eng` 등을 지정합니다.
- 모델 분석: `vision.config.completion`에 이미지 입력을 지원하는 모델과 연결 정보를 설정합니다.
  Loop 모델을 자동으로 재사용하지 않습니다. 이미지 해석 요청에는 별도 API 비용이 생길 수 있습니다.

기존 프로젝트의 선택·설정은 자동 변경하지 않습니다. 이미지 등록 창의 **Vision 설정** 버튼은
해당 컴포넌트를 명시적으로 활성화하고 설정 페이지를 엽니다. 기존 컴포넌트 선택과 설정은 보존하며
버전 충돌 시 저장하지 않습니다. 기존 프로젝트에 처음 활성화했다면 OCR backend 또는 모델을 지정하세요.
이후에는 설정 창의 프로젝트 → vision에서도 편집할 수 있습니다.

Vision이 추출한 텍스트를 RAG Job으로 저장한 이후부터 청크 재개가 가능합니다. OCR/해석 자체의
실패에는 아직 RAG Job이 없으므로 경로에서 다시 시작합니다. OCR에서 글자를 얻지 못했다고
유료 모델 분석으로 자동 전환하지 않습니다.

문서 metadata에는 이미지 ID/hash, OCR 좌표 또는 모델 정보, `derived_text` 표시와 원본 경로가
보존됩니다. 픽셀 자체를 임베딩하는 기능은 아닙니다. 모델 해석은 검증된 OCR로 취급하지 않습니다.
RAG Job 삭제는 Vision 이미지 자료를 지우지 않습니다. Vision의 개별 이미지 삭제는 tombstone이며
원본 bytes는 참조 보존을 위해 남는 백엔드 계약을 따릅니다.

## 문서 개요와 검색 순서

파일 등록 시 공백을 정리한 원문 앞부분을 최대 240자로 발췌해 `description`에 저장합니다.
추가 모델 호출은 없습니다. 문서 선택 → Enter → 에디터에서 description을 수정할 수 있습니다.
모델의 `rag_add_document`도 description을 받을 수 있으며 생략하면 같은 발췌를 만듭니다.

Hub 기본 RAG 컴포넌트는 각 실행의 첫 Completion 준비에서 catalog 최대 20개를 한 번 읽고,
제목(100자)·설명(240자)만 입력에 추가합니다. 현재 Tool 범위에 `rag_search`가 없으면 조회·주입하지
않습니다. 목록이 더 있으면 `rag_list_documents`로 추가 조회할 수 있다는 정보를 전달합니다.
본문·벡터를 미리 불러오거나 검색/임베딩을 호출하지 않습니다. 실행 도중 추가된 문서는 목록 Tool로
조회할 수 있고, 다음 실행에서는 갱신된 개요를 읽습니다.

지침은 **관련 RAG 문서 → 모델 지식 → 필요한 경우 인터넷** 순서입니다. 분명히 무관한 질문은
RAG 검색을 생략하며 설명은 관련성 판단용일 뿐 답변의 근거로 사용하지 않습니다. 이 순서는 모델의
판단을 돕는 지침이며 강제 검색 라우터는 아닙니다. 미리보기 조회 실패는 로그에 기록하고 본래 요청을
계속합니다. 기존 catalog가 없는 세대를 자동 변환하거나 내부 파일로 우회하지 않습니다.

새 프로젝트의 기본 시스템 프롬프트·RAG 생성 스킬에도 같은 지침이 들어갑니다. 기존 사용자 프롬프트와
스킬은 덮어쓰지 않습니다. 직접 주입한 사용자 RAGComponent는 그 구현의 capability를 유지합니다.
