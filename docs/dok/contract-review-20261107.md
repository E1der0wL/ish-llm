# dok 계약 검토 — 2026-11-07

대상은 `dok/`, `docs/dok`, `tests/dok`의 미커밋 변경이다. 설정 이름 정리, 공통 테마·언어팩, 팝업과 캘린더 저장·예약 알림, 날씨 상세·재시도, Hub 등록, 마우스·ESC 입력, 하단 바 표시를 검토했다. ish 본체·llm·hub 변경은 검토 커밋에 포함하지 않는다.

## 발견한 문제와 수정

1. **캘린더 파일 작업의 연속 취소**: 처음 취소를 받은 뒤 스레드 작업을 직접 기다리면 두 번째 취소가 asyncio 래퍼를 종료시켜 잠금을 먼저 해제할 수 있었다. 블로킹 작업의 성공·실패 두 경우에서 이를 재현했다. `core.tasks.run_blocking()`이 반복 취소를 견디며 실제 작업 완료를 기다리도록 하고 캘린더와 기존 시스템 수집이 같은 API를 사용하게 했다. 취소 후 작업 오류는 회수하되 취소 상태를 덮어쓰지 않는다.
2. **팝업의 테마 역할 문자열 반복**: 캘린더·날씨 화면과 공통 조합 도구에서 역할 이름을 직접 적던 부분을 `ThemeRole`·`ThemeColor` 공개 선언 참조로 바꿨다. 화면 색·설정값·직렬화 형식은 유지한다.

수정 이후 커밋을 막는 미해결 문제는 발견하지 않았다. 이는 검토한 경계와 아래 테스트 범위의 결과이며 실제 Windows Terminal의 모든 입력 경로를 검증했다는 뜻은 아니다.

## Owner와 경계 확인

- 필드·기본값·검증은 기능별 `Record`에 선언하고 schema, 저장, 영어 JSONC 주석은 같은 선언을 사용한다. `initial()`의 생성 예시와 누락 필드의 런타임 기본값을 구분한다. 제거한 설정 이름은 거부하며 런타임 호환 별칭이나 자동 변환을 추가하지 않는다.
- `Theme`가 팔레트·역할·색 해석을 소유한다. 바로가기 RGB와 비주얼라이저 색 배열은 독립 설정이다. 하단 바 전용 RGB 배경은 `ThemeBackground`가 해석한다. 언어 선택·기본 상태 문구는 `Locale`을 거치며 개인 문구·일정 내용은 바꾸지 않는다.
- `CalendarEvent`·`Recurrence`가 일정 검증·반복·알림 시각을 해석하고, `CalendarStore`가 잠금·원자적 교체·수정 충돌·처리 기록을 소유한다. UI는 typed API를 호출하며 저장 JSON을 다시 해석하지 않는다. 스냅샷 캐시는 저장 자료가 아닌 한 달의 조회 결과다.
- 표시용 작업, 호스트 설치 수명의 Hub 등록, 프롬프트 사이에도 유지할 캘린더 예약 알림의 수명을 구분한다. 날씨 요청은 한 번에 하나만 수행하며 실패 후 명시적 재열기와 정상 갱신 주기를 구분한다.
- Float 등록·키 우선순위·포커스 복원·마우스 필터·ESC 시간값은 dok 소유 범위에서만 교체·복원한다. 호스트 코드와 셸 프롬프트 편집 동작을 수정하지 않는다. 다른 플러그인의 후속 변경은 보존한다.
- 선택적 Hub 연동은 공개 등록 API와 Owner의 Agent 필드·Engine 식별자를 사용한다. Hub가 없으면 로드하지 않는다. Project·Agent 보존 규칙은 Hub에 위임하며 자동 에이전트 실행·모델 호출은 추가하지 않는다.

## 검증

Linux Python 3.12.14의 해시 검증된 Linux 파일시스템 스냅샷에서 **dok 276개 테스트 모두 통과**했다(87.607초). 선택적 의존성은 미커밋 작업 트리 대신 원격 main과 일치한 커밋 `dde0c882`의 hub/llm 소스를 읽기 전용으로 추출했다. dok의 실제 Hub 등록·사용자 Agent 수정 보존 검사도 통과했고 llm/hub 테스트 스위트는 실행하지 않았다.
