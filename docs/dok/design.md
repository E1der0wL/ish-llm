# dok Float dock 설계

현재 설계와 구현 계약이다. ish 본체를 수정하지 않고 `prompt.set_float()`와 Application의 조건부 키 바인딩 레이어를 사용한다. 입력 영역 하단에 dock 6줄(바로가기 위 투명 padding 포함)과 하단 투명 padding 1줄을 배치한다. bottom-toolbar 위치는 호스트가 유지하며 내용은 [dok 상태 표시줄](toolbar.md)에서 정의한다. 설치와 공개 API는 [사용 안내](README.md)를 따른다.

현재 구현은 dock·바로가기·Linux 출력 오디오 비주얼라이저와 MPRIS 플레이어 연결을 제공한다. PulseAudio 또는 PipeWire PulseAudio 호환 서버의 모든 출력 모니터를 수집한다. 플레이어 제어와 독 마우스의 계약은 [MPRIS 연결](media.md)에 정리했다. `PlaybackSnapshot`은 제목과 재생 진행 정보만 소유한다. 오디오 설정·상태·측정은 `AudioConfig`, `AudioSnapshot`, `SpectrumAnalyzer`가 별도로 소유한다.

여기서 dock이 입력과 자동완성보다 “위”에 있다는 것은 화면의 세로 위치가 아니라 겹침 순서를 뜻한다. dock을 앞에 표시하되 입력 버퍼와 자동완성 기능은 계속 동작한다. 사용자는 토글 키, dock 너비, 바로가기 명령어와 이모지를 등록하고 수정할 수 있다. 바로가기를 실행하면 등록 명령어 뒤에 현재 입력 버퍼를 이어 붙인 결과를 즉시 제출한다.

## 확정 범위

- ish 소스, 레이아웃 생성 메서드와 자동완성 구현을 수정하거나 교체하지 않는다.
- 화면 추가는 `set_float()`로 등록한 플러그인 소유 Float 하나로 처리한다.
- dock 표시 중에도 셸 입력 포커스를 유지한다.
- 자동완성이나 여러 줄 입력과 겹치면 dock을 앞에 그린다. 이 상황을 이유로 dock을 자동으로 숨기지 않는다.
- 토글은 표시 여부만 바꾼다. 음악 재생이나 입력 중인 명령어를 중단하지 않는다.
- 너비는 고정 셀 수와 ish PTY 너비의 비율을 모두 지원한다.
- 바로가기 실행은 `등록 명령어 + 구분 공백 + 현재 프롬프트 버퍼 전체`를 ish에 즉시 제출한다.
- 기존 여유 공간을 사용하며 `reserve_space_for_menu`, 입력창 높이와 bottom-toolbar 배치를 변경하지 않는다. toolbar 내용은 별도 설정으로 관리한다.
- 구현 코드는 `dok/`, 문서는 `docs/dok/`, 테스트와 수동 미리보기·검증 스크립트는 `tests/dok/`에 둔다.

## 호스트와 렌더러의 조건

ish의 사용자 Float는 주 입력 `FloatContainer`에 들어간다. bottom-toolbar와 검색 등의 보조 toolbar는 그 바깥에 있다. 따라서 Float의 좌표 기준은 터미널 전체가 아니라 입력 컨테이너다. [ish 레이아웃](https://github.com/E1der0wL/ish/blob/main/src/ish/ui/prompt.py)

prompt-toolkit 3.0.53의 기본 예약 높이 8은 자동완성 조건에서 적용되는 입력창 최소 높이다. toolbar까지 포함한 고정 하단 8줄이라는 뜻은 아니다. [PromptSession 높이 계산](https://github.com/prompt-toolkit/python-prompt-toolkit/blob/3.0.53/src/prompt_toolkit/shortcuts/prompt.py#L1226)

이 설계는 정상적인 한 줄 프롬프트, 한 줄 bottom-toolbar, 프레임 없는 입력 화면을 기본 표시 환경으로 삼는다. 설치된 ish의 버전과 설정이 다르면 실제 배치 검증이 필요하다.

## 배치와 크기

입력 컨테이너의 실제 그리기 영역을 `(x, y, W, H)`라고 할 때 기본 펼침의 기본 설정은 아래와 같다. [요소 표시와 세로 간격](layout.md)을 바꾸면 `ElementConfig.arrange()`의 결과로 실제 높이를 계산하고 `y + H - 실제 높이`부터 배치한다. 비활성화한 요소와 그 뒤 여백은 제거한다. bottom-toolbar는 호스트가 계속 소유한다.

| 구역 | 시작 위치 | 높이 |
| --- | --- | --- |
| dock | `y + H - 7` | 6줄(바로가기 위 padding 포함) |
| padding | `y + H - 1` | 1줄 |
| 기존 bottom-toolbar | 호스트가 배치한 위치 | 기존 높이 유지 |

`H=8`인 기본 화면의 예상 배치는 다음과 같다. 숫자는 입력 컨테이너를 기준으로 한 행 번호다.

```text
0  ish > 명령어 입력
1                       ▁▂▅▇▆▄▂▁
2                  01:24 ━━━━●──── 04:10
3                      아티스트 — 제목
4                        ⏮  ⏯  ⏭
5                 (투명 padding)
6                 [1] [2] [3] … [9] [0]
7
   ───────────── 기존 bottom-toolbar ─────────────
```

dock 본문은 사용자가 설정한 너비의 공통 영역을 중앙에 두고 각 줄도 별도로 가운데 정렬한다. 기본안은 고정 80셀이다. 고정 모드는 창이 넓어져도 설정한 셀 수를 유지하고, 비율 모드는 ish PTY의 현재 열 수에 따라 다시 계산한다. 실제 계산과 작은 화면 처리는 아래 사용자 설정 규칙을 따른다. 한글과 전각 문자의 표시 폭으로 계산하며 문자열 길이만으로 정렬하지 않는다.

`Float.transparent=True`를 사용하고 각 줄의 실제 내용 폭만 그린다. 좌우 여백과 바로가기 위·하단 padding은 전혀 그리지 않으므로 뒤의 입력·자동완성과 원래 클릭 동작이 보존된다. 내용 영역(문자 사이 공백 포함)은 dock이 앞에 그려지고 클릭을 처리한다. 이 영역의 색은 `DockStyle`의 터미널 기본 배경(`bg:default`)을 사용한다.

기존 여백을 사용한다는 조건상 입력 영역이 커지거나 작아지면 dock도 그 영역의 하단을 따른다. 터미널의 절대적인 맨 아래 좌표에 고정하지 않는다. 검색·검증 toolbar나 입력 프레임이 추가되면 padding과 bottom-toolbar 사이에 호스트가 그리는 행이 들어갈 수 있다. 이때 호스트 배치를 유지한다.

## Float 등록과 표시 순서

Float는 설치 시 한 번 등록하고 핸들을 보관한다. 토글할 때 제거·재등록하지 않고 내부 표시 상태를 바꾼 후 `app.invalidate()`로 다시 그린다. `set_float()` 호출은 ish에서 레이아웃 재생성을 일으키므로 일반 토글과 애니메이션 갱신에는 사용하지 않는다. [ish Float 등록](https://github.com/E1der0wL/ish/blob/main/src/ish/ui/prompt.py)

등록할 Float는 `left=0`, `right=0`, `top=0`, `bottom=0`으로 입력 컨테이너 전체의 실제 크기를 전달받는다. `DockOverlay`는 하단 7줄 중 내용이 있는 다섯 줄에 각각 내용 폭만큼의 Window를 배치한다. padding과 위쪽 입력 영역에는 아무것도 그리지 않는다. Window로 전달받은 `erase_bg`를 강제로 켜지 않는다.

이 구조는 터미널 크기나 이전 프레임의 높이를 추측하지 않고 현재 프레임의 `W`, `H`로 위치와 표시 가능 여부를 판단하기 위한 것이다. Float 자체가 입력 영역의 선호 높이를 늘리지 않도록 유지한다.

등록 옵션의 기본안은 다음과 같다.

| 항목 | 기본안 | 의도 |
| --- | --- | --- |
| `xcursor`, `ycursor` | `False` | 커서를 따라 이동하지 않음 |
| `hide_when_covering_content` | `False` | 입력과 겹쳐도 표시 |
| `transparent` | `True` | 그리지 않는 여백·padding의 기존 화면을 보존 |
| `z_index` | 기본값 | 아래의 실제 그리기 순서를 활용 |
| 자식 Window의 `z_index` | 별도 지정 없음 | 부모가 전달한 순서를 상속 |
| 포커스 | 받지 않음 | 셸 편집 유지 |

**단순히 큰 `z_index`를 지정하는 구현은 피한다.** 3.0.53은 `xcursor` 또는 `ycursor`가 `None`이 아닌 Float를 지연 렌더링하고, 목록 순서로 그리기 우선순위를 부여한다. 기본값 `False`도 이 조건에 들어간다. ish는 기본 자동완성 Float들 뒤에 사용자 Float를 추가하므로 dock이 그 뒤에 그려지는 구조를 활용한다. 이는 현재 버전의 구현 특성이므로 버전 변경 시 다시 검증한다. [Float 렌더링 순서](https://github.com/prompt-toolkit/python-prompt-toolkit/blob/3.0.53/src/prompt_toolkit/layout/containers.py#L730)

보장할 대상은 기본 입력과 기본 자동완성이다. 다른 플러그인이 나중에 더 앞에 표시되는 Float를 추가하면 그 플러그인과의 순서는 별도 조정 대상이다. 다른 Float를 재정렬하거나 제거하지 않는다.

## 표시 상태와 토글

초기 상태는 숨김이다. `DockState.mode`는 `hidden/basic/maximized` 중 사용자 선택을 소유하며 `requested_visible`은 그 상태에서 파생한다. Ctrl+W는 숨김/펼침을 전환한다. 처음 펼칠 때 최대화를 요청하며 크기 전환용 단축키는 없다. 실제 표시 모드는 `DockGeometry`가 현재 높이·너비로 결정하고 최대화 공간이 부족하면 기본 dock을 표시한다. 표시 상태는 ish 프로세스 안에서 유지하며 다음 입력 프롬프트에도 이어진다. 재시작 후에는 숨김으로 시작한다. [최대화 설정과 동작](dashboard.md)을 따른다.

| 상황 | dock 동작 |
| --- | --- |
| 토글 켜기 | 표시 의도 설정 후 다시 그리기 |
| 토글 끄기 | dock과 padding을 그리지 않고 원래 화면 복원 |
| 자동완성 표시 | 계속 앞에 표시 |
| 여러 줄 입력 또는 긴 줄의 자동 줄바꿈 | 계속 앞에 표시 |
| 명령어 제출 또는 셸 실행 중 | 그리기 중단, 표시 의도 유지 |
| 다른 플러그인의 입력 컨트롤에 포커스 이동 | 일시적으로 숨김, 셸 입력·검색으로 돌아오면 복원 |
| 다음 입력 프롬프트 | 크기 조건이 맞으면 다시 표시 |
| 최대화 정보가 들어갈 높이 부족 | 기본 dock으로 표시, 최대화 선택은 유지 |
| 입력 영역 높이 8줄 미만 | 일시적으로 그리지 않음 |
| 계산된 본문 너비 39셀 미만 | 일시적으로 그리지 않음 |
| 화면이 다시 충분히 커짐 | 표시 의도가 켜져 있으면 자동 복원 |

최소 높이 8은 dock 6줄(바로가기 위 padding 포함), 하단 padding 1줄, 상단 입력 영역 최소 1줄을 기준으로 정한 초기값이다. 최소 너비 39는 `[1]`부터 `[0]`까지 3셀 항목 10개와 사이 공백 9개를 표시하기 위한 초기값이다. 작은 화면에서는 6줄 중 일부를 잘라 그리거나 화면 밖으로 넘기지 않는다. 너비 비율이 작아 본문이 최소 너비에 못 미치는 경우에도 사용자 설정을 임의로 늘리지 않고 같은 규칙을 적용한다.

렌더러가 현재 입력을 종료한 상태에서는 dock을 그리지 않는다. 명령 제출 시 dock이 과거 출력으로 남지 않도록 종료 프레임도 검증한다.

토글 키 기본값은 `Ctrl+W`이며 사용자가 수정할 수 있다. 기존 Application 바인딩 위에 dok 레이어를 추가하고 원본 바인딩은 보존한다. 바로가기는 dock이 실제 표시 가능한 기본 입력 상태에서만 활성화하며, 이때 같은 키 또는 접두 시퀀스가 겹치는 호스트 바인딩을 조건부로 비활성화한다. 닫힘·공간 부족·다른 컨트롤 포커스에서는 호스트 키가 복원된다. 토글은 닫힌 상태에서도 동작한다. dok 내부의 중복 키·접두 충돌은 설정 오류다.

## 사용자 설정

사용자 설정 파일 기본 위치는 `<ish home>/dok/config.jsonc`이며 설치 시 다른 경로도 지정할 수 있다. 이전 `config.json`을 찾는 대체 경로는 없으며 모든 설정 파일은 JSONC로 읽고 쓴다. 여기서 `<ish home>`은 ish가 선택한 설정 홈이며 저장소의 `dok/` 소스 폴더와 다르다. 설치·재로드 시 기존 파일이 없으면 모든 설정값·바로가기 예시와 Owner 설명을 담은 파일을 생성하며, 동시 생성 시 이미 생긴 파일을 덮어쓰지 않는다. [설정 파일 계약](configuration-file.md)을 따른다.

첫 구현은 설정 파일 편집과 `ish_reload`를 통한 재적용을 지원한다. 사용자가 등록한 값을 파일에 보존하고 재시작 시 다시 읽는다. 표시 상태는 프로세스 내 상태로 유지하되 사용자 설정은 영구 보존한다. 설정 UI는 이 기능의 필수 조건으로 두지 않는다.

| 항목 | 형식과 기본안 | 수정 효과 |
| --- | --- | --- |
| `dock.keys.toggle` | 키 시퀀스 배열, 기본 `["c-w"]` | 기존 dok 키를 해제하고 새 키 등록 |
| `dock.width.mode` | `fixed` 또는 `ratio` | 너비 계산 방식 선택 |
| `dock.width.value` | fixed는 셀 수 정수, ratio는 0 초과 1 이하 비율 | 다음 그리기부터 반영 |
| `widgets.shortcuts.items` | 바로가기·구분선 슬롯 레코드 목록, 합계 최대 10개 | 각 슬롯의 표시와 실행 내용 갱신 |
| `widgets.shortcuts.items[].slot` | 1부터 10까지 중복 없는 정수 | 표시 순서 지정, 10번은 숫자 키 표기 `0` |
| `widgets.shortcuts.items[].command` | 바로가기 레코드에서 필수인 비어 있지 않은 문자열 | 입력 버퍼 앞에 붙일 명령어 |
| `widgets.shortcuts.items[].type` | `shortcut` 또는 `separator`로 명시 | `SlotEntryRule`이 레코드 종류 해석 |
| `widgets.shortcuts.items[].text` | 구분선의 비어 있지 않은 한 줄 표시, 기본 `│` | 해당 슬롯의 비실행 표시 |
| `widgets.shortcuts.items[].icon` | 사용자가 정한 이모지 또는 짧은 기호 문자열 | 바로가기 아이콘 변경 |
| `widgets.shortcuts.items[].label` | 선택적인 짧은 이름 | 넓은 화면의 표시와 설명 |
| `widgets.shortcuts.items[].key` | 선택적인 키 시퀀스 배열 | 해당 바로가기 키 등록 |
| `widgets.shortcuts.items[].enabled` | 기본 `true` | 실행과 키 활성화 여부 |
| `widgets.shortcuts.items[].style.color` | `#RRGGBB` 전경색 | 활성 바로가기의 아이콘·텍스트 색 |
| `widgets.visualizer.style.colors` | 하나 이상의 `#RRGGBB` 색 | 하나는 단색, 여러 개는 왼쪽→오른쪽 RGB 그라데이션 |
| `widgets.visualizer.width` | 1 이상 정수, 기본 38 | 화면 너비 내 표시 길이와 전체 주파수 범위의 배치 |
| `widgets.title.style.color` | 테마 역할/팔레트 이름 | 타이틀 색상. 재생 접두 문구와 연결 실패 안내는 언어팩에서 관리 |
| `widgets.progress.style.color`, `widgets.progress.width` | 남은 구간과 시간의 테마 참조, 막대 길이 기본 48칸 | 재생한 구간과 현재 위치 `●`는 theme.roles.foreground. 핸들은 막대 길이에 포함 |
| `widgets.controls.buttons` | 선택한 버튼의 순서 있는 목록 | 생략한 버튼 숨김, 빈 목록은 줄을 그리지 않음 |
| `widgets.controls.buttons[].action/text/style.color` | 액션 종류·표시 문자·테마 참조 | 액션별 기본 기호를 제공하며 중복 액션은 거부 |
| `widgets.shortcuts.spacing.gap` | 0 이상 정수, 기본 2 | 10개 슬롯을 유지하면서 항목 사이 공백을 화면 폭 안으로 제한 |
| `audio.enabled` | 기본 `true` | 표시 중 Linux 출력 오디오 수집 |
| `audio.sources` | 기본 `[]`는 모든 출력 모니터 | 선택한 출력 모니터만 수집 가능 |

등록하지 않은 슬롯은 빈 자리로 유지하며 실행하지 않는다. 사용자는 기존 슬롯을 수정하거나 레코드를 삭제해 등록을 해제할 수 있다. 11번째 슬롯, 중복 슬롯, 잘못된 키 이름이나 너비 값은 설정 오류로 처리한다. 너비 비율은 유한한 수만 허용하며 fixed 값은 39 이상 정수로 제한한다.

설정 예시는 다음과 같다. 예시에 없는 9개 슬롯도 화면에서는 자리를 유지한다.

```json
{
  "dock": {
    "keys": {
      "toggle": [
        "c-w"
      ]
    },
    "width": {
      "mode": "ratio",
      "value": 0.6
    }
  },
  "widgets": {
    "shortcuts": {
      "items": [
        {
          "slot": 1,
          "icon": "🔎",
          "label": "검색",
          "command": "rg -n",
          "key": [
            "escape",
            "1"
          ],
          "enabled": true,
          "type": "shortcut"
        }
      ]
    }
  }
}
```

고정 너비 80셀은 `dock.width`를 `{"mode": "fixed", "value": 80}`으로 바꾼다. `["escape", "1"]`은 prompt-toolkit에서 사용하는 Alt+1 시퀀스 표현이다. 터미널이 전달할 수 있는 키 조합을 사용해야 한다.

새 설정은 전체 검증을 통과한 뒤 UI 루프에서 한 번에 적용한다. 실패하면 기존 설정·키·dock을 유지한다. 재적용 중 입력 버퍼와 표시 의도를 초기화하지 않으며, 설치 과정에서 Float나 갱신 작업을 추가로 만들지 않는다. 플러그인이 설정 파일을 저장하는 기능을 제공할 때는 원자적 교체를 사용한다.

## 너비 계산과 이모지 표시

`T`는 ish가 사용하는 PTY의 현재 열 수, `W`는 Float에 주어진 실제 입력 컨테이너 너비다. 정상적으로 연결된 PTY 크기를 읽고, 사용할 수 없는 경우에만 ish Application 출력 장치의 현재 열 수를 대체값으로 사용한다. 플러그인 작업 프로세스의 stdout 크기나 시작 시점의 `COLUMNS` 값을 기준으로 삼지 않는다.

| 모드 | 요청 너비 | 예시 |
| --- | --- | --- |
| fixed | `value` | 80이면 PTY가 120열이든 160열이든 80셀 |
| ratio | `floor(T × value)` | 60%이면 PTY 120열에서 72셀, 160열에서 96셀 |

실제 본문 너비 `D`는 `min(요청 너비, W)`다. 본문의 왼쪽은 `x + floor((W - D) / 2)`이며 각 줄도 그 안에서 가운데 정렬한다. 고정값이 화면보다 넓으면 화면 너비까지만 축소하지만 저장된 고정값은 바꾸지 않는다. 창을 다시 넓히면 원래 너비로 돌아간다. 비율 계산에는 프레임 내부 너비 대신 PTY 열 수를 사용하고, 프레임 등으로 줄어든 실제 공간에는 마지막에 맞춘다.

이 너비는 다섯 줄 본문에 공통으로 적용한다. 각 줄의 실제 내용만 중앙에 그리므로 그 밖의 입력·자동완성은 보인다. padding도 투명하게 유지한다.

이모지는 사용자 문자열 그대로 설정에 보존하고 터미널 제어문자로 해석하지 않는다. 개행과 제어 문자는 아이콘·label에 허용하지 않는다. 빈 슬롯만 `[숫자]`로 표시하고 등록된 슬롯은 이모지와 label을 표시한다. 둘 다 없으면 명령어를 표시한다. 폭이 부족하면 label을 생략하고 필요할 때 남은 표시를 결합 문자 경계에서 줄인다. 빈 슬롯의 번호는 유지하고 등록된 슬롯의 남은 폭을 배분하며 번호로 대체하지 않는다.

이모지의 실제 폭은 터미널과 폰트에 따라 다를 수 있다. 결합 이모지를 중간에서 잘라 표시하지 않고, 표시 폭 계산과 클릭 영역을 같은 기준으로 만든다. 폭이 맞지 않는 환경에서는 사용자가 단순 기호나 ASCII로 바꿀 수 있다.

## 입력과 겹침의 의미

dock이 앞에 보인다고 해서 그 아래 입력 공간이 별도로 확보되는 것은 아니다. 입력 문자가 dock 아래로 들어가면 보이지 않지만 버퍼에는 남는다. 자동완성 후보도 가려질 수 있으나 선택과 삽입 동작은 그대로다. 사용자는 같은 토글 키로 dock을 숨겨 원래 내용을 확인할 수 있다.

일반 텍스트 키는 자동으로 점유하지 않는다. Ctrl 조합은 Ctrl+C를 포함해 명시적으로 등록할 수 있고 dock이 열린 동안 바로가기가 우선한다. Ctrl+I/Tab, Ctrl+M/Enter처럼 같은 터미널 입력을 공유하는 조합은 구분할 수 없다. 등록하지 않은 키는 셸 편집 기능을 유지한다.

터미널의 입력 커서는 문자 레이어와 별개이므로 높은 표시 순서만으로 dock 위에서 커서가 사라지는 것은 보장되지 않는다. 초기 설계에서는 입력 커서를 이동하거나 강제로 숨기지 않는다. 커서가 dock 영역에 진입했을 때의 모습은 구현 검증 항목으로 두고, dock을 숨겼을 때 커서와 선택 상태가 정확히 복원되어야 한다.

## 여섯 줄의 동작

| 줄 | 내용 | 표시 규칙 |
| --- | --- | --- |
| 1 | 비주얼라이저 | 한 줄 블록 문자, 고정된 중앙 폭, 입력 데이터가 없으면 정지 표시 |
| 2 | 재생 바 | 현재 시간, 진행 막대, 전체 시간. 길이를 모르면 전체 시간은 `--:--` |
| 3 | 타이틀 | 재생 스트림의 프로그램 이름들을 표시하며, 플레이어 곡 정보가 있으면 우선 사용. 폭이 부족하면 말줄임, 개행·제어 문자는 제거 |
| 4 | 설정으로 선택한 음악 버튼 | 이전·재생/일시정지·다음·재생·일시정지·정지 중 선택, 순서·기호·색 지정. 현재는 표시만 지원 |
| 5 | 투명 padding | 아무것도 그리지 않으며 기존 화면과 클릭 동작을 보존 |
| 6 | 바로가기 10개 | 사용자 이모지·이름과 `1..9,0` 순서의 고정 슬롯. 미설정 슬롯도 위치를 유지 |

현재 “뒤로가기/앞으로가기”는 이전 트랙/다음 트랙, “재생/정지”는 재생/일시정지로 해석한다. 탐색 위치 이동이나 완전 정지가 필요하면 해당 액션 연결을 바꿀 수 있게 한다.

본문 폭이 충분하면 바로가기에 이모지와 짧은 이름을 붙이고, 부족하면 등록된 표시를 축약한다. 바로가기는 한 줄을 넘기지 않으며 10개를 두 줄로 나누지 않는다.

마우스를 사용하려면 ish의 마우스 입력 설정을 명시적으로 활성화한다. 현재는 바로가기를 클릭으로 실행하며 재생 제어는 비활성이다. 각 줄의 내용 영역 클릭은 dock이 처리하고 투명한 여백·padding 클릭은 뒤의 컨트롤에 전달한다.

키보드 바로가기는 사용자가 설정한 수정키 조합만 등록한다. 예시는 `Alt+1..0`이며 충돌을 검사한다. 실제 대상이 지정되지 않은 슬롯은 실행하지 않는다. 클릭과 단축키는 모두 아래의 동일한 명령 조합·즉시 제출 경로를 사용한다.

## 바로가기 명령 조합과 실행

바로가기는 등록 명령어를 현재 입력 전체 앞에 붙여 즉시 실행하는 기능이다. 편집기에 삽입한 뒤 별도로 Enter를 기다리는 동작은 제공 기본값으로 사용하지 않는다.

조합할 문자열 `C`는 등록 명령어, `B`는 실행 순간의 `prompt.default_buffer.text` 전체다. 커서 앞부분이나 선택 영역만 사용하지 않는다. 프롬프트 장식 문자열, 아직 수락하지 않은 회색 자동 제안은 포함하지 않는다. 자동완성 선택 등으로 이미 버퍼에 반영된 내용은 포함한다.

- `B`가 빈 문자열이면 `C`만 제출한다.
- `C`의 마지막 문자나 `B`의 첫 문자가 이미 공백 문자이면 `C + B`를 제출한다.
- 그 외에는 단어가 붙지 않도록 공백 한 칸을 추가해 `C + " " + B`를 제출한다.
- 두 문자열의 기존 공백·따옴표·개행은 제거하거나 재작성하지 않는다. 빈칸만 있는 명령어는 등록 오류로 처리한다.

| 등록 명령어 | 입력 버퍼 | 제출 결과 |
| --- | --- | --- |
| `git` | `status --short` | `git status --short` |
| `rg -n` | `"TODO" .` | `rg -n "TODO" .` |
| `ls -la` | 빈 문자열 | `ls -la` |
| `git` | `status \| head` | `git status \| head` |

버퍼는 셸 명령 구문의 나머지 부분으로 취급한다. 버퍼 전체를 자동으로 하나의 따옴표 인자로 감싸지 않으며 파이프, 리다이렉션, 변수 확장과 여러 줄 입력도 원래 구문을 유지한다. 예를 들어 명령어가 `echo`이고 버퍼에 `hello; pwd`가 있으면 `echo hello; pwd`라는 셸 명령이 된다. 버퍼 전체를 단일 문자열 인자로 전달하는 모드는 현재 요구와 별개이며 이 설계에는 넣지 않는다.

실행은 현재 기본 프롬프트가 입력을 받는 동안에만 허용한다. 검색창이나 다른 입력 컨트롤에 포커스가 있거나 제출이 진행 중이면 실행하지 않는다. 한 프롬프트에서 중복 클릭·키 반복으로 동일 요청을 두 번 제출하지 않도록 실행 진입을 한 번만 허용한다.

제출 절차는 다음과 같이 설계한다.

1. 실행 순간의 설정과 원본 입력 Document를 확보하고 명령 문자열을 조합한다.
2. undo로 원본을 되돌릴 수 있도록 한 뒤 조합한 명령을 기본 버퍼에 반영한다.
3. 기본 버퍼의 `validate_and_handle()` 경로로 검증하고 제출한다. 커스텀 validator와 ish의 전송 크기 검증을 유지한다.
4. 검증이 거부되면 실행하지 않고 원본 입력과 커서·선택을 복원하며 오류 이유를 표시한다. 제출 진행 상태를 해제해 사용자가 수정 후 다시 실행할 수 있게 하며, 반복 시 접두 명령어가 중복되지 않게 한다.
5. 수락되면 조합한 명령이 ish의 기존 분배 경로를 거쳐 실행되며 dock은 입력 종료에 따라 사라진다. 히스토리 설정이 켜져 있으면 조합한 전체 명령이 기본 버퍼의 히스토리 경로를 따른다.

ish는 기본 버퍼의 검증에 전송 검사를 연결한다. 직접 `app.exit(조합한 명령)`만 호출하면 이 버퍼 검증과 히스토리 처리를 거치지 않을 수 있어 기본 제출 경로를 사용한다. [ish 버퍼 검증](https://github.com/E1der0wL/ish/blob/main/src/ish/ui/prompt.py), [prompt-toolkit 버퍼 제출](https://github.com/prompt-toolkit/python-prompt-toolkit/blob/3.0.53/src/prompt_toolkit/buffer.py)

`validate_and_handle()`의 반환값을 성공 여부로 간주하지 않고 검증 상태와 실제 수락 결과를 확인한다. 기존 설정에서 별도 accept handler가 제출을 보류하는 경우 그 결정을 따른다. 셸 실행 후 발생한 명령 실패는 제출 전 검증 거부와 구분하며 자동으로 재실행하지 않는다.

플러그인이 별도 `subprocess` 셸을 띄우거나 PTY에 직접 명령을 쓰지 않는다. 따라서 현재 셸의 작업 디렉터리와 환경, ish의 일반 셸 명령·등록 Python 도구 분배를 따른다. 다음 프롬프트에서 사용한 버퍼를 자동으로 다시 실행하거나 되살리지 않는다.

## 재생 상태와 화면 갱신

화면은 플레이어의 읽기 전용 상태 스냅샷을 그린다. 렌더링 콜백에서 프로세스 실행, 네트워크 요청이나 오디오 분석을 수행하지 않는다. 플레이어 연결 부분은 제목, 아티스트, 재생 상태, 현재 위치, 전체 길이와 지원 액션을 제공하고 비동기로 제어 요청을 처리한다.

재생 위치와 오디오 크기 데이터는 별개다. 실제 음악에 반응하는 비주얼라이저에는 오디오 분석 데이터가 필요하다. 재생 위치만으로 실제 음량이나 스펙트럼을 표현하지 않는다. 오디오 소스가 없으면 정지 패턴을 표시하고, 장식용 애니메이션은 별도 선택으로 둔다.

초기 갱신 목표는 재생 중 비주얼라이저 최대 초당 10회, 위치 조회 초당 1회다. 위치 사이의 화면 보간에는 단조 시계를 사용하고 일시정지·탐색·트랙 변경 때 기준을 갱신한다. 숨김 상태나 셸 실행 중에는 화면 애니메이션 작업을 중단한다. 음악 자체의 재생은 계속된다.

화면 갱신은 플러그인 작업에서 `app.invalidate()`를 요청한다. 호스트 전체의 refresh 설정을 덮어쓰지 않는다. 연결 실패 시 기존 셸 입력을 유지하고 타이틀 행에 연결 상태를 표시한다. 실패 후 자동 재연결을 하지 않으며 사용자가 dock을 닫았다 다시 열 때 새 연결을 시도한다. 정상 연결 중에는 출력 장치와 프로그램 조회를 계속하고 연결이 끊어지면 캡처와 조회 작업을 모두 종료한다. 실패 메시지를 매 프레임 터미널에 출력하지 않는다.

## 설치와 해제 수명주기

`.ishrc.py`에서 플러그인의 설치 함수를 호출하여 `prompt`를 전달한다. 일반 명령 워커인 `set_tool()`을 통해 화면을 설치하지 않는다. 설치 함수는 같은 prompt에 여러 번 호출해도 Float와 키가 중복되지 않도록 한다.

컨트롤러는 표시 의도, Float 핸들과 소유한 키 핸들러를 관리한다. `ish_reload`가 다른 스레드에서 설정을 읽는 경로도 고려해 실행 중인 UI 변경은 해당 루프로 전달한다.

오디오 수집은 표시가 확인된 후 `AudioRuntime`이 Application 배경 작업으로 시작한다. 같은 설정·표시 상태에서는 작업을 재사용하고, 숨김·프롬프트 종료·해제 시 캡처 프로세스를 종료하고 회수한다. 정상 수집을 중단했다면 다음 프롬프트에서 표시 의도에 따라 다시 시작한다. 연결 실패 상태라면 프롬프트 재진입으로 다시 시작하지 않고 dock을 닫았다 다시 열 때만 새 시도를 허용한다. 장치 재탐색과 실패 후 재시도 허용 상태는 오디오 Owner가 관리한다. 플레이어 프로세스는 실행하지 않으며 MPRIS 연결과 제어 작업은 별도 `MediaRuntime`이 관리한다.

해제할 때 등록한 Float 핸들만 제거한다. 키는 플러그인 소유 핸들러로 제거하여 이후 다른 설정이 등록한 바인딩을 삭제하지 않는다. 다른 플러그인의 Float, 스타일과 키는 보존한다. 후속 플레이어 연동에는 소유한 작업 취소와 연결 종료도 추가한다.

## 구현 순서와 완료 기준

첫 단계는 재생 연동 없이 고정 내용의 Float와 토글을 구현해 겹침 순서와 복원을 검증하는 것이다. 그다음 다섯 줄 표시와 바로가기를 연결하고, 마지막으로 선택한 플레이어와 비주얼라이저 데이터를 연동한다.

검증은 Linux Python 3.12.14와 호스트가 사용하는 prompt-toolkit 버전으로 수행한다. 다음 조건을 모두 확인하기 전에는 Float 방식의 화면 안정성이 확인됐다고 판단하지 않는다.

1. 한 줄 입력 화면에서 dock 6줄(바로가기 위 padding 포함), 하단 padding 1줄, 기존 toolbar가 의도대로 배치된다.
2. 일반 자동완성과 여러 열 자동완성이 dock 뒤에 그려진다. 토글 후 후보와 선택이 다시 보인다.
3. 여러 줄 입력, 긴 줄의 줄바꿈과 선택 영역을 가려도 내용·커서·스크롤 상태는 변경되지 않는다.
4. 토글 중 입력 버퍼, 포커스와 자동완성 상태를 유지한다. 반복 토글해도 레이아웃을 재생성하지 않는다.
5. 한글 제목, 전각 문자, 긴 제목과 좁은 화면에서도 6줄 구성이 늘어나지 않는다.
6. 프레임, 여러 줄 프롬프트, 검색·검증 toolbar에서 실제 컨테이너 하단을 따른다.
7. 최소 너비·높이 경계와 빠른 창 크기 변경에서 화면 밖으로 그리지 않고 정상 크기 복귀 시 다시 표시된다.
8. Enter로 명령을 제출할 때 dock이 출력 이력에 남지 않고, 명령 종료 후 표시 의도가 복원된다.
9. Ctrl+C, 검색, 배경 출력과 다른 전체 화면 프로그램을 거친 뒤 셸 입력이 정상적으로 돌아온다.
10. 재설치와 `ish_reload` 후 Float·키·갱신 작업이 중복되지 않고 해제 시 다른 설정을 보존한다.
11. 플레이어 응답 지연과 연결 실패가 타이핑이나 토글을 막지 않는다.
12. 마우스 기능을 켠 경우 내용 영역 클릭은 dock이 처리하며 투명 여백과 padding에서는 기존 컨트롤을 클릭할 수 있다.
13. fixed 너비는 창 확대 시 유지되고 ratio 너비는 PTY 열 수에 맞춰 다시 계산된다. 화면보다 큰 고정값, 프레임, 비율로 계산한 폭이 39셀 미만인 경우도 처리한다.
14. 설정 재적용으로 키·명령어·이모지가 변경되고, 키 충돌이나 잘못된 설정이면 기존 설정과 입력을 보존한다. 재시작 후 저장된 사용자 설정을 읽는다.
15. 빈 버퍼, 공백 경계, 따옴표, 파이프, 여러 줄 입력과 커서가 중간에 있는 버퍼에서 조합 결과가 명세와 일치한다. 회색 자동 제안은 붙이지 않는다.
16. 바로가기 제출은 기존 검증과 히스토리 경로를 사용한다. 검증 거부 시 원본을 복원하고 접두 명령이 중복되지 않으며, 연속 클릭·키 반복으로 이중 실행되지 않는다.
17. 이모지 변경, 결합 이모지, ASCII 대체와 말줄임 상태에서 표시와 클릭 영역이 일치한다. 빈 슬롯만 번호로 표시한다.

Linux 세션 D-Bus에서 MPRIS 규격을 제공하는 플레이어를 연결한다. 오디오 분석은 Linux 오디오 서버 출력 모니터로 구현했으며 Windows 네이티브 소리는 포함하지 않는다. 토글 키, 너비, 바로가기 10개의 명령어와 이모지는 사용자 설정으로 결정한다.

## 장시간 실행의 자원 한도

`dok.text.width()`는 prompt-toolkit과 같은 글자 폭 해석을 사용하되 문자열 전체를 캐시하지 않는다. prompt-toolkit의 짧은 문자열 캐시는 조합 수를 제한하지 않으므로 계속 변하는 비주얼라이저를 그대로 전달하면 표시 시간에 비례해 항목이 쌓인다.

폭을 이미 맞춘 한 줄 전용 `DockRowWindow`는 스크롤 위치를 0으로 유지한다. 일반 `Window`의 커서 추적도 전체 줄 문자열을 같은 캐시에 넣기 때문이다. 이 제한은 dok 창에만 적용하고 라이브러리나 호스트 창을 변경하지 않는다. `_scroll` 확장 지점에 의존하므로 실제 Float의 반복 렌더링 테스트가 캐시 한도·내용·좌표를 함께 검증한다.

`SpectrumAnalyzer`가 무음 판정과 FFT 생략을 소유한다. `PulseBackend.analyze_stream()`은 캡처 읽기 작업 하나와 최신 PCM 슬롯 하나를 소유하며, 분석 완료를 기다리는 동안 새 PCM이 도착하면 이전 슬롯을 덮어쓴다. 분석 작업을 프레임마다 추가로 예약하지 않는다. 스트림 종료·소비자 취소·generator 닫기에서 읽기 작업을 취소하고 기다리며, 외부 캡처 프로세스는 기존 `_process()` 수명주기가 종료·회수한다.
