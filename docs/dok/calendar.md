# 캘린더 편집과 예약 알림

팝업 제목은 `Calendar`로 고정한다. 표시 중인 월·년도는 달력 영역의 탐색 행에 표시하고, 오른쪽 오늘 날짜는 `오늘 2026-11-08`처럼 `YYYY-MM-DD` 숫자 전체를 표시한다. 이전·다음 달 `<`·`>` 버튼은 공통 팔레트의 `white` 글자색과 `button_bg` 배경색을 사용한다.

Alt+C로 캘린더를 연다. 왼쪽에는 일요일부터 시작하는 월간 달력과 각 날짜의 일정 제목 네 줄이 표시되고, 오른쪽에는 선택한 날짜의 일정 편집 폼이 표시된다. `popups.calendar.week_start`로 시작 요일을 바꿀 수 있다. 달력에서 `n`으로 새 일정을 만들며, 같은 날의 여러 일정은 `e`로 목록을 열어 선택한다. New/Events 버튼은 표시하지 않는다. 반복 일정은 원본 시리즈를 편집·삭제한다.

편집 순서는 **제목 → 시간 → 반복 간격 → 알림 → 명령어 → 메모**다. 반복 기간과 사용자 휴일도 반복 간격 영역에 둔다. 기존 일정의 위치 값은 저장 시 보존하지만 편집 폼에는 표시하지 않으며 명령어로 자동 변환하지 않는다. 휴일은 사용자가 표시한 일정만 해당하며 국가 공휴일을 조회하지 않는다. 토요일·일요일·휴일은 공통 테마의 saturday·sunday·holiday 역할을 사용한다. 달력 날짜를 선택하고 Enter/Space/Tab을 누르면 편집으로 이동한다. 마우스는 일반 팝업이 포커스를 가진 동안 자동 활성화되고 닫으면 원래 상태로 복원된다. 시간 구간과 하루 종일 날짜 사이에는 Nerd Font 화살표 ``를 사용한다.

수정 중인 내용을 남겨둔 채 날짜·일정을 바꾸거나 닫으면 Save/Discard/Cancel로 확인한다. Esc로 편집에서 달력으로 돌아오는 것만으로는 초안을 버리지 않는다. 삭제는 별도로 확인한다. 셸 프롬프트의 문서·커서·선택은 건드리지 않으며, 팝업 안의 F2·편집 키가 셸로 전달되지 않는다. 프롬프트 자체가 종료되거나 플러그인을 해제하면 팝업 수명도 종료된다.

작은 창에서는 달력과 편집 영역을 한 번에 표시할 수 없으므로 현재 조작 영역을 표시한다. Tab/Enter로 편집 화면, Esc로 달력에 돌아온다. 세로 공간이 부족하면 선택 날짜 및 활성 입력 항목이 보이도록 스크롤한다. 호스트의 빈 공간을 확장하지 않으므로 전체 달력을 한 번에 보려면 창을 넓히거나 프롬프트를 위쪽으로 옮겨야 한다.

## 시간과 반복의 의미

새 일정은 날짜를 처음 선택해 초안을 만들 때만 시작·종료 기본값을 정한다. 시작은 선택한 날짜에서 현재 지역 시각의 다음 정각(분·초·마이크로초 0), 종료는 시작 +1시간이다. 예를 들어 현재 14:37이면 시작 15:00:00, 종료 16:00:00이다. 자정을 넘으면 날짜도 넘긴다. 이후 시작 날짜·시각을 선택해도 종료 날짜·시각은 바뀌지 않으며, 하루 종일 모드에서도 자동 연동하지 않는다. 저장 시 종료가 시작보다 늦어야 한다는 검증은 유지한다. 저장된 일정은 기존 시각·마이크로초를 유지하며 열 때 현재 시간으로 덮어쓰지 않는다. `EventTiming`이 초기 정각·간격·날짜 넘김을 소유하고 View는 주입된 시계만 전달한다. Python의 마지막 날짜를 넘어가는 경우에는 해당 날짜의 마지막 정각 두 개를 사용한다.

시작·종료 날짜 `YYYY-MM-DD`와 시각 `HH:MM:SS`은 텍스트 입력 대신 각각 미니 달력과 시·분·초 선택기로 편집한다. 버튼 안의 날짜·시각과 `` 아이콘은 한 묶음으로 가운데 정렬한다. 미니 달력은 설정한 시작 요일과 사용자 휴일 색을 공유하고 연·월 이동, 오늘 선택을 제공한다. 시각 선택기는 24시간제로 시 0–23, 분·초 0–59를 선택하며 기존 마이크로초는 보존한다. 이는 datetime의 실제 날짜·시각 범위이며 추가 연도 제한은 없다.

시작·끝 날짜/시각 버튼 사이의 가로 간격은 3칸이다. 양쪽 버튼은 같은 너비를 사용한다. 내용이 들어갈 공간이 있으면 글자·아이콘 양옆 여백이 같아지도록 버튼 너비를 셀 단위로 맞추고 남는 폭은 버튼 바깥에 둔다. 하루 종일 모드에서는 같은 간격 안에 화살표를 표시한다. 선택 중인 값은 로컬 선택 상태에만 있고 적용 후에 초안으로 전달한다. 선택기 적용은 일정 저장이 아니며 저장/F2로 최종 저장한다. Esc·취소·바깥 본문 클릭은 기존 초안을 바꾸지 않는다. 선택기 안의 입력은 뒤의 일정 편집기나 셸로 전달하지 않는다. 선택기는 해당 필드 아래에 배치하되 공간이 모자라면 위로 이동하고 팝업 본문 안에 맞춘다. 공통 테마의 메뉴·선택·버튼·구분선 색과 현재 UI 언어를 사용한다.

새 일정은 현재 `clock.timezone`을 기억한다. `null`은 각 날짜에 해당하는 시스템 지역 시간 규칙을 사용한다. 이미 저장한 일정의 명시적 시간대는 전역 설정을 바꿔도 유지된다. 종료는 시작보다 늦어야 한다. `●/○ 하루 종일` 토글을 켜면 시각 선택기와 해당 Tab 포커스를 숨기고 날짜를 comment 색으로 표시한다. 편집기에 표시하는 하루 종일 종료 날짜는 포함한다. 저장소의 종료 시각은 그 다음 날 자정으로 변환하여 기존의 종료 미포함 계약을 유지한다.

일정 영역 전체는 `theme.roles.editor_bg`, 텍스트 입력창은 `input_bg`로 칠한다. 배경 영역의 너비는 유지하고 안쪽 위젯·라벨·구분선에는 좌우 한 칸씩 여백을 둔다. 매우 좁은 창에서는 내용 한 칸을 남기도록 여백을 줄인다. 드롭다운 기준점과 알림 목록 휠 영역도 같은 안쪽 좌표를 사용한다. 반복 간격·단위·휴일 선택은 한 행이다. 메모는 남는 높이를 채우고 저장·취소·삭제 버튼은 한 줄씩 위·아래 여백을 두고 본문 하단에 고정한다. 두 영역 아래, 하단 바 바로 위에는 팝업 전체 너비의 빈 행을 한 줄 더 둔다. 팝업 맨 아래의 키 안내는 달력·필드·목록·확인 창에 맞춰 갱신한다.

반복은 없음, N일, N주, N개월, N년이다. 간격은 양의 정수다. 월·년 반복은 최초 날짜를 기준으로 계산하고 해당 월에 그 일이 없으면 마지막 날을 사용한다. 예: 1월 31일 → 2월 28일 → 3월 31일. 일광절약 시간 전환으로 존재하지 않는 시각은 저장 시 거부하고, 반복 중 해당 시각이 사라지는 회차는 건너뛴다. 두 번 존재하는 시각은 첫 번째를 사용한다. 한 날짜에 겹치는 동일 시리즈는 한 항목으로 표시한다.

반복하는 일정에는 간격 행 아래 빈 줄 한 줄과 **값 / 반복·종료날짜 선택 버튼**을 둔다. `반복`은 최초 일정을 포함한 총 횟수다. 3을 입력하면 `3회`, 0은 `계속`으로 표시하며 저장 값은 숫자를 유지한다. 음수·소수 횟수는 허용하지 않으며 별도 횟수 상한은 없다. `종료날짜`는 미니 달력으로 선택하며 해당 날짜에 시작하는 회차까지 포함한다. 마지막 회차가 다음 날까지 이어지면 그 날짜의 달력 표시와 회차에 등록한 알림도 유지한다. 비활성 모드의 초안 값은 다시 전환할 때 재사용하지만 저장·검증에는 활성 조건만 사용한다. `Recurrence`가 달력·알림·명령어의 공통 종료 판정과 마지막 유효 회차 조회를 소유한다.

알림은 `숫자 + 단위 드롭다운 + 등록` 행에서 추가한다. 드롭다운 순서는 **일정 시작 시간, 주 전, 일 전, 시 전, 분 전, 초 전**이다. 일정 시작 시간을 선택하면 숫자를 공통 테마의 `comment` 색으로 표시하고 클릭·키보드 편집·Tab 포커스와 계산에서 제외한다. 단위를 다시 바꾸면 입력해 두었던 숫자를 재사용한다. 시작 시간의 등록 값은 항상 0이다.

등록 입력의 기본값은 **5분 전**이다. 기존 등록 알림을 바꾸거나 새 일정에 자동 등록하지는 않는다. 알림 목록의 삭제 버튼 배경은 목록과 같은 `input_bg`이고 글자색은 `delete` 역할을 사용한다.

등록된 알림만 저장 대상이다. 숫자나 단위를 바꾸고 등록하지 않은 값은 저장되지 않는다. 등록 행 아래에는 빈 줄 한 줄을 두고, 그 아래 고정 세 행의 스크롤 영역에서 한 번에 알림 세 개를 표시한다. 목록 배경은 `input_bg`, 세 개를 초과하면 오른쪽에 `scrollbar` 색의 위치 블록만 그리며 세로 레일 선은 표시하지 않는다. 키보드·목록 위 휠로 스크롤할 수 있으며 등록 개수에 임의 상한은 없다. 각 행의 삭제 버튼으로 개별 삭제할 수 있다. 마지막에 일정 **저장/F2**를 눌러 목록을 확정한다. 등록된 알림이 없으면 그 일정에는 알림이 없다.

`1주 전`과 `7일 전`처럼 같은 시각을 뜻하는 값은 한 알림으로 합친다. 목록은 알림이 먼저 울리는 순서다. 유한한 숫자와 소수를 지원하며 음수는 시작 후 알림을 뜻한다. 날짜·시간은 Python datetime이 표현할 수 있는 범위를 벗어날 수 없다. 일정 시작을 수정하면 알림도 그 차이를 유지하며 이동한다. 반복 일정은 매 회차 시작의 지역 시각을 기준으로 계산한다. 일광절약 시간 전환으로 특정 알림 시각이 존재하지 않으면 그 알림만 건너뛰고 다른 유효한 알림은 유지한다.

## 저장과 실행 수명

일정과 알림 처리 기록은 설정 파일과 같은 폴더의 `calendar.json`에 저장한다. 기본 위치는 `~/ish/dok/calendar.json`이다. 설정을 재생성해도 일정 파일은 덮어쓰지 않는다. 임시 파일·fsync·원자적 교체 및 프로세스 간 파일 잠금을 사용한다. 다른 ish에서 수정한 일정을 오래된 편집 화면으로 덮어쓰려 하면 충돌을 알리고 현재 초안을 보존한다. 닫았다 다시 열어 최신 내용을 확인한 뒤 편집한다. 손상된 저장 파일은 자동 초기화하거나 덮어쓰지 않는다.

`popups.calendar.reminders`는 예약 알림을 켜고 끈다. 외부에서 수정한 일정 파일은 캘린더 팝업을 열었을 때 `poll_s`(기본 1초), 닫았을 때 `idle_s`(기본 30초)마다 확인한다. dok 안에서 저장·삭제하거나 팝업을 열면 즉시 재확인한다. 이미 알고 있는 알림은 외부 파일 확인 주기와 관계없이 **다음 알림 시각**에 맞춰 깨어난다. 오늘 일정이 없더라도 미래 일정의 사전 알림은 유지한다.

미래 알림이 있으면 `clock_s`(기본 1초) 간격의 가벼운 시계 확인으로 시스템 시간 변경·절전 복귀를 감지한다. 이 확인은 파일을 읽거나 전체 일정을 다시 계산하지 않는다. 대기 중인 알림이 없으면 시계 확인도 하지 않는다. `popups.notifications.enabled`를 끄면 예약 알림을 처리 완료로 기록하지 않고 대기한다. 캘린더 전체를 끄면 저장소 확인 작업도 중단한다. I/O는 UI 스레드 밖에서 직렬로 실행하고 취소 중인 I/O가 끝나기 전에 다음 작업을 시작하지 않는다.

ish가 실행 중이고 UI 이벤트 루프가 유지되는 동안 알림을 확인한다. dock이 숨겨져 있어도 동작하며 셸 명령 실행 중에는 알림 대기열에 넣고 프롬프트 복귀 후 표시한다. ish가 종료된 동안 OS 알림을 발생시키는 별도 데몬은 없다. 다음 시작에서는 지나간 알림을 **일정의 등록된 알림별 최신 회차 하나씩**으로 모아 전달한다. 파일에 남은 처리 기록 때문에 같은 회차·같은 알림을 다시 알리지 않는다.

저장 형식은 `storage_version: 3`이며 `events`, `reminders`(알림 처리 기록), `commands`(명령 회차 처리 기록)를 분리한다. 일정은 `command`와 `repeat.end`(`count`/`date`), `repeat.count`(0 = 계속), `repeat.until`(종료날짜 또는 null)을 저장한다. `alarms` 예시는 `[{"unit": "minutes", "value": 5}, {"unit": "start", "value": 0}]`다. 기존 v1 단일 `alarm`과 v2 알림 목록은 Owner가 읽고 처리 기록·기존 위치를 보존한다. 조회만으로 파일을 다시 쓰지 않으며 다음 정상 수정·처리 기록 저장 때 v3로 기록한다. 이는 일정 데이터 보존을 위한 읽기 경로이며 설정 이름의 호환 별칭은 아니다.

중복 방지를 위해 알림 대기열에 넣기 **전에** 처리 기록을 저장한다. 그 직후 프로세스가 강제 종료되면 해당 알림이 화면에 표시되지 않을 수 있다. 여러 ish 프로세스가 같은 저장소를 쓰면 한 프로세스만 알림을 가져간다. 일반 `dock.notify()` 알림은 여전히 메모리 대기열이다. 에이전트 실행이나 Google Calendar 동기화는 수행하지 않는다.

## 일정 시작 시 명령어

`명령어`가 비어 있지 않으면 각 유효 회차의 시작에 기존 ish 프롬프트 제출 경로로 전달한다. 현재 셸의 경로·환경·명령 처리와 PTY 출력을 그대로 사용한다. 별도 백그라운드 셸이나 명령 전용 프로세스를 만들지 않는다. 입력 대기 중인 기본 프롬프트가 비어 있어야 한다. 다른 명령 실행 중, 입력 내용·팝업·검색 포커스·셸의 계속 입력 상태가 있으면 **그 회차를 건너뛰고 알림만 표시**한다. 작성 중인 내용에 명령을 합치거나 덮어쓰지 않고 나중에 재시도하지 않는다. 알림 UI를 전역으로 끄면 건너뛰기 안내도 표시되지 않는다.

명령 실행 감시는 스케줄러가 관찰한 미래 시작부터 활성화한다. 새로 발견한 과거 일정·시작할 때 이미 지난 회차는 실행하지 않는다. 종료하거나 캘린더를 비활성화한 동안 실행하는 별도 데몬은 없다. 실행 중 시계 변경 등으로 여러 회차가 지나가면 최신 회차만 확인한다. 같은 시각의 여러 명령 중 먼저 제출한 명령으로 프롬프트가 바빠지면 나머지는 건너뛴다. `popups.calendar.reminders`는 알림 전달 설정이며 명령어를 끄는 설정은 아니다. 명령어를 지우거나 캘린더 전체를 끄면 명령 실행도 중단한다.

CalendarStore는 파일 잠금 안에서 회차를 처리한 것으로 기록한 뒤 명령어를 Runtime에 반환한다. 실행·건너뛰기·호스트 거부 모두 같은 회차를 다시 제출하지 않는다. 기록 직후 종료되면 실행되지 않은 명령이 생길 수 있으며 효과가 불확실한 명령을 재실행하지 않는다. 저장 실패 시 제출하지 않는다. 저장·삭제·외부 수정·반복 종료 조건은 동일한 스냅샷과 계획 무효화 규칙을 사용한다. 이미 호스트에 제출된 명령은 이후 일정 수정이나 삭제로 취소하지 않는다.

`Reminder`·`ReminderUnit`은 알림 단위·숫자 해석·정규화·중복 기준·표시 문구를 선언한다. `CalendarEvent`·`Recurrence`는 날짜 검증과 반복·알림 시각 해석, `CalendarStore`는 저장·수정 충돌·처리 기록·다음 알림 계획, `CalendarRuntime`은 비동기 I/O와 대기·깨우기, `EventDraft`는 임시 편집, `CalendarPage`는 화면과 로컬 키/마우스를 소유한다. UI와 실행기는 저장 JSON이나 처리 기록 딕셔너리를 직접 해석하지 않는다.

`DateSelection`은 날짜·월·연 이동과 유효한 월 격자, `TimePart`·`TimeSelection`은 시·분·초 범위·선택·표시 구간을 제공한다. `picker_view`는 키·마우스를 이 API로 변환하고 테마로 그린다. `EventDraft.temporal_value()`·`choose_temporal()`이 필드와 타입의 대응·해석·적용을 소유한다. CalendarPage는 직접 날짜 버퍼를 파싱하거나 선택 결과를 저장 JSON에 쓰지 않는다. 선택기에 별도 저장소·런타임 작업·호스트 Float를 만들지 않는다.

## 반복 조회와 갱신

`CalendarSnapshot.on_day()`는 현재 조회 월의 결과만 재사용한다. 월 변경·새 일정 스냅샷·`CalendarEvent.recurrence_context()`가 제공하는 시스템 지역 시간 해석 환경 변경 시 다시 계산한다. 캐시는 스냅샷 비교나 저장 형식에 포함되지 않는다. 화면은 날짜별 결과를 숫자 행과 일정 행에서 공유하고, 좁은 창에서 보이지 않는 영역을 생성하지 않는다. 편집 중인 초안과 드롭다운·월 이동은 그대로 유지한다.

`CalendarStore`는 매 조회마다 잠금 안에서 파일 내용을 확인한다. 내용이 같으면 마지막으로 검증한 스냅샷을 재사용하고, 달라졌을 때만 JSON 해석과 필드 검증을 다시 한다. 수정 시각이나 파일 크기만으로 변경 여부를 판단하지 않는다. 파일 삭제·손상·외부 수정은 계속 감지한다. 알림 처리 기록은 작업마다 복사하므로 저장 실패가 캐시의 처리 기록을 바꾸지 않는다. 알림 기록만 바뀌고 일정 내용이 같으면 일정 조회 결과는 유지한다.

`CalendarRuntime`은 내용이 같은 스냅샷을 교체하거나 화면 갱신을 요청하지 않는다. 실제 일정 변경과 오류 복구는 즉시 반영한다. Store는 일정·처리 기록·시간 해석 환경이 같고 다음 알림 시각에 도달하지 않았다면 계산한 다음 시각을 재사용한다. 월 화면도 데이터·선택일·오늘 날짜·너비·테마·언어가 같으면 마지막 행 구성을 재사용한다. 파일 잠금·원자적 저장·중복 처리 방지 계약은 유지한다. 이전 측정 결과는 [반복 조회 최적화 기록](popup-performance.md#반복-조회-최적화-적용-2026-11-07)에 있다.
