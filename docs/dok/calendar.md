# 캘린더 편집과 예약 알림

Alt+C로 캘린더를 연다. 왼쪽에는 일요일부터 시작하는 월간 달력과 각 날짜의 일정 제목 네 줄이 표시되고, 오른쪽에는 선택한 날짜의 일정 편집 폼이 표시된다. `popups.calendar.week_start`로 시작 요일을 바꿀 수 있다. 달력에서 `n`으로 새 일정을 만들며, 같은 날의 여러 일정은 `e`로 목록을 열어 선택한다. New/Events 버튼은 표시하지 않는다. 반복 일정은 원본 시리즈를 편집·삭제한다.

제목, 시간 구간/하루 종일, 장소, 알림 시각, 반복 간격·단위, 사용자 휴일, 메모를 저장한다. 휴일은 사용자가 표시한 일정만 해당하며 국가 공휴일을 조회하지 않는다. 토요일·일요일·휴일은 공통 테마의 saturday·sunday·holiday 역할을 사용한다. 달력 날짜를 선택하고 Enter/Space/Tab을 누르면 편집으로 이동한다. 마우스는 일반 팝업이 포커스를 가진 동안 자동 활성화되고 닫으면 원래 상태로 복원된다. 시간 구간과 하루 종일 날짜 사이에는 Nerd Font 화살표 ``를 사용한다.

| 키 | 동작 |
| --- | --- |
| 달력 ←/→, ↑/↓ | 하루, 일주일 이동 |
| 달력 PageUp/PageDown, Home | 이전/다음 달, 오늘 |
| 달력 n / e | 새 일정 / 저장된 일정 선택 |
| Enter / Space / Tab | 달력에서 편집으로 이동 |
| 편집 Tab / Shift+Tab | 다음/이전 필드·버튼 |
| F2 | 저장 |
| Enter | 한 줄 입력에서는 다음 필드, 메모에서는 줄바꿈, 버튼 실행 |
| Space | 텍스트 입력, 버튼 토글, 드롭다운 열기 |
| 드롭다운 ↑/↓, PageUp/PageDown, Home/End | 항목 이동 |
| 드롭다운 Enter, Tab/Shift+Tab | 선택 적용; Tab은 다음/이전 필드로 이동 |
| Esc | 목록 취소 → 편집에서 달력으로 → 팝업 닫기 |

수정 중인 내용을 남겨둔 채 날짜·일정을 바꾸거나 닫으면 Save/Discard/Cancel로 확인한다. Esc로 편집에서 달력으로 돌아오는 것만으로는 초안을 버리지 않는다. 삭제는 별도로 확인한다. 셸 프롬프트의 문서·커서·선택은 건드리지 않으며, 팝업 안의 F2·편집 키가 셸로 전달되지 않는다. 프롬프트 자체가 종료되거나 플러그인을 해제하면 팝업 수명도 종료된다.

작은 창에서는 달력과 편집 영역을 한 번에 표시할 수 없으므로 현재 조작 영역을 표시한다. Tab/Enter로 편집 화면, Esc로 달력에 돌아온다. 세로 공간이 부족하면 선택 날짜 및 활성 입력 항목이 보이도록 스크롤한다. 호스트의 빈 공간을 확장하지 않으므로 전체 달력을 한 번에 보려면 창을 넓히거나 프롬프트를 위쪽으로 옮겨야 한다.

## 시간과 반복의 의미

시작·종료 날짜 `YYYY-MM-DD`와 시각 `HH:MM`은 각각 편집하며 초·마이크로초도 보존한다. 알림은 `YYYY-MM-DD HH:MM`이다. 새 일정은 현재 `clock.timezone`을 기억한다. `null`은 각 날짜에 해당하는 시스템 지역 시간 규칙을 사용한다. 이미 저장한 일정의 명시적 시간대는 전역 설정을 바꿔도 유지된다. 종료는 시작보다 늦어야 한다. `●/○ 하루 종일` 토글을 켜면 시각 입력과 해당 Tab 포커스를 숨기고 날짜를 comment 색으로 표시한다. 편집기에 표시하는 하루 종일 종료 날짜는 포함한다. 저장소의 종료 시각은 그 다음 날 자정으로 변환하여 기존의 종료 미포함 계약을 유지한다.

일정 영역 전체는 `theme.roles.editor_bg`, 텍스트 입력창은 `input_bg`로 칠한다. 반복 간격·단위·휴일 선택은 한 행이다. 메모는 남는 높이를 채우고 저장·취소·삭제 버튼은 한 줄씩 위·아래 여백을 두고 본문 하단에 고정한다. 두 영역 아래, 하단 바 바로 위에는 팝업 전체 너비의 빈 행을 한 줄 더 둔다. 팝업 맨 아래의 키 안내는 달력·필드·목록·확인 창에 맞춰 갱신한다.

반복은 없음, N일, N주, N개월, N년이다. 간격은 양의 정수다. 월·년 반복은 최초 날짜를 기준으로 계산하고 해당 월에 그 일이 없으면 마지막 날을 사용한다. 예: 1월 31일 → 2월 28일 → 3월 31일. 일광절약 시간 전환으로 존재하지 않는 시각은 저장 시 거부하고, 반복 중 해당 시각이 사라지는 회차는 건너뛴다. 두 번 존재하는 시각은 첫 번째를 사용한다. 한 날짜에 겹치는 동일 시리즈는 한 항목으로 표시한다.

알림 시각은 공란이면 비활성화된다. 반복 알림은 최초 시작과 알림 사이의 차이를 유지한다. 예를 들어 시작 09:30 / 알림 09:20은 매 회차 10분 전에 알린다. 종료 시각이 지난 뒤의 알림도 사용자가 지정한 시각을 따른다.

## 저장과 실행 수명

일정과 알림 처리 기록은 설정 파일과 같은 폴더의 `calendar.json`에 저장한다. 기본 위치는 `~/ish/dok/calendar.json`이다. 설정을 재생성해도 일정 파일은 덮어쓰지 않는다. 임시 파일·fsync·원자적 교체 및 프로세스 간 파일 잠금을 사용한다. 다른 ish에서 수정한 일정을 오래된 편집 화면으로 덮어쓰려 하면 충돌을 알리고 현재 초안을 보존한다. 닫았다 다시 열어 최신 내용을 확인한 뒤 편집한다. 손상된 저장 파일은 자동 초기화하거나 덮어쓰지 않는다.

`popups.calendar.reminders`는 예약 알림을, `poll_s`는 확인 주기(기본 1초)를 정한다. `popups.notifications.enabled`를 끄면 예약 알림을 처리 완료로 기록하지 않고 대기한다. 캘린더 전체를 끄면 저장소 확인 작업도 중단한다. I/O는 UI 스레드 밖에서 직렬로 실행하고 취소 중인 I/O가 끝나기 전에 다음 작업을 시작하지 않는다.

ish가 실행 중이고 UI 이벤트 루프가 유지되는 동안 알림을 확인한다. dock이 숨겨져 있어도 동작하며 셸 명령 실행 중에는 알림 대기열에 넣고 프롬프트 복귀 후 표시한다. ish가 종료된 동안 OS 알림을 발생시키는 별도 데몬은 없다. 다음 시작에서는 지나간 알림을 이벤트별 최신 회차 하나로 모아 전달한다. 파일에 남은 처리 기록 때문에 같은 회차를 다시 알리지 않는다.

중복 방지를 위해 알림 대기열에 넣기 **전에** 처리 기록을 저장한다. 그 직후 프로세스가 강제 종료되면 해당 알림이 화면에 표시되지 않을 수 있다. 여러 ish 프로세스가 같은 저장소를 쓰면 한 프로세스만 알림을 가져간다. 일반 `dock.notify()` 알림은 여전히 메모리 대기열이다. 이번 기능은 알림 표시이며 셸 명령·에이전트 실행이나 Google Calendar 동기화는 수행하지 않는다.

`CalendarEvent`·`Recurrence`는 검증과 반복 해석, `CalendarStore`는 저장·수정 충돌·처리 기록, `CalendarRuntime`은 비동기 I/O와 예약 알림 수명, `EventDraft`는 임시 편집, `CalendarPage`는 화면과 로컬 키/마우스를 소유한다. UI가 저장 JSON을 직접 해석하지 않는다.

## 반복 조회와 갱신

`CalendarSnapshot.on_day()`는 현재 조회 월의 결과만 재사용한다. 월 변경·새 일정 스냅샷·`CalendarEvent.recurrence_context()`가 제공하는 시스템 지역 시간 해석 환경 변경 시 다시 계산한다. 캐시는 스냅샷 비교나 저장 형식에 포함되지 않는다. 화면은 날짜별 결과를 숫자 행과 일정 행에서 공유하고, 좁은 창에서 보이지 않는 영역을 생성하지 않는다. 편집 중인 초안과 드롭다운·월 이동은 그대로 유지한다.

`CalendarStore`는 매 조회마다 잠금 안에서 파일 내용을 확인한다. 내용이 같으면 마지막으로 검증한 스냅샷을 재사용하고, 달라졌을 때만 JSON 해석과 필드 검증을 다시 한다. 수정 시각이나 파일 크기만으로 변경 여부를 판단하지 않는다. 파일 삭제·손상·외부 수정은 계속 감지한다. 알림 처리 기록은 작업마다 복사하므로 저장 실패가 캐시의 처리 기록을 바꾸지 않는다. 알림 기록만 바뀌고 일정 내용이 같으면 일정 조회 결과는 유지한다.

`CalendarRuntime`은 내용이 같은 스냅샷을 교체하거나 화면 갱신을 요청하지 않는다. 실제 일정 변경과 오류 복구는 즉시 반영한다. 알림 확인 주기·파일 잠금·원자적 저장·중복 처리 방지 계약은 변경하지 않는다. 측정 결과는 [반복 조회 최적화 기록](popup-performance.md#반복-조회-최적화-적용-2026-11-07)에 있다.
