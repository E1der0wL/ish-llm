# Google 일정 생성·편집·삭제

Google 연결의 읽기 동작을 유지하면서 별도 `CalendarWriter` capability로 쓰기를 제공한다. 기본은 읽기 전용이다. Google 쓰기 요청은 사용자가 저장 또는 삭제를 실행할 때만 발생한다. 명시적으로 등록한 dok 알림·명령어가 있으면 팝업과 독이 닫혀 있어도 해당 일정만 주기적으로 조회한다. LLM이나 Hub의 자동 실행은 연결하지 않는다.

## 사용 준비

[기존 연결 안내](connections.md)에 따라 OAuth Desktop 클라이언트와 source를 설정한다. 편집할 계정의 `connections.google` 항목에 `"write": true`를 넣고 같은 계정 ID로 다시 로그인한다.

```jsonc
{
  "connections": {
    "google": [{
      "id": "google",
      "enabled": true,
      "client_file": "google-desktop.json",
      "write": true,
      "updates": "all"
    }]
  }
}
```

```bash
cd ~/ish/plugin/script
python3 -m dok.connections login --config ~/ish/dok/config.jsonc --account google
```

dok 의존성이 설치된 Linux Python 3.12.14를 사용한다. `write: true`일 때 요청 scope는 `calendar.events`이며, 기존 읽기 전용 토큰만으로 편집 권한이 생기지 않는다. 재로그인·재로드 후 캘린더를 다시 열거나 F5로 조회한다. 실제 캘린더의 Google 권한도 `writer` 또는 `owner`여야 한다. 잠긴 일정과 기본 일정 유형 이외의 특수 일정은 읽기 전용으로 표시한다.

`updates`는 Google이 기존 초대 대상에게 보내는 변경 알림 정책이다. 기본 `all`, 외부 이메일 대상만 알릴 때 `externalOnly`, 알림 요청을 끌 때 `none`이다. Google의 전송·동기화 동작을 제어하는 Calendar API 옵션이며 dok의 로컬 일정 알림과는 별개다. [API 설명](https://developers.google.com/workspace/calendar/api/v3/reference/events/patch)

계정의 `write`를 `false`로 바꾸면 dok의 새 쓰기 요청을 차단한다. 이미 부여한 Google OAuth 권한을 서버에서 철회하지는 않는다. 이미 제출한 저장/삭제 요청도 취소되었다고 간주하지 않는다.

## 화면과 키

- 날짜에 일정이 있으면 오른쪽에 **일정 목록**, 없으면 **새 일정 편집 폼**을 표시한다. 선택한 날짜와 목록 제목 사이에는 한 줄을 띄운다. 목록에는 시간과 저장 캘린더가 표시되고 **추가 · 편집 · 삭제** 버튼은 이 순서로 맨 아래에 고정된다. 상단의 연결 상태·새로고침 버튼과 그 행은 제거했다. F5 수동 재조회 키는 유지한다.
- 달력에서 **Enter/Space/Tab**으로 오른쪽 영역에 들어간다. 목록에서 **↑/↓**로 선택하고 **Enter 또는 편집**, **Del 또는 삭제**를 사용한다. Tab은 목록·추가·편집·삭제 버튼을 순회한다. 읽기 전용 일정은 편집·삭제가 비활성화되고 Enter로 내용을 볼 수 있다.
- **N 또는 추가:** 로컬 새 일정 편집 폼을 연다. 외부 쓰기 대상이 있으면 위쪽 `저장할 캘린더`에서 `로컬 · dok`과 설정된 Google 캘린더 중 선택할 수 있다. 작성 중인 로컬 초안이 있으면 저장/버리기/취소를 먼저 확인한다. 기존 일정을 다른 저장소로 자동 이동하지 않는다.
- **새 Google 일정:** 위쪽 `저장할 캘린더`에서 등록된 쓰기 가능 Google source를 다시 선택할 수 있다. 캘린더는 settings의 source 목록을 사용하며 계정 전체 목록을 별도로 수집하지 않는다.
- **목록에서 기존 Google 일정 편집:** 최신 일정을 조회하고 제목·시간·종일 여부·반복·dok 알림·명령어·메모를 편집한다. 기존 Google 장소 값은 유지한다. 로컬과 같은 `EventForm`의 입력·선택기·하단 버튼을 사용한다. 공통 `EventDraft`가 반복·알림 입력 규칙을 소유하며 Google 초안도 같은 규칙을 사용한다. 사용자 휴일 표시는 로컬 일정에서만 제공한다. 기존 일정의 저장 위치는 원래 캘린더로 고정한다.
- **Tab/Shift+Tab:** 항목 이동. 날짜는 미니 달력, 시각은 시·분·초 선택기를 사용한다. 새 일정의 첫 시작 시각은 현재 시각 +1시간의 정시, 종료는 시작 +1시간이며 이후 날짜/시간 선택 때 덮어쓰지 않는다.
- **F2 또는 저장:** 미저장 변경이 있으면 `* 저장`으로 표시하고, 변경을 원래대로 되돌리거나 저장한 뒤에는 별표를 없앤다. 새 Google 일정의 저장 위치 변경도 미저장 상태에 포함한다. Google에는 변경된 필드만 전송한다. 저장·삭제 성공 후 해당 날짜 화면으로 돌아간다. **삭제:** 우측 공통 제목 줄을 비운 확인 화면을 거친 뒤 삭제한다. **Esc:** 선택기→편집→목록→달력 순으로 뒤로 이동하며 수정이 있으면 저장/버리기/취소를 확인한다. Alt+C는 기존 닫기 동작을 유지한다.
- 전송 중에는 중복 저장이나 일반 닫기를 차단한다. 하단 키 안내는 현재 영역에 맞게 바뀌며 버튼·입력·선택기·스크롤은 팝업 마우스 경로를 사용한다.

Google 반복 회차를 편집하면 범위 선택 화면 없이 **전체 반복 편집**을 바로 연다. 선택한 회차의 `recurringEventId`를 통해 시리즈 원본과 ETag를 조회하며, 반복 규칙·dok 알림·명령어는 시리즈에 적용한다. 삭제도 시리즈 전체를 대상으로 하며 확인 화면에 **반복 일정 전체**라고 명시한다. 부모 일정이 없거나 쓰기 불가이면 회차 편집으로 대체하지 않는다. 단일 일정은 해당 일정만 편집·삭제한다. 회차별 편집과 “이번 이후” 분할 UI는 제공하지 않는다.

우측 첫 줄은 모든 화면에서 고정 제목 영역이다. 일정 목록·편집 화면은 선택한 날짜를 표시하고, 삭제 확인·저장 위치 선택·충돌/확인·읽기 전용 상세에서는 비워 둔다. 제목은 본문 스크롤과 드롭다운 영역 밖에 유지한다. 기존 일정 편집 폼에서는 저장할 캘린더 영역과 회차/전체 반복 안내 문구를 표시하지 않는다. 새 일정의 저장 위치 선택은 유지한다.

새 Google 반복 일정과 전체 반복 수정은 **RRULE**을 사용한다. 일·주·월·년 간격, 전체 횟수(0은 계속), 종료 날짜를 지원한다. 월/년 반복의 짧은 달 말일 보정은 RRULE의 BYMONTHDAY/BYSETPOS로 표현한다. 시간 지정 반복에는 IANA 시간대를 전송한다. 표현할 수 없는 기존 Google 사용자 지정 반복·제외 규칙은 그대로 보존하고 규칙 편집만 비활성화한다. [Google 반복 일정](https://developers.google.com/workspace/calendar/api/guides/recurringevents)

Google에는 일정 내용과 RRULE을 저장한다. dok 알림·명령어는 연결/캘린더/일정 ID를 키로 로컬에 저장하며 Google 설명이나 확장 속성에 넣지 않는다. 기존 참석자, 회의 정보와 Google 자체 알림은 PATCH에서 변경하지 않는다. Google 자체 알림과 dok 팝업 알림을 둘 다 켜면 각각 도착할 수 있다. dok 팝업과 명령 실행에는 ish 실행이 필요하다.

일정 저장과 실행 설정의 책임, 실행 기록, 숨김 상태 조회는 [일정 실행 계약](calendar-actions.md)을 따른다.

## 충돌과 통신 오류

편집 시작 때 읽은 Google `etag`를 원본 버전으로 유지하고 PATCH/DELETE에 `If-Match`를 보낸다. 다른 기기에서 변경되면 412를 처리해 최신 내용을 조회하고 초안을 유지한다. 비교 화면에서 두 가지를 선택한다.

1. **최신 내용 불러오기:** 내 초안을 최신 값으로 교체한다.
2. **수정 다시 적용:** 내가 바꾼 필드만 최신 값 위에 적용한다. 다른 곳에서 바뀐 나머지 필드는 유지한다. 새 버전의 초안을 검토하고 저장을 다시 눌러야 하며 자동으로 덮어쓰지 않는다.

삭제 충돌도 최신 버전을 읽은 뒤 다시 확인하게 한다. 이벤트가 없어졌거나 접근할 수 없으면 자동 생성하거나 삭제 성공으로 추정하지 않는다. [Google 조건부 수정 계약](https://developers.google.com/workspace/calendar/api/guides/version-resources)

새 일정의 ID는 초안에서 한 번 생성해 유지한다. 전송 이후 타임아웃·5xx·강제 종료 등으로 결과가 불분명하면 `결과 불확실` 상태를 보여주고 같은 요청을 자동 재전송하지 않는다. `최신 일정 조회`로 현재 상태를 읽어 확인한 후 새 버전으로 편집한다. 조회 결과가 없다고 해서 쓰기가 적용되지 않았다고 단정하지 않으며 해당 요청의 재전송 차단을 유지한다.

불확실 요청 기록은 현재 dok 런타임의 메모리에만 존재한다. 프로세스가 종료되면 기록은 사라지지만 요청을 복구·재실행하지도 않는다. 재시작 뒤에는 캘린더를 조회해 결과를 확인해야 한다. 분산 시스템의 정확히 한 번 실행을 보장하는 기능은 아니다.

## 책임과 검증 범위

- `writes.py`: 편집 값 검증·변경 필드·충돌·불확실 결과·쓰기 계약.
- `edits.py`: source 권한 확인, 읽기/쓰기 직렬화, 불확실 요청의 재전송 차단.
- `remote_draft.py`: 공통 로컬 초안 규칙을 재사용하는 Google 초안, 시간대 해석, 회차/시리즈별 지원 필드와 충돌 재적용.
- `view.py`: 날짜별 목록/편집 전환, 안정적인 일정 ID 선택, 로컬 저장·삭제 흐름.
- `editor.py` / `remote_draft.py`: 공통 `EditorField`를 사용하며 각 초안이 지원 필드·검증·시간 해석을 소유한다.
- `form_view.py`: 로컬·Google이 함께 사용하는 입력, 시간 선택, 여백, 스크롤, 고정 하단 버튼의 단일 렌더러.
- `remote_view.py`: 캘린더 선택·확인·충돌·비동기 작업 상태 전이. 편집 화면은 공통 렌더러에 위임한다.
- Google `writer.py`: HTTP CRUD·버전 헤더·응답과 Google 필드 해석. `transport.py`는 조회/편집에 공통 인증·401 갱신을 제공한다.
- 공통 `EventDraft`와 `PickerOverlay`, `CalendarFormLayout`이 입력·선택기 배치·시간 버튼 간격을 소유한다. 기존 공개 import 이름은 유지한다.

UI 확정 후 MockTransport와 가짜 공급자로 Google 요청, 충돌, 취소, 재전송 차단, 원래 로컬 일정 동작을 dok 테스트에서 검증했다. 430건 중 424건 통과, 선택 Hub·llm 연동 6건 건너뜀이며 캘린더/Google 검사는 모두 실행했다. [검증 기록](validation.md). 실제 Google 계정의 데이터는 쓰지 않았다. ish 본체·llm·hub는 변경하지 않았고 llm/hub 전체 회귀 테스트는 실행하지 않았다.

이번 일정/실행 분리와 공통 제목 행 변경은 UI 확정 후 dok 452건 중 446건이 통과했고 선택 Hub/llm 6건은 건너뛰었다. 실패·오류는 없다. 위 424건 기록은 이전 변경의 검증 결과이며 최신 결과는 [검증 기록](validation.md)을 따른다.
