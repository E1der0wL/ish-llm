# 명령어 자동완성 등록과 관리

사용자가 프롬프트에 작성한 조회 명령의 출력을 자동완성 데이터로 등록한다. `-h`, `--help`, `help`를 추측해 실행하지 않으며 저장한 조회 명령도 시작·입력·자동완성·설정 재적용 시 재실행하지 않는다. ish 본체·llm·hub 소스는 변경하지 않는다.

## 화면과 사용 흐름

1. ish 프롬프트에 조회할 명령을 입력한다.
2. 기본 `Alt+O`로 커서 아래 등록창을 연다. 열기만 해서는 명령을 실행하지 않는다.
3. 자동완성을 연결할 **접두사**를 정하고 **병합 / 교체** 중 하나를 선택한다.
4. **Enter**로 등록한다. 팝업을 닫고 원래 프롬프트에 작성했던 명령을 ish의 검증·제출 경로로 한 번 실행한다.
5. 명령이 끝나 다음 프롬프트가 열리면 출력을 분석하고 선택한 방식으로 저장한다. 완료 또는 실패는 dok 알림으로 표시한다.

팝업 본문은 접두사 입력과 병합·교체 선택 사이에 빈 줄 한 칸을 둔다. 화면이 좁으면 여백부터 줄여 두 항목을 유지한다. 제목·관리 탭·조회 명령 편집·검토 목록·실행/등록/취소 버튼·하단 설명은 없다. 관리는 별도의 Alt+M 중앙 팝업에서 한다.

| 항목 | 의미 |
|---|---|
| 접두사 | 후보를 연결할 명령 토큰. `git log`와 `git logger`는 다른 대상 |
| 병합 | 기존 후보를 유지하고 새 후보를 추가한다. 이름이 같은 후보는 새 정보로 갱신하며 잠금 항목은 보존 |
| 교체 | 선택한 접두사의 후보 목록을 이번 분석 결과로 교체. 잠금 항목과 다른 접두사는 유지 |

Tab / Shift+Tab을 누를 때마다 병합·교체가 바로 전환된다. 별도의 영역 이동 없이 문자·공백·방향키는 계속 접두사 편집에 사용한다. 마우스로 병합·교체를 바로 선택할 수도 있다. 두 버튼은 공통 테마의 버튼 배경색을 쓰며, 사이 여백을 포함한 전체 너비와 양 끝을 위 접두사 입력 칸에 맞춘다. Enter는 작성된 명령을 한 번 실행해 분석·등록하고, 열기 키(기본 Alt+O)는 실행·저장 없이 창을 닫는다. Esc는 최상위 등록 화면을 유지한다. 원래 프롬프트 내용은 취소해도 유지한다.

Enter 이후 실행한 명령의 효과는 등록 실패로 되돌아가지 않는다. 외부 명령의 입력과 종료는 기존 ish 동작을 따른다. 별도 프로세스나 자동 재시도로 실행하지 않는다.

## 관리 팝업

기본 **Alt+M**은 중앙 관리 팝업을 연다. 왼쪽은 접두사, 오른쪽은 해당 접두사에 직접 등록된 항목과 설명이다. 부모 접두사에서 상속된 항목은 부모를 선택해서 수정한다. 목록은 생성 후보와 같은 전체 이름 정렬 규칙을 사용한다. 각 카테고리 제목 옆에 ** 추가 ·  편집 ·  잠금 ·  삭제** 아이콘 보조 버튼을 둔다. 잠긴 대상은 잠금 해제 아이콘으로 바뀐다. 접두사의 편집은 이름 변경이다. 기존 목록 아래의 텍스트 작업 버튼은 제거했고 하단에는 저장·닫기만 둔다. 열기·편집은 조회 명령이나 Hub 분석을 실행하지 않는다.

항목 편집은 이름, 설명, 종류(옵션/하위 명령어), 값 필요 여부, 공백/등호 구분, 선택 값, 잠금을 제공한다. 각 필드는 **제목 → 입력 칸 또는 드롭다운 → 빈 줄 한 칸**으로 묶으며, 드롭다운 버튼도 입력 칸과 같은 왼쪽 시작점에 정렬한다. 선택 값은 한 줄에 하나씩 입력한다. 값 없는 옵션과 하위 명령어는 관련 없는 입력을 숨긴다. 최종 검증은 Candidate의 공개 생성 API를 사용한다. 사용자가 작성한 설명은 번역하거나 바꾸지 않는다.

보조 버튼은 별도 버튼 배경 없이 팝업 바탕을 그대로 사용하며, 카테고리 제목은 왼쪽에 두고 각 영역의 오른쪽 끝에 아이콘 묶음을 정렬한다. 편집 버튼 영역은 필드 목록에 붙이지 않는다. `CompletionManager._editor_footer()`가 본문 하단 3행을 **빈 줄 → 적용·취소 → 빈 줄**로 예약하고 `_draw_editor()`는 남은 높이에만 필드를 배치한다. 필드 수·드롭다운 높이·오류 표시가 바뀌거나 본문을 스크롤해도 버튼 행은 같은 위치에 남는다. 화면이 3행보다 작으면 버튼을 우선 남기며 F2/Esc 조작은 유지한다. 기존 초안 적용과 파일 저장 구분은 바꾸지 않는다.

| 영역 | 키 |
|---|---|
| 공통 목록 | Tab/Shift+Tab 영역 전환, ↑/↓ 선택, F2 저장, Esc 접두사 영역, Alt+M 닫기 |
| 접두사 | Enter 항목 영역, A 추가, R 이름 변경, D/Delete 삭제, L 잠금 전환 |
| 항목 | Enter 수정, A 추가, D/Delete 삭제, L 잠금 전환 |
| 편집 | Tab/Shift+Tab 필드 이동, Enter 드롭다운 선택 또는 접두사 적용, F2 초안 적용, Esc 편집 취소 |
| 확인 | ←/→ 또는 Tab 선택, Enter 확인, Esc 취소 |

변경 상태 전용 행은 표시하지 않는다. 적용한 초안이 저장된 카탈로그와 다르면 목록의 저장 버튼이 `* 저장`이 되고, 저장 성공 또는 원래 값으로 복원되면 별표가 사라진다. 필드 편집 중에는 `ItemDraft.dirty` / `EditBuffer.dirty`가 공개하는 변경 여부를 사용해 `* 적용`으로 표시한다. 수정하지 않은 항목을 적용할 때 수집 근거를 지우지 않는다. 파일 저장 실패는 별표와 초안을 유지하며 오류를 표시한다. F2의 초안 적용 / 파일 저장 구분과 하단 키 안내 바는 유지한다.

마우스로 목록·버튼·입력 필드를 선택하고 휠로 해당 목록을 이동할 수도 있다. 각 영역의 키 안내는 팝업 하단과 toolbar 중앙에 현재 상태로 다시 표시한다. 편집의 **적용/F2**는 팝업 초안만 바꾸고, 목록의 **저장/F2**는 전체 초안을 한 번에 저장한다. 저장 전 닫기는 버릴지 확인하며 기본 선택은 취소다. 저장 충돌·실패는 기존 파일과 초안을 유지하고 오류를 표시한다. 다른 프로세스가 변경했다면 창을 닫고 설정을 재로드한 뒤 다시 연다.

잠금은 자동 수집에만 적용한다. 접두사 잠금은 해당 목록 전체를, 항목 잠금은 그 이름의 항목을 병합/교체에서 보호한다. 수동 수정·삭제는 계속 가능하다. 삭제한 항목은 다음 수집에서 다시 추가될 수 있다. 이름 변경은 다른 접두사를 연쇄 변경하지 않는다. AI 결과는 잠금 정책을 바꿀 수 없다. 수집 제외 기능과 저장 필드·처리 규칙·언어 문구·버튼·목록은 제거했다.

`completion.manage.key`는 기본 `["escape", "m"]`, `null`은 단축키 해제다. `completion.manage.panel`은 중앙 배치와 공통 크기·여백·테마 계약을 사용하며 기본 크기는 104열 × 28행이다. 좁은 화면에서는 현재 편집 필드를 따라 표시하며 F2/Esc로 적용·취소한다. `completion.enabled: false`는 등록·관리 단축키와 저장 후보 공급을 함께 끈다.

## 설정과 저장

`completion.enabled`는 등록창과 저장된 후보 공급을 제어하며 dock 표시와 독립적이다. `key`는 기본 `["escape", "o"]`, `null`이면 단축키를 해제한다. 기존 dok 키와 중첩되면 공통 KeySequence 검증이 거부한다. `panel`은 폭·높이·여백·테마 설정을 재사용하며 기본 크기는 42열 × 5행이다. 아래 공간이 부족하면 위에 배치하고 오른쪽이 잘리면 왼쪽으로 맞춘다. 팝업으로 포커스가 바뀌어도 원래 프롬프트의 고정된 입력 위치를 기준으로 배치한다.

`completion.hub: true`는 Enter로 확정한 실행의 결과 분석에 설치된 Hub의 `command-options` 에이전트를 우선 사용한다. 새 에이전트의 초기 연결값은 최상위 `hub.model`·`hub.api_key`·`hub.api_base`로 지정한다. 모두 기본 `null`이며 이때 해당 값을 에이전트에 명시하지 않는다. Hub는 기존 에이전트의 값을 보존하므로 생성 후 설정 변경은 Hub에서 한다. 연결이 없거나 분석에 실패하면 로컬 분석을 사용한다. 기본 `timeout_s: 60`은 Hub 응답 대기에만 적용하며 셸 명령을 강제 종료하지 않는다. 팝업 열기·편집·취소만으로 AI를 호출하지 않는다.

Hub 분석은 요청 시점의 dok `language`를 따른다. `null`은 ish 언어 선택을 사용하며 미지원 언어는 영어다. 설명(`help`)만 해당 언어로 번역하도록 요청하고, 옵션/하위 명령어 이름·입력 선택값·근거 문장은 원문을 유지한다. 번역된 설명은 후보와 함께 저장해 자동완성 옆에 표시한다. 언어 설정만 바꿔도 기존 목록을 자동 재분석하지 않으며, 다른 언어로 갱신하려면 다시 등록한다. 로컬 파서는 원문 설명을 유지한다.

새 `command-options` 에이전트에는 고정된 `reasoning_effort: low`를 넣고 온도는 지정하지 않는다. 나머지 dok 에이전트는 `medium`을 사용한다. 기존 에이전트 설정을 자동 덮어쓰거나 요청마다 강제로 바꾸지는 않는다.

데이터는 설정 파일과 같은 폴더의 `completions.json`에 저장한다. Catalog·Registration·Candidate가 필드·형식·검증·전이를 선언하고 저장소는 파일 잠금·원자적 교체·동시 편집 충돌을 담당한다. 충돌 시 오래된 목록으로 덮어쓰지 않는다. 재시작 시 읽고 등록 후 메모리 스냅샷을 게시한다. 입력 중에는 디스크·네트워크·명령 조회를 하지 않는다. 외부 파일 변경은 재시작 또는 설정 재로드로 읽는다.

## 분석·자동완성 계약

다음 프롬프트에서 호스트의 accepted_prompt_id·last_command·마지막 출력 API로 이번 실행을 확인한다. 실행을 식별할 수 없거나 출력이 잘렸거나 후보가 하나도 추출되지 않으면 기존 목록을 유지하고 실패를 알린다. 여러 줄 입력과 ish 내부 도구는 지원하지 않는다. 단일 줄 파이프·셸 문법은 사용자가 입력한 그대로 호스트에서 실행하며 접두사 해석 범위와는 별개다.

HelpAnalysis는 로컬 추출 규칙, 제어문자 제거, 에이전트 역할과 Analysis schema를 소유한다. 기본 에이전트에 도구는 등록하지 않는다. 조회별 독립 세션을 사용하고 공개 Hub/llm 계약으로 완료된 공개 결과만 읽는다. 관찰 취소와 Run 취소는 구분한다. 사용자 편집된 에이전트 정책은 Hub가 관리한다.

분석 항목은 옵션/하위 명령, 설명, 값 필요 여부, 공백/등호 연결, 문서에 명시된 선택 값과 단일 행 근거를 가진다. 후보 이름·선택 값·근거가 실제 출력에 있는지 Owner가 확인한다. 설명의 의미까지 자동으로 증명하지는 않는다. 로컬 분석은 명확한 옵션 선언 열과 Commands/Subcommands/명령어 제목 아래 선언만 읽으며 모든 도움말 형식을 지원하지는 않는다.

접두사는 문자열 startswith가 아니라 literal argv 토큰 배열이다. ish의 현재 셸 파서와 completion_context·quote_argument API를 사용한다. 확장·치환·복잡한 셸 문맥은 기존 공급자에 맡긴다. 등록된 옵션의 값 소비 규칙으로 하위 명령을 찾고 `--` 뒤에서는 추가 옵션을 제안하지 않는다. 공통 옵션은 하위 접두사로 상속하며 구체적인 항목을 우선한다. 하위 명령은 직접 등록된 접두사에서만 제안한다. 경로·브랜치 같은 동적 값 조회는 하지 않는다.

파일 읽기·저장은 Runtime의 직렬화된 작업으로 실행하며 UI와 자동완성은 typed Catalog API만 읽는다. 공급자는 기존 자동완성을 보존하고 해제 시 자신의 연결인 경우에만 복원한다.

## 목록·테마·진행 알림

기존 사용자/ish 공급자는 기존 순서대로 먼저 표시하고 한 번만 조회한다. dok 후보는 그 뒤에 붙이며 삽입 결과가 같으면 기존 항목을 유지한다. 선행 `-`를 포함한 전체 후보 이름을 대소문자 구분 없이 정렬하며 특수문자를 제거하거나 무시하지 않는다. 비교는 casefold한 문자열의 유니코드 코드 포인트 순서이며, 같으면 원문 이름으로 순서를 정한다. 예를 들어 `--alpha`, `--beta`, `-a`, `-b` 순서다. 이름 자체, 옵션 의미와 설명은 바꾸지 않는다. 상속된 옵션과 선택 값에도 같은 정렬을 적용하며, 저장한 원본 순서와 데이터는 변경하지 않는다. 기존 목록을 다시 등록할 필요가 없다.

`completion.menu`는 ish의 자동완성 목록에 dok 테마를 적용한다. 기존·생성 후보가 한 목록 안에서 같은 스타일을 사용한다. `enabled: false`면 ish 스타일을 유지한다. `color`·`background`는 항목/바탕, `help`는 설명, `selected_color`·`selected_background`·`selected_bold`는 선택 행, `scrollbar`·`scrollbar_background`는 스크롤바/레일이다. 값은 공통 테마 역할 또는 팔레트 이름이며 RGB는 `theme.colors`에서 관리한다. 등록 팝업의 `completion.panel`과는 별개다. 단일·다중 열 배치와 키 조작은 기존 ish 동작을 유지한다. 스타일은 재로드로 갱신하며 비활성화/해제 시 자신이 설치한 계층만 제거한다. 다른 영역의 스크롤바나 다른 플러그인의 교체는 건드리지 않는다.

생성 작업은 우측 하단 알림 하나를 단계별로 갱신한다. 조회 실행 → Hub 분석·번역(또는 로컬 분석) → 저장 순서이며, Rich의 ProgressBar가 완료한 단계 수를 렌더링한다. 막대는 테두리와 좌우 padding을 제외한 팝업 내부 너비를 모두 사용하며 터미널·패널 크기 변경에도 맞춰진다. 공통 알림 표시 규칙에 따라 하단 버튼은 표시하지 않으며 제목 오른쪽 닫기 아이콘과 Alt+X는 유지한다. 채워진 부분은 title, 남은 부분은 muted, 전체 완료는 save 테마 역할을 사용한다. 실제 퍼센트를 추정하지 않는다. Rich가 문자와 부분 셀을 렌더링하고, 어댑터가 TextRow로 변환해 기존 팝업에 전달한다. Rich Live나 별도 출력·렌더링 스레드를 시작하지 않는다. 실행 중인 셸 명령에는 ish가 화면을 넘기므로 진행 알림은 프롬프트가 돌아오면 그 시점의 상태부터 표시한다. 작업 중에는 자동으로 사라지지 않고 완료/실패 후 기존 알림 지속 시간을 적용한다. 알림 비활성화와 Alt+X 닫기를 따르며 입력 포커스를 빼앗지 않는다. 단계 전환과 표시 너비·테마 변경 시에만 막대를 다시 렌더링하며 추가 주기 조회나 AI 호출은 하지 않는다. Hub 실패 후 로컬 분석으로 전환되면 표시 문구도 바뀐다.

모든 우측 하단 알림은 내용과 padding에 맞춰 높이를 줄여 고정 높이의 불필요한 빈 줄을 남기지 않는다. 공통 알림 기본 여백에 따라 제목 아래와 본문 아래(키 안내 바 위)에 각각 한 줄을 둔다. 우측 하단 위치와 마우스 영역도 실제로 그린 높이에 맞추며, 사용자가 지정한 padding과 화면에 맞춘 최대 높이는 유지한다.

사용자가 [최종 진행 화면](../../tests/dok/reports/completion-menu-ui-20261108-rich-v4/completion-progress.png)을 확정한 뒤 Linux Python 3.12.14의 해시 검증된 독립 소스 스냅샷에서 dok 359개 테스트가 모두 통과했다. 건너뛴 검사는 없다. 목록 순서·중복 제거·스타일 갱신/복원, 캘린더 제목 번역, 진행 알림의 단계·교체·취소·만료, Rich 막대의 너비와 팝업 높이/클릭 영역을 검증했다. [검증 기록](../../tests/dok/reports/dok-i866sp1k/summary.md), [실행 로그](../../tests/dok/reports/dok-i866sp1k/dok.txt). 실제 모델 호출과 llm/hub 전체 회귀 테스트, WSL 개인 설치본 적용은 하지 않았다.

그 이후 요청된 모든 우측 하단 알림의 하단 버튼 제거와 위·아래 한 줄 padding은 [일정 알림 화면](../../tests/dok/reports/notification-padding-20261108/reminder.png)과 [진행 알림 화면](../../tests/dok/reports/notification-padding-20261108/progress.png)으로 확정했다. 이 후속 변경까지 포함한 별도의 Linux 소스 스냅샷에서 dok 359개 테스트가 모두 통과했고 건너뛴 검사는 없다. [최신 검증 기록](../../tests/dok/reports/dok-zwlfvy2p/summary.md).

선행 하이픈을 제외하던 정렬을 전체 이름 비교로 수정한 후에도 dok 359개 테스트가 모두 통과했다. 하이픈 개수, 대소문자 동률, 하위 명령어의 내부 특수문자, 공백/등호 방식의 옵션 값, 기존 공급자 우선순위와 저장 원본 보존을 확인했다. [특수문자 정렬 검증](../../tests/dok/reports/dok-2ua6qbh9/summary.md).

## 이전 UI 확인 상태

항목 편집 드롭다운의 왼쪽 정렬까지 반영한 [최신 편집 화면](../../tests/dok/reports/completion-manager-ui-20261108-v5/editor.png)을 사용자가 확정했다. 하단 고정 버튼과 필드별 한 줄 여백을 포함한 최종 dok 테스트는 **381개 통과, 건너뜀 0개**였다. [검증 기록](../../tests/dok/reports/dok-8c56cix8/summary.md). 아래 미리보기 준비 기록의 테스트 보류 단계는 종료했다.

2026-11-08 후속 변경: Alt+M 관리 팝업, toolbar 중앙 키 안내, 모든 알림의 키 안내 바와 날씨의 현재/Current 버튼을 구현했다. 사용자 수정 요청에 따라 카테고리 오른쪽의 투명 보조 버튼, 필드별 빈 줄 한 칸, 본문과 분리한 하단 고정 편집 버튼, 모든 알림의 내용 맞춤 높이를 적용하고 수집 제외 기능을 제거했다. [관리 화면](../../tests/dok/reports/completion-manager-ui-20261108-v4/manager.png), [항목 편집](../../tests/dok/reports/completion-manager-ui-20261108-v4/editor.png), [필드가 적은 항목 편집](../../tests/dok/reports/completion-manager-ui-20261108-v4/editor-short.png), [알림](../../tests/dok/reports/completion-manager-ui-20261108-v4/notification.png)은 실제 렌더러에 샘플 데이터를 전달한 미리보기다. 이 문단은 UI 확정 전 미리보기 준비 기록이다. 확정 후 검증은 위의 381개 통과 기록을 따른다. WSL 개인 설정·설치본은 변경하지 않았다.

접두사 편집, Tab으로 병합·교체 즉시 전환, Enter로 실행·분석·등록, Esc 취소 UI를 확정했다. 입력 칸과 버튼 사이에는 한 줄 여백을 두고 버튼의 배경 영역은 입력 칸 너비에 맞춘다. Linux Python 3.12.14의 해시 검증된 독립 소스 스냅샷에서 dok 351개 테스트를 모두 통과했다. 프롬프트 키 입력·기존 자동완성 보존·병합/교체·실패 시 목록 보존·분석 취소 정리와 언어 전달을 확인했다. 임시 Hub 워크스페이스에서 새 에이전트 연결값 저장과 기존 설정 보존도 확인했다. Hub 분석 검증은 공개 데이터 계약과 모의 응답을 사용했으며 실제 모델 호출과 llm/hub 전체 회귀 테스트는 실행하지 않았다.
