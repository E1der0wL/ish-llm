# dock 높이 확대 검토

저장소의 ish 호스트와 설치된 prompt-toolkit 3.0.53 코드를 기준으로 한 높이 확대 검토다. 이후 구현한 [최대화 정보 영역](dashboard.md)은 이 검토를 바탕으로 공간이 충분하면 확장하고, 부족하면 기본 크기로 표시한다. 아래 고정 높이 표는 기본 dock만 늘렸을 때의 계산이다.

## 결론

Float 높이를 늘리는 것은 가능하지만 셸 사용에 영향이 없다고 보장할 수는 없다. Float는 호스트의 입력 영역 위에 겹쳐 그리며 전용 공간을 확보하지 않는다. 충분한 높이가 있으면 입력 버퍼와 명령 실행은 유지되지만, dock 내용이 여러 줄 입력·자동완성·커서를 가릴 수 있다. 높이만 늘리기보다 실제 입력 컨테이너에 공간이 있을 때만 확장하는 방식이 현재 제약에 맞는다.

## 공간 계산

`dok/view.py`의 `DockRow`와 `DockGeometry`가 행과 표시 가능 조건을 소유한다. 현재 본문은 6줄(바로가기 위 투명 padding 포함), 하단 padding은 1줄이다. 상단 입력 한 줄을 남기는 최소 높이는 8줄이다.

| 현재보다 추가할 높이 | 하단 padding을 포함한 dock 높이 | 필요한 입력 영역 최소 높이 | 입력 영역이 8줄일 때 |
| --- | --- | --- | --- |
| 0줄 | 7줄 | 8줄 | 표시 |
| 1줄 | 8줄 | 9줄 | 공간 부족으로 숨김 |
| 2줄 | 9줄 | 10줄 | 공간 부족으로 숨김 |

여기서 높이는 터미널 전체가 아니라 Float에 전달되는 입력 컨테이너 높이다. bottom-toolbar, 입력 프레임, 검색·검증 toolbar 등의 공간은 별도로 계산해야 한다. 현재 정책은 dock 일부를 잘라 그리지 않고 전체를 숨기며, 충분한 공간이 돌아오면 다시 표시한다. 표는 기존 정책을 그대로 확장했을 때의 계산이며 확대 기능의 실기 검증 결과는 아니다.

`PromptSession._get_default_buffer_control_height()`는 자동완성 설정과 상태에 따라 기본 `reserve_space_for_menu=8`을 최소 높이로 사용한다. 이는 dock 전용 빈 공간도, 실제 높이가 항상 8이라는 보장도 아니다. `DockOverlay.preferred_height()`는 0을 반환하므로 dock 자체가 호스트에 더 넓은 공간을 요청하지 않는다.

## 셸 사용에 미치는 영향

- 입력·명령 실행: dock은 포커스를 받지 않고 버퍼를 수정하지 않는다. 다만 호스트는 Float를 고려해 커서나 입력을 재배치하지 않으므로, 여러 줄 입력이나 줄바꿈된 긴 명령의 일부가 가려질 수 있다. 최소 한 줄을 남기는 현재 조건도 모든 입력의 가시성을 보장하지 않는다.
- 자동완성: dock 내용이 메뉴보다 앞에 그려진다. 확대하면 메뉴가 가려지는 범위도 커질 수 있으며, 메뉴 선택 자체는 계속 동작한다.
- 투명 여백: 추가 행이 padding이면 그 행 자체는 뒤 화면이나 클릭을 덮지 않는다. 그러나 하단 기준 배치에서 그 위의 내용 행이 위로 이동하므로 전체 영향이 없는 것은 아니다.
- 마우스·키: 그려진 내용은 클릭을 소비하고 투명 여백은 뒤 컨트롤에 전달한다. dock이 공간 부족으로 숨겨지면 바로가기 우선 키도 비활성화된다. 보이는 동안의 지정 키 우선 동작은 기존과 같다.
- toolbar·출력: bottom-toolbar는 Float 밖에 있으므로 현재 컨테이너 경계를 지키면 직접 덮지 않는다. dock은 프롬프트 종료 시 숨겨진다. 프레임과 추가 toolbar가 나타나면 실제 가용 높이는 달라진다.
- 성능: 빈 padding 행은 그리지 않으므로 오디오 분석량을 늘리지 않는다. 텍스트 행의 소폭 증가만으로 성능 문제를 단정할 근거는 없지만, 새 애니메이션이나 갱신 작업을 추가한다면 별도 검증이 필요하다.

## 확대 시 권장 조건

ish 본체와 예약 공간을 유지하려면 실제 입력 영역 높이에 맞춰 추가 행을 허용하고, 부족할 때 현재 크기로 축소하거나 기존 정책대로 숨기는 선택이 필요하다. 어느 방식을 택하든 크기·최소 높이·행 배치는 `DockGeometry`가 소유해야 한다. 항상 큰 dock을 표시하면서 입력도 가리지 않으려면 호스트에 별도 공간을 확보해야 하므로 현재의 “기존 공간에 Float만 배치” 조건만으로는 보장할 수 없다.

실제 확대 구현 시에는 높이 경계, 긴 명령과 여러 줄 입력, 두 자동완성 메뉴, 입력 프레임, 검색·검증 toolbar, 창 축소·복원, 클릭과 키 복원, 명령 제출 후 화면 복원을 검증해야 한다.
